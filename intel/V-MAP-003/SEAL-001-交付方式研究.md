- 「粉專 API 排程」不列入第一版。
- 「名單表單」不在第一丹範圍。

所以真正會用到、又只有 V5.0 才有的，只剩**內容日曆**。

## 2. 三種交付方式

| | **A｜每店獨立部署** | **B｜集中代管** | **C｜先用既有工具完成試點** |
|---|---|---|---|
| 做法 | 每家店用**自己的** Cloudflare 帳號與 Anthropic 帳號，部署一份 V5.0 | 由我方的 Cloudflare 帳號代管。兩種變體：B1 每店一份 V5.0（各自的 Worker、D1、Secret）；B2 改成多店共用一套系統 | 不部署。產文用 **FB 四主體產文工具（V4.2 預覽版，用店家自己的 Claude Pro）**；月曆用 Business Suite 規劃工具；紀錄用店家自己的 Google 試算表 |
| 要改程式嗎 | 不用 | B1 不用；B2 **要**（帳號系統、每店資料隔離、金鑰加密） | 不用 |
| 符合「帳號、資料、金鑰獨立」 | ✅ 完全符合 | B1 🟡 金鑰屬於店家，但**存放在我方帳號**；B2 同左 | ✅ 完全符合 |

## 3. 比較

| 面向 | A｜每店獨立部署 | B｜集中代管 | C｜既有工具試點 |
|---|---|---|---|
| **建置時間** | 一次性：寫部署 SOP＋演練，約 4～6 小時【推估】<br>每店：陪店家註冊 Cloudflare 與 Anthropic、儲值、部署、設 Secret，約 2～3 小時【推估】 | B1：一次性約 2 小時；每店約 0.5～1 小時【推估】<br>B2：改程式＋安全檢查，約 2～4 週【推估】 | 一次性：確認預覽版分享設定、做發布紀錄表範本，約 2～3 小時【推估】<br>每店：0（開課前店家自己開好 Claude Pro） |
| **單客成本（我方）** | 人工 2～3 小時＝NT$2,000～3,000；之後每次版本更新每店 0.5 小時 | B1：約 NT$500～1,000／店，之後由我方持續維運；B2：開發成本攤提＋持續維運 | 約 NT$0（一次性準備費約 NT$2,000～3,000，由所有試點店分攤） |
| **單客成本（店家）** | Claude Pro 約 US$20／月＋API 用量（四篇約 NT$3～4 🟡）＋Anthropic 最低儲值 🟡；Cloudflare 免費方案 | Claude Pro＋API 用量（同 A）；若我方另收代管費，另計 | 只有 Claude Pro 約 US$20／月（已含在原本的工具費）；Canva、CapCut、Business Suite 免費起 |
| **資料安全** | 最佳隔離：資料與金鑰都在店家自己的帳號。<br>風險：店家要自己保管密碼與 Secret；遺失或外洩時我方無法處理 | 資料、金鑰集中在我方帳號：一次外洩會影響所有店家。<br>我方成為個資**受託者**（名單功能啟用時），要負監督與保護責任。<br>Cloudflare 免費額度全帳號共用：D1 儲存以全帳號資料庫加總計算 ✅，每日請求數也共用 🟡 | 資料留在店家自己的 Claude、Facebook、Google 帳號；我方不保管任何東西。<br>風險：店家把顧客個資貼進 Claude（教材已規定不可以） |
| **客戶操作難度** | **高**：要開 Cloudflare 與 Anthropic 帳號、用信用卡儲值 API、看懂 Secret 設定。日常使用則簡單（登入網站） | **最低**：店家只要登入網站 | **低～中**：日常要切換 Claude、Business Suite、試算表三個畫面；沒有一體化的內容日曆 |
| **後續維護責任** | 分散：每店一套，更新要逐店部署。我方沒有店家的 Cloudflare 權限，每次更新都要約時間陪同；責任界線必須寫進合約 | **集中在我方**：當機、權杖過期、版本升級都由我方處理。等於隱含持續服務義務，和「不承諾無限售後」**衝突**，需要另外設計月費 | 最少：我方只維護一個預覽版連結；Facebook、Claude 等工具由各自廠商維護 |
| **主要風險** | 店家第一關就卡在註冊與儲值；更新難以推送 | 我方變成小型 SaaS 業者（資安、個資、服務水準）；B2 的開發時間 | 預覽版的分享方式與用量上限要先實測 🟡；功能比 V5.0 少（沒有內容日曆） |

## 4. 建議

1. **第一家試點用 C。**
   - 第一丹要驗證的是「老闆能不能自己跑完一輪」，C 已經涵蓋全部 7 項驗收能力。
   - 不用部署，也不用保管任何人的金鑰。
   - 產文規則和 V5.0 完全相同，符合「V5.0 為基準」。
2. **正式版在 A 和 B 之間二選一，等試點回訪後再決定。** 判斷依據：
   - 店家有沒有因為「沒有內容日曆」而卡住或停用？
     - 沒有 → 正式版繼續用 C，不需要部署。
     - 有，而且店家願意自己註冊、儲值 → A。
     - 有，但店家做不到 → B1，同時要設計月費並寫清楚維運責任範圍。
   - B2（多店共用系統）在完成 3 家以上試點、並確定要收月費之前都**不建議**動工。

### 5.3 試點店條件與流程

- **條件**（沿用 06 文件）：單店、老闆在現場、有粉專（最好也有自己管理的社團）、願意自己開 Claude Pro。排除「全部幫我做」型。
- **流程**：開課前表單 → W1～W3 核心課 → W4 驗收日（OA4、OA5、OA6 必過，其餘 4 項過 3 項）→ 14 天自主產出期 → 第 30 天回訪。
- **我方工時預算**：沿用 05 文件的 A 方案預算；C 方案沒有部署工時，不增加單客成本。

### 5.4 試點結束時要回答的問題

1. 店家有沒有獨立完成 OA4、OA5、OA6？
2. 14 天內發了幾篇、幾支短影音？有幾篇是 P2（準時、無人介入）？
3. 沒有內容日曆，有沒有造成困擾？（決定正式版是否需要 A 或 B）
4. 店家實際付了哪些工具費？Claude Pro 的額度夠不夠用？
