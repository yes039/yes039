# 02｜海豹三兵共用核心架構

> 沿用 V-MAP 002 的三兵設計：依作品切分，同一個 Claude Project，Claude 是唯一窗口。本文只說明「共用什麼、分流什麼」，以及既有 repo 能力的盤點。

## 1. 架構總覽

```
                          ┌──────────── 共用核心（A、B 混班） ────────────┐
                          │ C0 部隊模板：店家資料卡｜品牌規範｜禁區｜戰果庫 │
                          │ C1 文宣兵：FB 貼文＋圖卡（Canva）              │
                          │ C2 影音兵：拍攝指令單 → 兩種固定格式短影音     │
                          │ C3 戰果兵：排程、留言建議、週報                │
                          │ C4 週作戰循環（約 1.5 小時／週）               │
                          └───────────────────────┬───────────────────────┘
                     ┌────────────────────────────┴────────────────────────────┐
         A 分流：自用                                                B 分流：接案
   A1 用自己店的真實資料建檔                                  B1 多客戶專案管理（一客一 Project）
   A2 自家粉專 Business Suite 設定                            B2 需求訪談與報價
   A3 自主操作驗收（老闆本人）                                B3 提案 → 退回 → 修改 → 交付
                                                              B4 交付責任包（授權、個資、權限、合約）
                                                              B5 模擬案＋真實案結業驗收
```

## 3. 分流模組

### A 分流（自用）

| 模組 | 內容 | 驗收重點 |

### B 分流（接案）

| 模組 | 內容 | 沿用來源 | 新增內容（需建置） |
|---|---|---|---|
| **B1 多客戶專案管理** | 一個客戶一個 Claude Project；共用的「模板 Project」只放方法，不放任何客戶資料；素材依客戶與月份建資料夾；作品帳（編號、版本、核可、發布連結） | M003 素材庫、作品帳、平台帳；V-MAP 002 共用編號 | 客戶命名規則、交接清單 |

## 4. 為什麼這樣分（設計理由）

1. **核心不分版本**：A、B 用同一套部隊模板與三兵，教材只寫一次，維護成本不會加倍。這也遵守「不另起爐灶」。
2. **B 的增量只放在「替別人做」才會遇到的事**：多客戶、報價、退回修改、責任。這些正是 A 不需要學的內容，所以分流的部分沒有重疊。
3. **C 扮演模擬客戶**：讓每位 B 學員都有穩定、可重複的練習對象，而不是靠教練一個一個陪練（這是控制工時的關鍵，見 05 文件）。劇本要由人寫好、Shen 核可後才能使用。
4. **不新增工具**：B 的多客戶管理用 Claude Projects、資料夾與一張表格就能完成，不引入 CRM 或專案管理軟體。Pro 方案的 Project 數量沒有上限，但所有客戶共用同一個使用額度 🟡（二手來源）。
