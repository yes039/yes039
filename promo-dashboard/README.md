# 宣傳戰情室 v0.1（開發測試版）

我們自己的 FB 廣告宣傳儀表板。系統的經營與管理主體是我們；每個合作、自有課程或客戶都是一個「專案」。第一個專案是 Jason 合作招生，玉欣珍會員活化是另一個獨立專案，兩者不共用、不混算名單與成果。

**狀態：只在本機開發與測試，尚未部署。** 畫面上的數字都來自標示【測試】的程式產生資料（專案代碼 `TJSN`、`TYXZ`），不是實際營運資料。正式部署、接入真實名單、投放廣告與發送訊息，都等 Shen 看過成果後再決定。

## 四層架構

| 層 | 畫面 | 內容 |
|---|---|---|
| 宣傳總覽 | `#/` | 你有權查看的所有專案：正在推什麼、花多少、帶來什麼成果、異常、待辦、資料更新狀態 |
| 專案 | `#/p/{id}` | 合作對象、目標、帳號、預算、成果指標定義；分頁：活動、比較、登錄與匯入、代碼與連結、資料來源、專案設定 |
| 活動 | `#/c/{id}` | 推什麼、對誰、導向哪裡、預算、期間、負責人；漏斗、每日趨勢、素材比較、追蹤連結、領取碼 |
| 素材／渠道 | 活動頁內 | FB 付費廣告、免費貼文、LINE、QR、合作方渠道；每則素材有自己的代碼與成效 |

## 第一版功能

- 專案新增、編輯、切換；每個專案自行定義成果指標（電子書領取、名單、有效名單、報名、付款、退款可各自啟用、改名、寫定義）。
- 活動設定：代碼、推廣內容、受眾、導向、領取流程、期間、預算、目標每筆成本、負責人、狀態。
- FB 廣告花費、曝光、連結點擊：人工登錄或 Meta 廣告報表 CSV 匯入（依廣告名稱開頭的素材代碼對應）。
- 成果：人工登錄或 CSV 匯入；電話、Email 只存雜湊值，用來在同一專案內去重。
- 活動、素材、渠道比較；付費與免費分開列。
- 資料來源、資料更新到哪天、缺漏原因、待辦（自動產生＋人工新增）。
- 活動代碼、素材代碼、追蹤連結（UTM 自動小寫）、LINE 領取碼的產生與檢查。
- 專案權限：系統管理者看全部；其他人只看被加入的專案，看不到其他專案是否存在。

## 計算規則

- **數字狀態**：沒有資料時不顯示 0，而是顯示「尚未接入」「資料不完整」「暫不計算」等原因；確實為 0 時顯示「已確認為零」。表格中「!」表示資料不完整，滑鼠移上去看原因。
- **轉換率與成本**：一律用合計分子 ÷ 合計分母，不平均各列比率。
- **總覽加總**：只加總口徑一致的數字（平台定義的花費、曝光、點擊，且同幣別）。名單、報名、付款由各專案自行定義，總覽不跨專案加總。
- **去重**：名單類以人計（同一專案內相同電話或 Email 的雜湊值算一人），專案合計可能小於各活動相加；付款以筆數計。
- **來源不明**：沒有活動代碼、素材代碼或領取碼的成果，列在「來源不明」，不分攤給任何活動。
- **漏斗比例**：是「這一階段數量 ÷ 上一階段數量」，各階段是獨立事件，不代表同一批人。
- **持續／觀察／調整**：只對付費範圍判斷；樣本不足（點擊與花費都未達門檻）一律「觀察」；門檻可在專案設定調整。

## 執行

```bash
npm install
npm test                          # 後端單元測試（9 項）
npm run dev                       # 本機伺服器 http://localhost:8787（記憶體資料庫，自動載入測試資料）
node scripts/e2e.mjs              # 介面操作測試（需先 npm run dev）
node scripts/screenshots.mjs      # 桌機與手機截圖到 screenshots/
npm run preview                   # 產生 preview/index.html：瀏覽器內執行同一套 API 與測試資料
```

## CSV 格式

**FB 廣告報表**：從 Meta 廣告管理員匯出、選「依天」細分。必要欄位：報告開始日期、廣告名稱、花費金額、曝光次數、連結點擊次數（支援中英文欄名；實際欄名待以真實匯出檔核對）。廣告名稱需以素材代碼開頭，例如 `JSN-2610-01-VD01-v1｜說明`。對應不到的列仍記錄花費，並列為待辦。

**成果紀錄**：`類型,日期,活動代碼,素材代碼,領取碼,數量,金額,外部編號,電話,Email,備註`。類型可填電子書領取、名單、有效名單、報名、付款、退款。有外部編號時重複匯入會覆蓋同一筆。

## 正式部署前檢查（尚未執行）

1. 建立 D1 資料庫並套用 `schema.sql`，把 `database_id` 寫入 `wrangler.toml`。
2. 設定 Cloudflare Access（Email 名單），填 `ACCESS_TEAM_DOMAIN`、`ACCESS_AUD`；未設定時 API 一律拒絕。
3. 設定 `ADMIN_EMAILS` 與 `wrangler secret put HASH_SALT`。
4. 用一份真實的 Meta 匯出檔核對欄名。
5. 不匯入測試資料；接入真實名單前確認各專案的資料使用範圍。
