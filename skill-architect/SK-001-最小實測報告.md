## 1. 隔離確認（先確認，後實測）

**做法**：在暫存目錄另開一個子 Claude Code CLI 執行測試，設定如下。

- 乾淨環境：`env -i`，只保留代理與憑證變數。
- 假 HOME：`HOME=<暫存>/home`，不讀使用者層的技能與設定。
- 只讀專案層設定：`--setting-sources project`。
- 不掛任何 MCP：`--strict-mcp-config`，所以碰不到 Google Drive。
- 權限模式 `--permission-mode dontAsk`，以白名單放行。
- 預算上限：`--max-budget-usd`。

**隔離過程中的兩個發現（已修正，可回饋給正式規格）**

1. 專案 `.claude/settings.json` 的 **allow 規則在未信任的資料夾不會生效**，deny 規則則一律生效。這是官方設計：專案不能替自己開權限。因此 allow 規則改由啟動參數 `--allowedTools` 傳入。
2. 寫檔權限規則要寫成 `Edit(路徑)`，寫成 `Write(路徑)` 不會生效；絕對路徑要用 `//` 開頭。

**殘餘風險（如實揭露）**：這是 Claude Code 應用層的隔離，不是作業系統沙箱，子 CLI 行程仍以 root 執行。因為 Bash 已被移除，模型沒有繞過的工具。子 CLI 的工具清單仍有 `ListAgents`（唯讀），`SendMessage` 已禁止。

## 4. 發現的問題（建議下一版修正，本次未修）

1. **SK-03 對錯誤口徑放水（最重要）**。規則寫「以成果單宣告的口徑為準」，所以 yx-A 把「已入帳」算成「未入帳積壓」（5 張／24,150），SK-03 看出語意不符卻只記 NOTE。
   建議：口徑與案件需求的字面語意矛盾時，判 FAIL。
2. **SK-01 遇到缺檔就整案 BLOCKED**，原計畫預期的是「只標那張卡 BLOCKED，其他卡照做」。目前做法較保守、安全，但兩種做法要擇一寫死。
3. **「異常筆數」口徑不一**：各次整合單分別給 20、25、30 筆，SK-03 標 UNVERIFIABLE。建議 SK-01 不要把異常總數列為 key_figure，或明確定義計數單位。
4. **技能呼叫屬性**：被其他技能呼叫的技能不能設 `disable-model-invocation`。正式規格書 §3、§5 的草案 frontmatter 需要更正。
5. **寫檔一律用相對路徑**：長路徑會被模型抄錯，已在 SK-02 修正並驗證。
