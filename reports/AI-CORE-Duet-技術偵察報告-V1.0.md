## 3. 三條技術路線比較

| 面向 | **A. Claude 原生功能＋Skills** | **B. Claude Code＋Agents＋排程工作流** | **C. 自建雲端 AI 調度平台** |
|---|---|---|---|
| 主動性 | 低。要人開對話才會動。Duet 在台灣不能用 | **高**。雲端排程定時自己跑，也能被 GitHub 或 API 事件觸發 | 最高，完全自訂 |
| 多員工協作 | 靠人在不同 Project 之間貼文件 | 可以用子代理平行處理，用檔案契約交接 | 自己寫訊息佇列和狀態機 |
| 任務追蹤 | 人工維護 Sheet | Agent 讀寫 Drive 的 Sheet，或 repo 裡的 Markdown | 自建資料庫 |
| 成果驗收 | 人工 | 契約檢查表由 Agent 先驗，人工核可節點再驗（兩層） | 自建規則引擎 |
| 老闆介面 | Sheet | Sheet，或一頁儀表板 Artifact | 自建網頁或 App |
| 建置時間 💭 | 1～3 天 | **1～2 週（G1）** | 2～3 個月以上 |
| 使用成本 | Pro $20/月 | Pro $20 到 Max $100/月 | API 用量、主機、維運人力，每月估計 NT$1～3 萬以上 💭 |
| 維護負擔 | 低 | 中（要管 SKILL.md 和排程設定） | 高（程式、資安、帳號授權都要自己顧） |
| 主要風險 | 沒有主動性，人一忙流程就停 | 排程任務還是研究預覽，功能可能變；額度上限 | 開發失敗、資安、做出來官方隔天就推出同功能 |
| 可複製性 | 高（貼 Prompt 就能用） | **高**（repo 可以整包複製給客戶，換資料就能用） | 低到中（每位客戶都要部署） |

**建議**：主線走 **B**。A 當客戶端的低門檻版本（只需要 Claude 帳號）。C 暫緩，等 G1 和 G2 的數據證明有需求、而且 B 碰到天花板時再評估。

## 4. G1 最小試辦設計（本輪只出設計，不開發）

**原則**
- 全部用現有資產，不重新發明
- 員工直接用海豹小隊三兵
- 任務帳直接用 G1 任務總帳
- 驗收直接用 M001 的驗收標準

### 4.1 編制

| 角色 | 來源資產 | 落地方式（下一輪才做） |
|---|---|---|
| **AI 調度官** | `seal-team/README.md` 的接力和退回規則，加上 G1 任務總帳的欄位 | 一份新的 SKILL.md，搭配一個 Claude Code 雲端排程任務，每天 1 次（建議早上 8 點前） |
| 員工①：企劃兵 | `roles/01-企劃兵.md` | 把職責卡轉成 `.claude/skills/seal-planner/SKILL.md`，內容不改寫 |
| 員工②：製片兵 | `roles/02-製片兵.md` | 同上，命名 `seal-producer` |
| 員工③：戰果兵 | `roles/03-戰果兵.md` | 同上，命名 `seal-analyst` |

### 4.2 調度官每日流程（設計）

1. 讀「G1 任務總帳」，加上 `seal-team/missions/*/` 各資料夾的現況。
2. 依照接力規則判斷每個任務卡在哪一棒：
   - 上游文件齊全 → 派給下一位兵（用子代理執行），產出草稿放進對應資料夾。
   - 卡在人工節點（H1～H7）→ 列入「待老闆」清單，**不代辦**。
   - 缺資料 → 填寫退回欄，**不自行補**。
3. 更新總帳的「狀態」和「下一步」，MEMO 欄只能追加，不覆蓋歷史（沿用總帳 V2.0 的規則）。
4. 產出一則晨報：今天完成什麼、卡在哪裡、需要老闆做哪 3 件事。

**權限邊界**：不發布影片、不對外傳訊息、不刪檔案、不碰帳號密碼。所有對外動作都留給老闆核可，跟 Duet 的核可原則一致。

### 4.3 任務追蹤機制

- **主檔**：`Shen 小秘書｜G1 任務總帳`，現有欄位直接沿用。
- 試辦期間只新增「SEAL」科目，任務 ID 沿用海豹小隊的 M00x 編號。
- 每一列的狀態只准用以下 6 種：待執行、進行中、待老闆、已退回、已驗收、暫緩。

### 4.4 成果驗收機制（兩層）

1. **AI 先驗**：每份交付物都要對照契約模板檢查——欄位齊全、編號一致（M00x-V1／T1）、上游沒有被下游自行補資料。
2. **人工終驗**：H2 作戰令核可、H4 成片核可。只有老闆打勾，狀態才能改成「已驗收」。
3. 驗收紀錄寫進 `04-復盤/`，戰果寫進 `戰果庫.md`。

### 4.5 老闆管理介面

- **G1 版**：直接看 Google Sheet，加上每日晨報。零開發。
- **可選升級**：一頁唯讀儀表板（Artifact），讀總帳資料，顯示每位員工的在辦、待老闆、逾期件數。要等 G1 跑完兩週、確認欄位穩定後再做。

### 4.6 G1 驗收條件（14 天試辦）

| # | 條件 | 及格線 |
|---|---|---|
| 1 | 調度官準時執行 | 14 天裡有 13 天以上產出晨報 |
| 2 | 完整跑通一場 | M001（或新開的 M003）從素材到 7 天復盤全部完成；M001 演習手冊的 6 項驗收全部打勾 |
| 3 | 追蹤可稽核 | 試辦任務的每一次狀態變更，都能在 MEMO 歷程找到日期和原因 |
| 4 | 零越權 | 對外發布、傳訊息、刪除的動作，0 次未經核可 |
| 5 | 退回機制有效 | 至少 1 次「缺資料就退回」，而且被正確觸發，沒有自行腦補 |
| 6 | 老闆省時 | 老闆每天花在這套流程上的時間 ≤ 15 分鐘（不含拍片和組片） |
| 7 | 可複製 | 把 repo 複製到新資料夾、換掉店家資料卡後，30 分鐘內能啟動第二家 |
