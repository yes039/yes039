# B｜營運指揮台架構

> 原型使用**模擬資料**，沒有串接 Facebook，也沒有真實數據。原型檔案：[dashboard/index.html](dashboard/index.html)（單一 HTML，手機瀏覽器直接開啟）。

## 1. 定位

一個手機可看的單頁工具，讓總指揮每天 1 分鐘看懂三件事：

1. **今天要做什麼**（待發布、待審核、72h 到期回收）
2. **我需要核准什麼**（G1–G5 關卡）
3. **招生進度是否落後**（漏斗對照週里程碑）

## 2. 版本路線

| 版本 | 資料來源 | 能做什麼 | 時程 |
|---|---|---|---|
| v0 原型（本次） | 寫死在頁面裡的模擬資料 | 瀏覽、篩選、在畫面上推進狀態（重新整理即重置） | 11/02 送審 |
| v1 試辦 | Google Sheet 五張表（人工填寫） | 指揮台讀取 Sheet 顯示；FB 數據仍由人工抄錄 | 核准後 |
| v2 評估 | 視需要評估 Meta Graph API | 自動拉粉專洞察數據；需另行申請權限並經核准 | 12 月後再議 |

v0、v1 都不碰 FB 帳號，不會發文、不會私訊。

## 3. 畫面結構（底部 5 個分頁）

```
┌──────────────────────────────┐
│ FB 營運指揮台   W2・11/12（模擬）│  ← 頁首：週次切換、模擬資料標章
├──────────────────────────────┤
│ [總覽] 今日任務／待核准／漏斗／警示 │
│ [排程] 月曆 → 週 → 日          │
│ [內容] 8 狀態看板＋素材包明細     │
│ [名單] 名單表＋來源追蹤碼排行     │
│ [績效] 72h 回收表＋週報          │
└──────────────────────────────┘
```

| 分頁 | 區塊 | 對應執行令 |
|---|---|---|
| 總覽 | KPI 漏斗（實績／月目標／週里程碑）、今日任務、待我核准、落後警示 | 一、五 |
| 排程 | 月曆（每日槽位色塊）、週排程列表、每日任務 | 四 |
| 內容 | 狀態看板（8 欄可橫滑）、內容卡（標題候選、文案、圖卡提示詞、腳本、CTA、追蹤碼、陣地時間） | 三、四 |
| 名單 | 名單列表（階段：私訊→報名→出席→成交）、追蹤碼來源排行 | 六-5 |
| 績效 | 72h 回收表、四柱比較、週報與優化建議 | 五、六-6 |

## 4. 資料模型（v1 對應 Google Sheet 五張表）

### 4.1 內容 Posts

| 欄位 | 說明 | 範例 |
|---|---|---|
| code | 追蹤碼（主鍵） | FB11-PG-W2-01 |
| week | 週次 | W2 |
| slot | 槽位 | P1 |
| pillar | 陣地 ME/PG/GR/EX | PG |
| type | 故事／觀點／案例／教學／招生／討論／互動／觀察 | 教學 |
| topic | 選題 | 3 句話讓 AI 幫你寫 LINE 祝福 |
| titles | 標題候選 ×3 | 「…」「…」「…」 |
| copy | 完整文案 | — |
| card_prompt | 圖卡提示詞（米色／咖啡色／金色） | — |
| video_script | 短影音腳本（可空） | — |
| cta | CTA 與關鍵字 | 留言「祝福」領範本 |
| publish_at | 預定發布時間 | 2026-11-09 19:30 |
| status | 8 狀態之一 | 已核准 |
| needs_confirm | 是否含【待確認】課程資訊 | true |
| url | 發布後網址 | — |

### 4.2 審核紀錄 Approvals

| 欄位 | 說明 |
|---|---|
| id | 流水號 |
| gate | G1 選題／G2 內容／G3 發布／G4 私訊／G5 廣告 |
| target | 追蹤碼或名單 ID |
| decision | 核准／退回／待決 |
| note | 修改意見 |
| decided_by / decided_at | 核准人、時間 |

規則：內容狀態要從「待審核」走到「已核准」，必須有一筆 G2＝核准；從「已核准」走到「已排程」必須有 G3＝核准；含 `needs_confirm=true` 的內容不能進入「已排程」。

### 4.3 名單 Leads

| 欄位 | 說明 |
|---|---|
| id | L-001 |
| nickname | 暱稱（不記錄身分證、地址等敏感資料） |
| first_code | 第一次接觸的追蹤碼 |
| channel | 留言／私訊／表單 |
| stage | 名單→報名→出席→成交（或流失） |
| session | S1／S2 |
| last_contact | 最後聯繫日期 |
| note | 關心的問題（價格、時間、學不會…） |

### 4.4 績效 Metrics（72h 回收）

code、collected_at、reach、engagement、clicks、valid_comments、valid_dms、signups、attended、deals、source_note。

### 4.5 任務 Tasks

date、time、pillar、slot、task、owner、done。

## 5. 狀態機

```
待選題 ─G1→ 待製作 → 待審核 ─G2→ 已核准 ─G3→ 已排程 → 已發布 ─72h→ 已回收 → 已優化
                        └退回→ 待製作
```

原型裡每張內容卡有「推進到下一狀態」按鈕；碰到 G2、G3 關卡時，按鈕會變成「送總指揮核准」，並顯示在總覽的「待我核准」清單，模擬核准後才可繼續。含【待確認】的卡片在「已核准」停住並提示原因。

## 6. 指標計算

| 指標 | 公式 |
|---|---|
| 觸及累積 | Σ Metrics.reach |
| 名單累積 | Leads 筆數（stage ≠ 流失前的有效名單） |
| 報名／出席／成交 | Leads.stage 達到該階段的人數 |
| 達成率 | 累積 ÷ 當週里程碑 |
| 落後警示 | 達成率 < 80% |
| 每篇名單轉換 | 該追蹤碼名單數 ÷ 該篇觸及 |
| 72h 到期 | publish_at + 72h ≤ 現在 且 status = 已發布 |

## 7. 技術選擇

- v0：單一 HTML 檔、原生 JavaScript、無外部依賴，手機直接開啟或發布成 claude.ai Artifact 連結。
- v1：Google Sheet 發布為 CSV 或用 Apps Script 提供唯讀 JSON，指揮台讀取顯示；寫入仍在 Sheet 完成。
- 權限：指揮台只讀；所有對外動作（發文、私訊、廣告）都不在系統內完成。
