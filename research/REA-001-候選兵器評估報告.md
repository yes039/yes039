## 2. 整合能力：Claude Code 經 MCP 調用

### 2.1 可行性：**可行**
- 官方安裝文件把 Claude Code 列為支援的 agent（`docs/installation.md:148`，id 為 `claude_code`）。
- 手動註冊（`docs/installation.md` MCP Registry 段）：
  ```json
  { "mcpServers": { "rea": { "command": "npx", "args": ["-y", "rea-agents@6.4.0", "mcp"] } } }
  ```
  在 Claude Code 中寫進專案層級的 `.mcp.json`，就只在該專案生效。
- **不建議使用 `npx rea-agents setup`**。它會改寫既有的 agent 設定（README：「Setup adds REA's MCP server and matching workflow instructions, with backups of existing configuration」），並把 skill 安裝到 `~/.claude/skills`（`docs/installation.md:348`）。這屬於「修改既有環境」，違反本任務禁令。

### 2.2 環境要求
| 項目 | 要求 | 來源 |
|---|---|---|
| Node.js | 22.x（≥22.19）／24.x（≥24.11）／26+，另需 npm | `package.json` `engines`、README |
| 僅做 JS／Electron／.NET 靜態分析 | **不需要其他工具** | README FAQ「Static JavaScript and .NET inspection work without a native analysis engine」 |
| 網站分析 | Chrome 系瀏覽器（CDP） | README 表格 |
| 原生二進位 | Hopper、Ghidra（12.1.x＋JDK 21+）或 IDA 三擇一 | README、`docs/windows-ghidra-p0.md` |
| 原生程序擷取 | Linux／macOS PTY | README 表格 |
| Android | JADX＋完整 JDK、adb、Apktool 等，均由使用者自備 | README 表格 |

### 2.3 成本估算
| 成本項 | 估算 | 說明 |
|---|---|---|
| REA 本體 | **0 元** | MIT 開源 |
| 靜態 JS 分析路線 | **0 元**（另需 Node） | 最小驗收只走這條 |
| Ghidra 路線 | 0 元 | 開源（NSA），需安裝 Java 21+，約數 GB 磁碟 |
| Hopper 路線 | 付費授權（有 demo 模式，功能受限） | 價格以 hopperapp.com 官方為準，本次未查核 |
| IDA 路線 | 高額商業授權 | 以 Hex-Rays 官方為準，本次未查核；**不建議** |
| **Claude 用量（隱性成本）** | 中到高 | 101 個工具的 schema 在連線時會提供給模型；官方為此另做了 `REA_MCP_INPUT_SCHEMA_PROFILE=compact`（CHANGELOG 6.4.0），可見 schema 體積不小。逆向分析的回傳（反編譯碼、Evidence）也偏長。實際 token 數應在驗收中量測，不宜先估。 |
| 維運成本 | 高 | 每兩三天一版，每版可能有 breaking change；若要收編，必須鎖定版本，升級前要重新驗收 |

### 2.4 權限要求與風險
- **REA 自己沒有授權閘門**。`docs/mcp-contracts.md`「Request scope and local effects」：「REA does not require permission grants or per-call approval flags … MCP clients control their own confirmation UI.」
- **不是沙箱**。`SECURITY.md`：「This is not a sandbox and does not protect against malicious processes already running as the same operating-system user. Opening an untrusted binary delegates parsing and analysis to the selected local provider with that user's permissions.」
- **含有會造成副作用的工具**：`install_adb_package`、`uninstall_adb_package`、`push_adb_file`、`start_adb_app`、`capture_process_scenario`（會實際執行程式）、`capture_electron_scenario`、`capture_browser_scenario`、`extract_firmware`（會寫入磁碟）。
- 結論：若要接上 Claude Code，閘門必須設在 Claude Code 這一端。做法是用 permission 規則只允許唯讀工具，其餘一律 deny，而且只在隔離的容器或 VM 內使用。

|---|---|---|
| **FB 發文系統** | 唯一能想到的「用途」是逆向 Facebook 網頁或 App 來自動發文。**這違反 Meta 服務條款**（禁止未經授權的自動化存取與繞過技術措施），而且有帳號被停權的風險。正規途徑是 Meta Graph API／Pages API，或 Meta Business Suite 排程。REA 對此**沒有正當用途**。 | ❌ 不適用（而且禁止） |

## 5. 最小驗收實驗方案（**提案，待 C 核准後才執行**）

### 5.1 目標
用最小成本回答三個問題：
1. 在 Claude Code 中，REA 能不能在**唯讀**模式下正常運作？
2. 它對「審查第三方 JS 套件」的增量價值，是否高於 grep 加人工閱讀？
3. token、時間、磁碟等實際成本是多少？

### 5.2 標的（合法、開源、不含客戶資料）
- **主標的**：REA 自己的 `tests/fixtures` 下的 JavaScript／Electron fixture（MIT，作者設計來被分析）。
- **對照標的**：一個小型 MIT 授權 npm 套件的解壓縮原始碼（建議 `ms` 或 `left-pad` 等級，固定版本）。
- 一律不使用：任何商業軟體、Meta／CapCut 相關檔案、我方客戶素材、`seal-team/missions/` 內的檔案。

### 5.3 隔離措施
| 措施 | 內容 |
|---|---|
| 執行場地 | 全新、用完即棄的 Claude Code 雲端 session（或本機 Docker 容器），**不是**目前的工作環境 |
| 版本鎖定 | `rea-agents@6.4.0`，記錄 npm tarball 的 SHA-512 integrity |
| 註冊方式 | 只在隔離的實驗目錄放專案層級 `.mcp.json`；**不執行** `rea setup`，不寫入 `~/.claude*` |
| Claude Code 權限 | `permissions.allow` 只放 `mcp__rea__analyze_javascript_application`、`mcp__rea__binary_session`、`mcp__rea__list_unknowns`；其餘 `mcp__rea__*` 一律 deny（特別是 `*adb*`、`capture_*`、`extract_firmware`、`install_*`、`push_*`） |
| 網路 | 只允許 npm registry 下載套件；分析階段不需要連外 |
| 不碰 | 本 repo 的 `seal-team/`、任何正式系統、任何帳號憑證 |

### 5.4 步驟
1. 開隔離 session，記錄 Node 版本。
2. 用 CLI 跑 `npx -y rea-agents@6.4.0 analyze-javascript-application <fixture 絕對路徑> --json`，存成 JSON，記錄耗時與輸出大小。
3. 在 Claude Code 中以 MCP 方式對同一標的問：「列出所有對外網路呼叫與檔案系統存取，附 Evidence」，記錄 token 用量。
4. 對照組：同一個問題，不用 REA，只用 Claude Code 內建的 Read／Grep，記錄 token 用量與結論。
5. 以人工核對兩組結論（以原始碼為準），計算漏報和誤報數。
6. 結束後銷毀 session；只把報告（不含第三方程式碼大段落）帶回本 repo。

### 5.5 通過條件（全部達成才考慮收編為備援器）
- [ ] MCP 連線成功，`binary_session` 回報版本與 6.4.0 一致
- [ ] 被 deny 的工具確實無法呼叫（例：嘗試 `install_adb_package` 時被 Claude Code 擋下）
- [ ] REA 組的漏報數 ≤ 對照組，而且至少多發現 1 項人工有確認的事實
- [ ] REA 組的 token 成本不超過對照組的 2 倍
- [ ] 全程沒有寫入實驗目錄以外的檔案（以前後 `find` 快照比對）

### 5.6 預估投入
- 人力：約 1–2 小時（含核對）
- 金錢：0 元授權費；Claude 用量估計數十萬 token 以內，以實測為準
- 風險：低（開源標的、隔離環境、唯讀工具）
