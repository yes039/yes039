# 02｜公開網站、YouTube、GitHub 三項讀取實測

測試環境：雲端隔離容器（Linux、Python 3.13），獨立 venv 安裝 Agent-Reach v1.5.0（commit `94f06c1`）＋ yt-dlp 2026.07.04。
憑證：**不帶任何憑證**。每條指令都在假的 HOME 下執行，並移除 `GH_TOKEN`／`GITHUB_TOKEN`。
原始紀錄：[evidence/](evidence/)｜重跑腳本：[scripts/run_live_tests.sh](scripts/run_live_tests.sh)

## 結果總表

| 項目 | Agent-Reach 建議路徑 | 本次結果 | 判定 |
|---|---|---|---|
| T1 公開網站 | `curl https://r.jina.ai/<URL>` | ❌ 測試環境的網路政策封鎖 `r.jina.ai`（直接連 `python.org` 也被擋） | **未完成，待重測** |

> 三項裡只有 GitHub 拿到實際資料。網站和 YouTube 是**測試環境的網路限制**擋下來的，不是 Agent-Reach 的問題，但目前也**還不能宣稱它可用**。這裡沒有用假資料充數。

## T1 公開網站（Jina Reader）

```
$ curl -sS "https://r.jina.ai/https://www.python.org/about/"
curl: (56) CONNECT tunnel failed, response 403
```

- 被擋在對外的 proxy 這一層（沒有加入允許的網域），請求根本沒有送到 Jina。
- 已知的設計限制（來自程式碼與文件審查）：網址和內容會經過 Jina 第三方伺服器；沒有 API key 時有每分鐘請求數的限制。
- 待重測：在允許 `r.jina.ai` 的環境執行 `run_live_tests.sh`。

## T2 YouTube（yt-dlp）

```
$ yt-dlp --skip-download --dump-json "https://www.youtube.com/watch?v=jNQXAC9IVRw"
ERROR: [youtube] jNQXAC9IVRw: Unable to download API page: ('Unable to connect to proxy',
OSError('Tunnel connection failed: 403 Forbidden'))
```

- yt-dlp 安裝正常。doctor 提示要設定 JS runtime（`--js-runtimes node`），YouTube 現在需要它來解簽章。
- 已知限制（來自 `skill/references/video.md`）：雲端或機房 IP 常被 YouTube 要求機器人驗證；自動字幕會有重複行；留言是爬網頁拿的，不保證完整。**正式部署前一定要在目標機器上實測。**

## T3 GitHub

| 子項 | 指令 | 結果 |
|---|---|---|
| T3a | `git clone --depth 1 https://github.com/yt-dlp/yt-dlp.git` | ✅ 0.93 秒，拿到 HEAD `43a45ae`（2026-10-21） |
| T3b | `curl https://raw.githubusercontent.com/yt-dlp/yt-dlp/master/README.md` | ✅ HTTP 200，179 KB，0.44 秒 |
| T3c | `gh repo view yt-dlp/yt-dlp`（未登入） | ❌ exit 4，要求 `gh auth login` |
| T3d | `gh search repos "agent web reader"`（未登入） | ❌ exit 4，同上 |

**發現**：Agent-Reach 的 README 寫 GitHub「零設定、公開 repo 直接用」，但它走的是 `gh` CLI，而 `gh` 沒登入就無法使用；doctor 自己也顯示「需要 `gh auth login`」。所以：

- 讀**單一 repo**：用 `git clone`／`raw.githubusercontent.com` 免登入就夠。
- 要**搜尋** repo、issue：需要 GitHub Token。建議另外建一個**只有公開唯讀權限的 fine-grained token**，不要拿正式帳號的 `gh auth login` 來用。

實際讀到的 2 筆 GitHub 情報已轉成 Airtable 格式：[evidence/airtable_batch_github_實測.json](evidence/airtable_batch_github_實測.json)。

## 重測方式

在允許 `github.com`、`raw.githubusercontent.com`、`r.jina.ai`、`www.youtube.com`、`*.googlevideo.com`、`pypi.org` 的機器上：

```bash
bash intel-officer/C-001-agent-reach/scripts/run_live_tests.sh \
  "https://要測的網頁" "https://www.youtube.com/watch?v=要測的影片" "https://github.com/owner/repo"
```

腳本會把所有東西裝在 `./.c001-sandbox/`（刪掉這個資料夾就清乾淨），不帶任何憑證，最後直接產出可以匯入 Airtable 的 CSV。
