# 01｜GitHub 專案與安裝安全性審查

審查對象：[Panniantong/Agent-Reach](https://github.com/Panniantong/Agent-Reach)
鎖定版本：`v1.5.0`，commit `94f06c1969dfc1834001269d79d3ad0972d9dee6`（2026-10-08）
審查日期：2026-10-22｜方法：讀原始碼＋隔離 venv 安裝＋單元測試，**沒有做任何系統層安裝，也沒有授權任何帳號**

## 1. 專案概況

| 項目 | 數值 | 判讀 |
|---|---|---|
| 授權 | MIT | 商用、修改都可以 |
| 熱度 | 約 10 萬 stars、8.9k forks、237 個 open issues | 社群很大；問題量也多 |
| 建立／最近推送 | 2026-02-24／2026-10-20 | 才 8 個月，仍在快速變動 |
| 程式量 | Python 約 7,300 行；測試檔 36 個、607 個測試 | 以這種規模來說測試覆蓋算高 |
| CI | GitHub Actions：py3.10–3.13＋Windows | 有 |
| 安全政策 | 有 `SECURITY.md`（私下通報，48 小時內回覆） | 有 |
| 定位 | **安裝器＋健檢＋路由**，本身不抓資料 | 真正讀資料的是上游工具（Jina Reader、yt-dlp、gh、OpenCLI…） |

> 重點：Agent-Reach 本身的程式碼風險很低，**風險幾乎都在它會幫你裝的上游工具，以及這些工具要求的登入態**。

## 2. 原始碼審查結果

| 檢查項 | 結果 |
|---|---|
| `shell=True`、`os.system`、`eval/exec`、`curl \| sh` | **都沒有**。所有子程序都用 `subprocess.run([...])` 參數陣列呼叫 |
| 遙測／回傳資料 | **沒有**任何分析或回傳。對外連線只有：GitHub API（`check-update`）、Exa MCP、V2EX／雪球／B站健檢、Groq／OpenAI（只在用 `transcribe` 時）。還會主動設 `GH_TELEMETRY=false` |
| 憑證儲存 | `~/.agent-reach/config.yaml`，權限 0600、目錄 0700，有測試覆蓋（`test_private_file_writes.py`） |
| 錯誤訊息遮罩 | 有 `scrub_url_credentials`，代理帳密不會出現在錯誤輸出裡 |
| 瀏覽器 Cookie 讀取 | `cookie_extract.py` 一次只讀**一個指定平台**的指定 Cookie（Twitter、B站、雪球）；小紅書明確不讀；**FB/IG 不在清單內** |
| 預設安裝行為 | `agent-reach install` 預設**只檢查**，要加 `--system` 才會真的裝東西。實測 `--dry-run` 和 `doctor` 都**沒有在 HOME 寫入任何檔案** |
| 單元測試 | 607 個測試，無憑證環境 **607/607 通過**；帶 `GITHUB_TOKEN` 時會有 1 個測試失敗（`test_get_configured_features` 讀到環境變數，屬於測試隔離瑕疵，不是安全問題） |

## 3. 安裝面的風險（要管控的地方）

| # | 風險 | 嚴重度 | 說明 | 管控方式 |
|---|---|---|---|---|
| R1 | **PyPI 套件名稱被別人用掉** | 高 | `pip install agent-reach` 會裝到**另一個人（jgalea）的同名專案 0.1.0**，不是這個專案。作者已在 2026-10-08 修正文件（commit `9219cba`） | 一律從 GitHub 安裝，而且鎖定 commit |
| R2 | 官方安裝指令跟著 `main` 分支走 | 中 | 文件教 `pip install .../archive/main.zip`，作者每推一次就會變 | 改用 `git+https://github.com/Panniantong/Agent-Reach.git@<commit>` |
| R3 | 「把網址丟給 Agent 叫它自己裝」 | 中 | `install.md` 是寫給 AI Agent 看的指令文件，等於讓遠端文件指揮你的 Agent。作者要是改了內容（或帳號被盜），Agent 會照做 | 不採用這種安裝法，由人執行固定版本的指令 |
| R4 | `--system` 會裝**沒鎖版本**的全域 npm 套件 | 中 | `npm install -g @jackwener/opencli`、`mcporter`、`undici` 都沒鎖版本；OpenCLI 有 `postinstall` 腳本（看過內容，只寫 shell 補全和 `~/.opencli`，沒有連網） | MVP 不用 `--system`；真的需要時鎖版本、裝在獨立使用者或容器內 |
| R5 | 自動寫入 Agent 的 Skill 目錄 | 低 | `--system` 會把 SKILL.md 寫進 `~/.claude/skills/`、`~/.openclaw/skills/` 等，改變 Agent 的行為 | 先看過內容再手動放 |
| R6 | 網頁內容經第三方轉送 | 中 | 「讀任意網頁」走 `r.jina.ai`，**你要讀的網址和內容都會經過 Jina 的伺服器** | 公開資訊可以接受；內部或敏感網址不要走 Jina |
| R7 | OpenCLI 能完整操控日常 Chrome | **高** | FB/IG 走 OpenCLI 擴充功能＋本機常駐程式，**直接使用你 Chrome 的登入態**；它的 FB/IG 模組還包含加好友、加社團、追蹤、按讚、留言、發文等**寫入動作**（見 03） | MVP 不裝 |
| R8 | doctor 的「✅」不等於真的能用 | 低 | 實測 `r.jina.ai` 連不上時，doctor 仍把「任意網頁」標成 ✅（它沒有實際連線測試） | 監控要用實際讀取結果，不要只看 doctor |

## 4. 結論

- **Agent-Reach 本體：可用**。程式乾淨、預設唯讀、有測試，沒有發現後門或回傳資料的行為。
- **要用就照「安全安裝」做**（隔離 venv、鎖 commit、不加 `--system`、不用「丟網址給 Agent 自己裝」）：

```bash
python3 -m venv ~/.agent-reach-venv
~/.agent-reach-venv/bin/pip install \
  "git+https://github.com/Panniantong/Agent-Reach.git@94f06c1969dfc1834001269d79d3ad0972d9dee6"
~/.agent-reach-venv/bin/agent-reach doctor      # 只檢查，不改系統
```

- **紅線**：不碰 OpenCLI（FB/IG/Reddit/小紅書這一路），除非用專用 Chrome 設定檔＋專用小號，而且要另外核准（見 03）。
