## 1. 客戶流程（水電、營造各一個入口）

```

   頁首與標示列寫明「示範公司・示範資料」，頁首右邊固定有「換成我的公司」按鈕

  │
  ▼
③ 自動回到頁首，同一個九宮格已經換成「我的」
   標示列改成藍色，寫明「依你輸入的條件模擬，不是真實資料」
   六個原有畫面全部換成我的資料
  │ 往下滑
  ▼
④ 三個情境（異常→原因→建議→決策→派工→驗果，完成後儀表板依結果更新）
   → AI 經營特助 → 改善試算
  │
  ▼
⑤ 下一步：體驗成果卡（存圖、傳 LINE）／我想預約真實導入示範／LINE 有興趣
```

## 3. 架構

**同一套畫面，兩種資料來源：**
- Demo 模式用原 Demo 的示範資料。
- 我的公司模式由產業模型產生同一種資料結構，原有畫面不改寫就能直接顯示。

| 檔案 | 內容 |
|---|---|
| `src/xp-core.js` | 共用體驗層：模式切換、換成我的公司、情境、特助、試算、成果卡、測試代碼、觀察紀錄（兩個產業共用，百業複製時沿用） |
| `src/xp.css` | 體驗層樣式，類別一律用 `x` 開頭，不影響原 Demo |
| `src/water-adapt.js` | 水電：模型 → 原 Demo 資料（工地、回報、異常、缺料） |
| `src/build-adapt.js` | 營造：模型 → 原 Demo 資料（工程、待決策、標案、分包、業主款、追加減、決議、成本、缺失） |
| `build22.py` | 組裝產生器；原 Demo 只在記憶體中加錨點，原檔不動 |
| `tests/g22.test.js` | 驗收測試 |

水電和營造各自維持獨立的計算模型。營造的進度、成本、現金流仍然分開計算，延續 G2 的公式。

### 3.1 模型與畫面的對應（我的公司模式）

**水電**

| 畫面上的數字 | 來自模型 |
|---|---|
| 今日回報 x/n | 工地數 × 回報率 |
| 未回報、連續 2 天 | 未回報工地數；其中一半視為連續 2 天 |
| 要你決定 | 異常 ÷ 2 ＋ 明天缺料（1）＋ 落後（1），與特助一致 |
| 逾期 | 落後工程數（紅燈） |
| 缺料待辦 | 缺料項數，平均分到缺料工地；明天會缺的標「提出」 |

**營造**

| 九宮格 | 來自模型 |
|---|---|
| 工程進度 | 工程數；各工程的應達與實際進度 |
| 今日要你決定 | 落後、未簽追加減、逾期應收、成本效率 < 0.97，各 1 件 |
| 請款與收款 | 已請未收；逾期金額只放在落後工程 |
| 採購・發包・估驗 | 分包已估未付；差異提醒 = 異常 ÷ 2 |
| 日報與會議 | 已交 = 工程數 − 異常工程；待追蹤決議 |
| 工安與品質 | 缺失數、逾期缺失 |
| 變更設計與追加減 | 未簽金額拆成三筆，與情境 S02 相同 |
| 成本與毛利 | 各工程毛利的加權平均 = 模型的預估毛利 |

金額分配到各工程時，用最大餘數法把總額換成整數元，所以合計一定等於總額，顯示方式也和原 Demo 一樣（整數「萬」）。

### 3.2 工地數不是 8 的時候（水電）

- 少於 8 個：保留九宮格，多出來的格子標「未使用」。
- 多於 8 個：九宮格先排最需要注意的 8 個，並註明其餘 N 個在「工地總覽」。

## 5. 限制

1. **原畫面上的操作不會回寫到模型。** 在我的公司模式中，於原有畫面按「已處理」「提醒主任」或在 LINE 回報送出，只會改變畫面上的工地／工程狀態，不會改變情境、特助和試算的計算。修改條件、完成情境或按「重新產生」時，會依模型重新產生資料。
2. **我的資料是模擬產生的。** 工地／工程名稱、主任名字、訊息文字都取自固定字庫，並標示「模擬」，刻意不和示範公司的名稱重複。
3. **成本與毛利**在原 Demo 標示為「完整企業版功能」。我的模式沿用這個標示，數字依條件模擬。
4. **開發連結目前是私人連結。** 要給測試者看，需由總指揮在 Share 選單設定。
5. **沒有任何資料會傳出頁面。** 觀察紀錄只存在畫面上，延續 G2.1 的做法。
