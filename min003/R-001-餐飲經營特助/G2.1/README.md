### 0.3 手機實測狀態（T05）

本開發環境只有 Linux 上的 Chromium，沒有 iPhone、Android 實機，也沒有 Safari（WebKit）。以下**不以模擬寬度測試冒充實機通過**：

| 環境 | 狀態 | 本輪能做到的 |
|---|---|---|
| iPhone Safari | **待驗（需實機）** | Chromium 以 iPhone 尺寸與 UA 模擬截圖；未測 Safari 的字型、安全區、滑桿與 `<details>` 實際表現 |
| LINE 內建瀏覽器（iOS／Android） | **待驗（需實機）** | 無法模擬。已知風險：LINE 可能清除本機儲存（V1.2 技術設計書 12.1），重新開啟時「我的店」可能消失 |
| Android Chrome | **待驗（需實機）** | 桌機 Chromium 行動模式 390 × 844 自動測試通過，與實機 Chrome 同核心但非實機 |

建議實機驗收清單（由總指揮或商務專人以手機開啟開發版連結）：
1. 首屏不需捲動即可看到九宮格與「30 秒免費體驗｜換成我的店」。
2. 隱私告知卡不遮任何內容；不選也能操作。
3. 「更多 Demo 內容」可展開，三張卡文字清楚、箭頭對齊（淺色、深色各看一次）。
4. 換成我的店四步：滑桿可拖動、店名輸入時畫面不放大。
5. 走完一張決策單到成果卡（約 14 次點擊），記錄實際秒數。
6. 在 LINE 內開啟一次，關閉後再開，確認「我的店」是否保留。

## 1. 客戶體驗動線

```
第一眼   首頁直接是示範餐廳九宮格（營收、毛利、營業利益、異常數）＋ 下方主要 CTA
第二步   「30 秒免費體驗｜換成我的店」→ 同一頁四步：店型 → 店名 → 經營數字 → 確認
          → 回到九宮格位置，標示「這是你的餐廳經營模擬」，可「修改條件」「返回 Demo」
第三步   導引卡「你的店最該先處理：○○」→ 決策單六步
          發現異常 → 分析原因 → 規則建議 → 老闆決策 → 模擬派工 → 數據驗收
          → 「原來我的店，可以這樣管理！」管理體檢成果卡 ＋ 下一步選擇
```

## 2. 從首頁到完成第一個管理情境：實際操作步驟

以手機 390 × 844 自動測試實際點擊，四種店型都是 **14 次點擊**（含第 1 次的隱私選擇；店名與經營數字可不改）。

| # | 畫面 | 點擊 |
|---|---|---|
| 1 | 首頁 Demo，底部出現 V1.2 告知與同意卡 | 同意記錄操作（或「只看不記錄」） |
| 2 | 示範九宮格下方主要 CTA | 30 秒免費體驗｜換成我的店 |
| 3 | 同頁設定 1/4：選擇店型 | 選店型卡 |
| 4 | 同頁設定 1/4 | 下一步 |
| 5 | 2/4：店名（選填） | 下一步 |
| 6 | 3/4：經營數字（已帶入店型預設，滑桿調整） | 下一步 |
| 7 | 4/4：確認（明寫不用登入、不用留聯絡方式） | 開始體驗 |
| 8 | 我的九宮格＋導引卡「你的店最該先處理：…」 | 開始處理這個問題 |
| 9 | 導引 1/6 發現異常（規則觸發條件） | 分析原因 |
| 10 | 導引 2/6 分析原因（資料、試算標示） | 看規則建議 |
| 11 | 導引 3/6 規則建議（方案、金額、假設，標「建議」） | 由老闆決定 |
| 12 | 導引 4/6 老闆決策（已預選建議方案，可改選或暫不處理） | 決定採用 |
| 13 | 導引 5/6 模擬派工（工作依職務派給店內人員） | 派工並模擬執行 7 天 |
| 14 | 導引 6/6 數據驗收（7 天圖表、通過／部分／未達成） | 完成，看我的管理成果 |
| — | 管理體檢成果卡：處理前 → 7 天後、每月影響、九宮格燈號、其餘待處理、下一步 | — |

| 咖啡廳 | 下午低客單 | 下午茶套餐 | 通過 |
| 便當店 | 雞腿肉進價 +23% | A＋B 組合 | 通過 |
