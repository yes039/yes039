## 1. 客戶體驗動線

```
第一眼   首頁直接是示範餐廳九宮格（營收、毛利、營業利益、異常數）＋ 下方主要 CTA
第二步   「30 秒免費體驗｜換成我的店」→ 同一頁四步：店型 → 店名 → 經營數字 → 確認
          → 回到九宮格位置，標示「這是你的餐廳經營模擬」，可「修改條件」「返回 Demo」
第三步   導引卡「你的店最該先處理：○○」→ 決策單六步
          發現異常 → 分析原因 → 規則建議 → 老闆決策 → 模擬派工 → 數據驗收
          → 「原來我的店，可以這樣管理！」管理體檢成果卡 ＋ 下一步選擇
```

## 2. 從首頁到完成第一個管理情境：實際操作步驟

以手機 390 × 844 自動測試實際點擊，四種店型都是 **14 次點擊**（含第 1 次的隱私選擇；店名與經營數字可不改）。

| # | 畫面 | 點擊 |
|---|---|---|
| 1 | 首頁 Demo，底部出現 V1.2 告知與同意卡 | 同意記錄操作（或「只看不記錄」） |
| 2 | 示範九宮格下方主要 CTA | 30 秒免費體驗｜換成我的店 |
| 3 | 同頁設定 1/4：選擇店型 | 選店型卡 |
| 4 | 同頁設定 1/4 | 下一步 |
| 5 | 2/4：店名（選填） | 下一步 |
| 6 | 3/4：經營數字（已帶入店型預設，滑桿調整） | 下一步 |
| 7 | 4/4：確認（明寫不用登入、不用留聯絡方式） | 開始體驗 |
| 8 | 我的九宮格＋導引卡「你的店最該先處理：…」 | 開始處理這個問題 |

## 3. G2-006 與 G2.1 差異

| 範圍 | G2-006 | G2.1 |
|---|---|---|
| 首頁首屏 | 30 秒摘要在九宮格之上；CTA 是頁面下方深藍區塊裡四個按鈕之一 | 九宮格直接在首屏（y 113–493）；正下方一顆醒目主要 CTA「30 秒免費體驗｜換成我的店」（y 530–587） |
| 示範標示 | 頁首小字 | 九宮格上方「示範餐廳：示範小館・鐵板熱炒」 |
| 換成我的店 | 另開頁面；步驟：店型 → 單數 → 客單 → 人數 | 在首頁九宮格位置原地展開；步驟：店型 → **店名** → **經營數字（三項一頁、已帶預設）** → **確認** |
| 完成設定後 | 首頁上方紫色橫幅 | 回到九宮格位置，標示「這是你的餐廳經營模擬」＋「修改條件」「返回 Demo」；Demo 頁可「看我的店」切回 |
| Demo 與我的店 | 換店型就覆蓋示範店 | 兩者並存，可來回切換；決策單進度各自保存 |
| 第一次體驗 | 客戶自己找決策單 | 導引卡自動挑出最有感的一張，帶著走六步 |
| 決策單步驟名稱 | 發現問題、分析原因、建議方案、老闆決策、執行追蹤、數據驗收 | 發現異常、分析原因、**規則建議**、老闆決策、**模擬派工**、數據驗收 |
| 規則建議 | 列出方案 | 加標「建議」，並寫明「AI 經營特助（規則版）…未啟用 AI 模型」 |
| 老闆決策 | 需先點選方案 | 導引時預選建議方案，可改選 |
| 執行追蹤 | 需逐項勾選才能模擬 | 每項工作顯示派給誰（依職務）；一鍵「派工並模擬執行 7 天」 |
| 完成後 | 結案 | 導引時進入「原來我的店，可以這樣管理！」成果卡與下一步選擇 |
| 次要 CTA | 首頁深藍區塊 | 移到「想多了解」清單；成果卡為主要出口 |
| 提示訊息 | 底部浮出 | 改在頁首下方，不遮住按鈕 |
| 未改 | 財務公式、四店型資料與規則、六步決策邏輯與驗收算法、改善試算、服務方案、進階功能、V1.2 事件與同意、`food` 與 `?t=` | 同左 |

## 5. 邊界確認

- V1.2 歸因、權限、事件類型、同意規則未修改；G2.1 仍只透過 `MIN.track/task/consult/submit` 記錄。
- 「換成我的店」只收店型與數字；店名只顯示在畫面，不寫入事件或表單。
- 規則建議一律標示「規則版、未啟用 AI 模型」；成果卡也標示規則／試算／AI 分析未啟用。
- 未串接 AI、POS、LINE；不發送通知；模擬派工不會傳訊息給員工。
