## G2 做了什麼

**A 線｜產品優化**

| 任務 | 結果 |
|---|---|
| T01 財務公式審核 | 找出並修正 12 項口徑問題（折扣、金流、正職日攤、月估算係數、四捨五入、報廢、外送與漲價門檻等）。統一「先四捨五入到元再加總、分配用最大餘數法、燈號用四捨五入後比率」。18 項指標有公式、來源、假設；原型內 105 項自檢全過 |
| T02 四種店型 | 鐵板熱炒、小吃麵店、咖啡廳、便當店各有自己的菜單分類、加點指標、關鍵食材、渠道與時段結構、人員型態、成本目標、啟用規則與方案。觸發的異常與前三項建議四店型都不同 |
| T03 經營決策閉環 | 每項異常一張決策單：發現問題 → 分析原因 → 建議方案 → 老闆決策 → 執行追蹤 → 數據驗收。驗收以模擬 7 天資料判斷通過／部分達成／未達成；結果型指標（比上週下滑）併入原因，避免重複處理 |
| T04 AI 建議可信度 | 每段內容標示「規則」「試算」「資料」「AI 分析」。AI 分析一律標「未啟用」，頁面明寫尚未串接 AI 模型 |

**B 線｜商業變現**

| 任務 | 結果 |
|---|---|
| T05 30–60 秒免費體驗 | 四步精靈（店型 → 單數 → 客單 → 人數／外送），最少 8 次點擊，產生「我的模擬九宮格」並記錄耗時 |
| T06 改善價值試算 | 食材成本降低、營收與客單提升、排班效率三情境，每項列公式與假設，明寫「不是獲利承諾」 |
| T07 商機轉換 | 領取經營體檢摘要、加入 LINE、預約專人診斷三種 CTA；沿用 V1.2 事件類型與推薦夥伴歸因規則，可在「整合測試」頁切換五種開啟方式模擬 |
| T08 付費服務展示 | 免費體驗、初階導入、正式經營特助三層，列功能與價值差異，價格標「待總指揮定案」 |

## 尚未完成與限制

- **未部署**。依 V1.2 技術設計書第 0 節，Artifact 不能做真實追蹤；正式獲客版須部署到自有網域，並完成《G2 市場驗證計畫》第 1 節的前提。
- 事件、表單只存在使用者裝置；不建立 CRM 商機，不通知商務專人或夥伴。
- 「整合測試」頁的歸因判斷是模擬伺服器行為；保護期、重複客戶、爭議等規則在 V1.2 後台，不在模板。
- 「AI 經營特助」是固定規則＋情境試算，沒有語言模型。
- 決策單驗收資料是模擬的 7 天，不是實際成效。
- 每種店型只模擬一項關鍵食材漲價；週、月時段資料是日資料乘營業日。
- 換店型只等比縮放份數與費用，同一店型內不同規模的經營差異沒有模擬。
- 實機（iOS Safari、Android Chrome、LINE 內建瀏覽器）、螢幕閱讀器、真人 30–60 秒計時都還沒測。
- 多店管理只有入口。
