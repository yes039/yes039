## 九宮格（005A 版）

| 今日營收 | 訂單與客單 | 產品銷售 |
|---|---|---|
| **食材成本** | **經營總覽（中央）** | **人事成本** |
| **外帶與外送** | **會員與回購** | **AI 經營特助** |

| 卡片 | 首頁 KPI | 燈號依據 | 詳細頁可操作 |
|---|---|---|---|
| 今日營收 | 營收、目標達成率、比昨日 | 達成率 | 近 7 天長條圖（含目標線）、渠道組成 |
| 訂單與客單 | 單數、客單價、比上週同日 | 營收比上週同日 | 營收差 = 單數效果 + 客單效果，每小時單數對比 |
| 產品銷售 | 飲品加點率 | 加點率下滑幅度 | 排行四種排序、菜單結構四象限 |
| 食材成本 | 理論食材成本率、關鍵食材漲幅 | 成本率 vs 店型目標、漲幅 | 影響產品表、**進價滑桿試算** |
| 經營總覽 | 營收、毛利、營業利益（估）、異常數 | 其他卡最差燈號；營業利益 < 0 即紅 | 今日／本月損益階梯、問題清單、明天待辦 |
| 人事成本 | 人事成本率、人數、工時 | 成本率、超時、離峰過多 | 排班甘特圖 × 每小時單數、**排班試算** |
| 外帶與外送 | 外送占比、抽成 | 外送扣抽成後貢獻率 | 渠道貢獻表、每份外送毛利、**外送加價試算** |
| 會員與回購 | 30 天回購率、LINE 好友 | 回購率 | 券活動漏斗、沉睡會員 |
| AI 經營特助 | 建議數、待辦數 | （資訊） | 今日摘要、3 項建議：查看依據／加入待辦／稍後處理 |

**不預設早、中、晚班**。營業時段分析、阿米巴獨立核算、多店管理放在首頁下方「進階功能」（第二層），時段由店家自訂（全日一段／兩段／三段／自訂）。

**營收、毛利、營業利益、淨利分開呈現**：每日畫面只算到「營業利益（估）」；「預估淨利」只出現在本月視圖，並標示「未經會計結算」。整個原型沒有任何地方把營收減食材成本稱為淨賺。

## 轉換路徑

看見今日戰況（30 秒摘要＋九宮格）→ 發現異常（燈號、需要老闆決定）→ 查看原因（詳細頁）→ 取得改善建議（AI 經營特助）→ 想像自己的店（換成我的餐廳：4 種店型＋單數、客單、人數、外送）→ 提出需求（30 秒需求回饋）。

全程不需要輸入營業數字或任何機密。

## 尚未完成的功能與限制

**本輪刻意不做（開發令邊界）**
- 未部署；未串接 POS、會計、外送平台、LINE；未呼叫任何 AI 或付費 API。
- 「AI 經營特助」的摘要與建議由固定規則依模擬數據產生，不是語言模型推論。畫面已標示。
- 需求回饋與體驗事件只存在使用者這台裝置（`localStorage`），不送出，不建立 CRM 商機，也不通知商務專人。
- 未修改水電、營造模板或 MIN-003 V1.2 原型。本 repo 內也沒有這些檔案，所以「沿用水電儀表板的成功元素」是依開發令描述重做，沒有比對原始碼。

**原型簡化（正式版需補）**
- 資料時間固定為「10/29（四）21:30 打烊後」，沒有營業中即時更新與「預估打烊營收」。
- 食材成本只模擬一項關鍵食材漲價，其他食材以正常進價計；理論成本不含損耗，月實際成本率用固定 2.2 個百分點差距估算。
- 時段的食材成本以當日平均成本率乘時段營收估算，正式版應依每張單的品項計算。
- 週、月資料是用日資料乘固定倍數產生，不是真的 7 天或 30 天明細。
- 會員數字（好友數、回購率、券漏斗）是固定比例縮放，不會隨店型改變行為。
- 換店型後的單數、客單只是等比縮放同一套份數結構；份數比例與漲價情境對每種店型都一樣。
- 所得稅以稅前淨利 20% 暫列，未區分公司、行號、小規模營業人。老闆本人薪資未計入人事成本（畫面已提示）。
- 多店管理只有入口與規劃說明，沒有模擬數字。
- 待辦沒有提醒、指派或到期日；「稍後處理」只是標記。
- 尚未做無障礙稽核（螢幕閱讀器、對比度全面檢查）；已有鍵盤焦點樣式與 reduced-motion 設定。

**待總指揮決定**
- 各店型的食材成本率目標（目前鐵板熱炒 32%、麵店 33%、咖啡廳 30%、便當店 38%）與人事成本率目標 25% 是否採用。
- 外送平台抽成以 32% 估算是否合適。
- 回饋表單的聯絡欄位與同意文字是否需法務確認（個資法告知事項）。
