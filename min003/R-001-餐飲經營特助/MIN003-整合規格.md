# R-001 × MIN-003 整合規格（草案）

本輪只定義介面，原型不連接任何追蹤後端。原型內的事件與回饋寫在使用者裝置的 `localStorage`（key：`r001-proto-v1`），可在首頁底部「整合事件紀錄」查看。

不影響現有水電、營造模板與 MIN-003 V1.2 原型：R-001 是獨立資料夾、獨立檔案，沒有共用程式碼或樣式。

## 1. 識別碼

| 欄位 | 值 | 說明 |
|---|---|---|
| `template_id` | `R-001` | 餐飲模板固定值 |
| `proto` | `G1-005A` | 原型版本，修正令改版時遞增 |
| `ref` | 網址 `?ref=` 參數，預設 `P-DEMO` | 推薦夥伴代碼 |
| `session_id` | `s_` + 8 碼隨機字串 | 同一裝置的一次體驗；重設不換 |

### 推薦夥伴專屬連結

```
https://<MIN-003 網域>/r001/?ref=<夥伴代碼>
```

- 夥伴代碼由 MIN-003 發放，格式建議 `P-` + 4 碼數字。
- 未帶 `ref` 時記為 `P-DEMO`，CRM 端歸「自然流量」。
- 若之後放進只允許 `#hash` 的嵌入環境，需改為 `#ref-P0001` 的 hash 格式。

## 2. 體驗事件

共同欄位：

```json
{"template_id":"R-001","proto":"G1-005A","ref":"P-0001","session_id":"s_ab12cd34","event":"card_open","props":{},"ts":"2026-10-29T13:30:00.000Z"}
```

| event | 觸發 | props |
|---|---|---|
| `page_view` | 開啟原型 | `landing`、`ref` |
| `card_open` | 進入任一卡片或頁面 | `card`（revenue、orders、food…） |
| `scenario_start` | 從導覽開始 S01–S05 | `scenario` |
| `scenario_complete` | 完成情境的關鍵動作 | `scenario` |
| `ai_action` | AI 建議的三個按鈕 | `action`（view_basis／add_todo／later）、`sid` |
| `todo_add` | 加入待辦 | `from`、`sid` |
| `mystore_apply` | 套用「換成我的餐廳」 | `preset`、`orders`、`ticket`、`staff`、`delivery`；店名只記是否填寫 |
| `cta_click` | 點「換成我的餐廳」或「我想了解專屬版本」 | `target`、`from` |
| `feedback_submit` | 送出 30 秒需求 | `pains`（數量）、`stores`、`pos`、`has_contact` |
| `reset` | 重設模擬資料 | — |

情境完成條件：S01 開啟經營總覽；S02 開啟產品銷售；S03 拖動食材進價滑桿；S04 切到排班試算；S05 任一 AI 建議按鈕。

## 3. 需求回饋 → CRM 商機

原型送出後顯示的資料格式（正式版 POST 到 MIN-003 後端）：

```json
{
  "template_id": "R-001",
  "proto": "G1-005A",
  "ref": "P-0001",
  "session_id": "s_ab12cd34",
  "submitted_at": "2026-10-29T13:35:00.000Z",
  "store_profile": {"preset": "noodle", "orders_per_day": 160, "ticket": null, "delivery": true, "staff": 5},
  "needs": ["不知道今天有沒有賺"],
  "stores": "1 家",
  "pos": "POS 系統",
  "contact": {"name": null, "value": "line: demo123", "consent": true},
  "journey": {"cards_viewed": ["overview", "food", "ai"], "scenarios_done": ["S01", "S03"], "todos": 1},
  "crm": {"action": "create_lead", "notify": ["line", "email"], "status": "NOT_SENT_PROTOTYPE"}
}
```

建議的後端處理（未實作）：

1. `POST /api/experience/feedback` 收件，驗證 `template_id` 與 `ref`。
2. 建立 CRM 商機：來源 = R-001、推薦夥伴 = `ref`、需求標籤 = `needs`、店型與規模 = `store_profile`、體驗深度 = `journey`。
3. 只有 `contact` 不為空且 `consent = true` 時才通知商務專人（LINE／Email）；否則只建立匿名商機統計。
4. 推薦夥伴可在 MIN-003 後台看到自己連結帶來的體驗數、完成情境數與商機數，不顯示客戶聯絡資料。

事件上報建議：`POST /api/experience/events`，前端批次送（每 10 筆或離開頁面時），失敗保留在本機重送。

## 4. 個資與機密

- 「換成我的餐廳」只收店型與區間數字，不收營業額、帳號或 POS 資料。
- 店名不寫進事件，只記「有填寫」。
- 聯絡方式只出現在回饋，且必須勾同意。正式版需補個資告知文字（蒐集目的、利用期間、聯絡窗口）。

## 5. 正式資料串接（下一階段）

| 資料 | 來源 | 對應卡片 |
|---|---|---|
| 訂單明細（品項、渠道、時間、折扣、會員） | POS | 今日營收、訂單與客單、產品銷售、外帶與外送、會員 |
| 配方（品項 × 食材用量）、進貨單價 | 店家設定、進貨單 | 食材成本 |
| 盤點 | 店家每月輸入 | 月實際食材成本率 |
| 排班、打卡 | 排班表或打卡系統 | 人事成本 |
| 外送平台結算 | 平台報表 | 實際抽成 |
| LINE 好友、券核銷 | LINE OA | 會員與回購 |
| 固定費用、目標 | 店家設定 | 經營總覽、阿米巴 |

AI 經營特助正式版應保留「每條建議附可追溯依據」的格式，模型產出的建議需能回連到原始數據。
