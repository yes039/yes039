# R-001 × MIN-003 V1.2 整合規格（G2-006）

G2 起，R-001 依《MIN-003 G1 技術設計書 V1.2》的模板契約實作，取代 G1 自訂的 `?ref=` 與事件名稱。本輪只在原型內模擬 `track.js`，不連任何後端。

**不影響既有模組**：R-001 是 `min003/R-001-餐飲經營特助/` 內的獨立檔案，沒有共用程式或樣式。V1.2 原型、技術設計書、封版報告、G2 市場驗證計畫、既有測試都沒有修改；只在 `min003/README.md` 索引新增一列 R-001 連結。合併後重跑 V1.2 既有測試：權限矩陣 34/34、手機操作 11/11。

## 1. 識別碼對照

| 項目 | V1.2 規則 | R-001 做法 |
|---|---|---|
| 模板識別碼 | `templates.id`，餐飲列為 `food` | 事件 `template_id: "food"` |
| 產品代號 | — | `product: "R-001"`、`ver: "G2-006"`，只作版本比較 |
| 客戶代碼 | `R` ＋ 3 位流水號，只在後台 | 模板不讀、不顯示 |
| 連結 | `/d/food?t={10 碼 Crockford Base32}` | 讀 `?t=`；Artifact 展示時另接受 `#t-連結碼`，讀到後從網址移除 |
| 推薦夥伴 | 夥伴連結碼與客戶連結碼格式相同，伺服器端判斷 | 模板只送連結碼，不知道是誰 |

G1 用的 `R-001` 當 `template_id` 會與 V1.2 的客戶代碼 `R001` 混淆，G2 已改正。

## 2. 模板契約（track.js 的本機模擬）

| 函式 | 送出 | 需同意 |
|---|---|---|
| `MIN.pageOpen()` | `page_open`（可見 2 秒後） | 否 |
| `MIN.consent(choice)` | `consent`（full／view） | — |
| `MIN.track(feature)` | `feature_click` | 是；「只看不記錄」時不送 |
| `MIN.task(name)` | `task_complete`（同一 session 每個任務一次） | 是 |
| `MIN.consult(feature)` | `consult_click` | 否（客戶主動） |
| `MIN.submit(type, payload)` | `feedback_submit` 或 `booking_submit` | 否；聯絡方式另需勾選同意 |

事件欄位與 V1.2 `events` 表一致：`session_id, token, template_id, type, feature, consent_level, internal, ts, dedup_key`。`page_open` 與 `feature_click` 以「連結碼＋session＋事件＋功能＋30 分鐘時間桶」去重。

告知與同意卡文字沿用 V1.2 第 3.2 節，只把開頭改成「這是餐飲 AI 經營特助的體驗頁」。頁尾有「隱私選擇」可隨時改。

## 5. 表單 payload（原型顯示「正式版會送出的資料」）

```json
{
  "cta": "booking",
  "template_id": "food",
  "product": "R-001",
  "ver": "G2-006",
  "session_id": "s_xxxxxxxx",
  "token": "HXEZ2JM5KR",
  "submitted_at": "2026-10-29T13:35:00.000Z",
  "profile_preset": "teppan",
  "store_profile": {"preset":"teppan","orders_per_day":107,"ticket":499,"staff":8,"delivery":true,"custom":false},
  "want_custom": "預約專人診斷",
  "top_issues": ["food","attach","rev"],
  "booking": {"way":["視訊"],"time":[],"need":[]},
  "contact": {"name": null, "value": "line: demo123", "consent": true},
  "journey": {"scenarios_done":["S01","S03"],"cases_closed":1},
  "crm": {"stage":"預約洽談","notify":"NOT_SENT_PROTOTYPE"}
}
```

- 不含店名：店名只用於畫面，不寫入事件或表單。
- `store_profile` 只有店型與區間數字，不是營業機密。
- 通知內容依 V1.2 第 7.2 節最小化：商務專人通知只帶客戶代碼、店型、需求重點與後台連結，不放聯絡方式；夥伴通知只有進度。

## 6. 本機儲存

- `localStorage` key：`r001-proto-g2`（與 G1 的 `r001-proto-v1` 分開，不互相影響）。
- 存放：店家設定、決策單進度、待辦、隱私選擇、事件（最多 400 筆）、表單。
- 「重設模擬資料」清除店家設定、決策單、待辦，保留事件、表單與隱私選擇，以便測試歸因。
