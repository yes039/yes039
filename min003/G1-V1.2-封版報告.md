## 2. 補正一：匿名體驗紀錄補歸因與同意管理

### 2.1 為什麼這是個資問題
- 連結碼本身不含姓名電話，但後台可以把它對應到特定公司與窗口，所以**體驗事件一旦能對應到客戶，就屬於可間接識別的個人資料**，要符合個資法的告知、特定目的與目的內利用（個資法第 8、19、20 條的要求）。
- 推薦夥伴連結的匿名 session 在客戶留下資料前無法識別個人；**客戶留下資料、事件被補歸到客戶的那一刻**，等於把先前的行為資料和個人連結起來，必須事先告知並在同意範圍內。

### 2.2 補歸因規則（封版版本已落實到原型）

| 規則 | 內容 | 原型 |
|---|---|---|
| R1 只補歸已同意的事件 | 只有客戶選「同意記錄操作」後產生的事件可以補歸；未同意時本來就不會產生操作事件 | ✅ 模擬案例第 3 步只補歸同意後事件 |
| R2 頁面開啟不補歸到個人 | 未同意時的 `page_open` 只計入夥伴連結的匿名統計 | ✅ |
| R3 送出前告知 | 回饋表單送出鈕上方說明：「您剛才在這個頁面的試用紀錄（只限您同意記錄的部分）會和這份回饋一起交給負責同仁，用來準備說明內容；保存 12 個月，可隨時要求刪除」 | ✅ 已加入 |
| R4 同一個 session、24 小時內 | 只補歸同一瀏覽器 session、送出前 24 小時內的事件；不跨裝置、不用指紋辨識 | 設計書規範，正式開發實作 |
| R5 同意紀錄可追溯 | 補歸時寫入同意紀錄編號與告知文字版本 | 設計書規範 |
| R6 撤回 | 客戶撤回同意後停止記錄；已補歸的操作明細依刪除政策處理（預設 30 天內刪除明細，只留統計） | 設計書規範 |

### 2.3 技術邊界（做不到或刻意不做）
- **跨裝置串連**：客戶在手機開、電腦填，系統不會也不嘗試把兩邊連起來（不做指紋、不放第三方 Cookie）。
- **LINE 內建瀏覽器**：可能清除 `sessionStorage`，同一人隔天再開會變成新 session；補歸只看同一 session，所以可能少補，不會多補。
- **轉傳**：客戶把夥伴連結轉給同事，事件仍記在同一條夥伴連結下；只有實際留下資料的人才會建檔。
- **未同意者的行為分析**：一律不做；漏斗的「實際操作」數因此是下限。

## 3. 補正二：推薦夥伴報備的個資告知與資料最小化

夥伴報備屬於**間接蒐集**（資料不是向客戶本人蒐集），依個資法第 9 條，總部須在處理或第一次聯繫時告知資料來源與第 8 條的應告知事項。

| 設計 | 內容 | 原型 |
|---|---|---|
| 欄位最小化 | 只收**公司名稱**（必填）與**公司電話**（選填，限市話或代表號），不收窗口姓名、個人手機、身分證、家庭或財務資料 | ✅ 表單已改；填入個人手機格式會被擋下 |
| 夥伴的告知義務 | 勾選「我已告訴對方會由總部聯繫，並取得同意提供公司名稱與電話」才能送出 | ✅ |
| 總部首次聯繫告知 | 第一次聯繫時說明：由哪位夥伴推薦（或「合作夥伴推薦」）、聯繫目的、資料保存期間、可拒絕並要求刪除；聯繫紀錄勾選「已告知來源」 | 設計書規範；G2 用話術卡執行 |
| 對方拒絕 | 立即刪除報備資料，歸因紀錄只留「已撤回」 | 設計書規範 |
| 保存期限 | 未受理或不歸因的報備資料，`未受理報備保存天數`（預設 90 天）後自動刪除 | ✅ 參數化 |
| 比對用電話 | 報備時電話只存雜湊值用於比對重複；總部受理後才存明文 | 設計書規範 |
| 不透露其他夥伴 | 重複報備只回覆「已有其他夥伴推薦」 | ✅（權限測試第 29 項） |
| 合作協議條款 | 夥伴須遵守：只報備已同意的對象、不得自行報價承諾、不得外流示範資料、違反可停權 | 待法務起草（D10） |

## 4. 補正三：佣金與歸因參數化

原型「佣金結算」畫面新增**參數設定**（僅總部管理者可改），程式裡不再寫死這些數字。

| 參數 | 預設 | 允許範圍 | 生效方式 |
|---|---|---|---|
| 預設佣金比例 | 10% | 0–30% | 新夥伴的預設值；個別夥伴可依合作協議另訂 |
| 佣金上限（每筆） | 0（不設） | ≥ 0 | 新建立的佣金 |
| 歸因保護期 | 90 天 | 30–365 天 | 新成立的歸因 |
| 冷卻期 | 14 天 | 0–90 天 | 待核准的佣金 |
| 續約佣金 | 不給 | 不給／比例給付 | 新成交 |
| 續約比例／次數 | 5%／1 次 | 0–30%／≥1 | 續約佣金開啟時 |
| 爭議處理期限 | 7 天 | 1–30 天 | 新提出的爭議 |
| 未受理報備保存 | 90 天 | 30–365 天 | 排程刪除 |

- **版本化**：每次儲存版本號 +1，寫入變更紀錄（誰、何時、哪些值由多少改成多少）。
- **快照**：佣金建立當下記錄比例、上限與參數版本；之後改參數**不影響已建立的佣金**（測試第 33、34 項驗證）。
- 正式版資料表：`settings(key, value_json, version, changed_by, changed_at)`，`commissions` 增加 `cap`、`settings_version`。
