## 四、第一批真實資料怎麼進來（最小人工輸入）

**建議做法：你用對話回報 → 我寫進事件檔 → 手機頁重新發布。**

```
你在對話裡說一句話
  例：「素材卡住了，等報名 QR code」
        ↓
我轉成一筆事件，追加到 war-room/campaigns/C001/events.json
  {時間, 節點, 事件, 原因, 回報人}
        ↓
手機頁讀這份事件檔，依序重播進 HQ，算出戰況
        ↓
你打開手機看到的，就是事件檔記錄的現實
```

- **好處**：不用做任何輸入介面；每一筆都有時間、原因、誰回報；git 歷史就是完整軍情紀錄；重新整理不會掉。
- **代價**：每次更新要經過我；從你回報到手機看到約一兩分鐘。
- **之後可升級**：如果回報頻率高，再做「手機上直接點選回報」（需要另外確認 Artifact 的資料儲存能力），這是第二階段的事。

另外需要一份 `facts.json`（招生基本資料＋每日名單／報名數字），同樣由你口述、我寫入。

**動工時預計的最小改動**（確認後才做）：
1. 新增 `war-room/campaigns/C001/events.json`、`facts.json`。
2. 新增實戰頁（沿用掌上戰情），把演練腳本換成讀事件檔；DEV 區拿掉。
3. 摘要卡加一行戰果：「報名 x／名額 y」。
4. 更新 C001 Config 的節點文字。
5. 引擎、兵陣 layout、V3.1 邏輯不動。

## 五、盤點時發現的一個現實與模型的落差（需要你決定）

**現實不是線性的：影片 v1（M002）在「報名資訊」這份素材還沒到位之前就先做出來了。**

但目前引擎規則是「素材 DONE 才能開始製片」。如果照實記錄：
- 素材：WAITING（等報名資訊）
- 製片：引擎不允許在素材完成前開工，所以無法記錄「v1 已做好」。

可選的處理方式（第一階段不改引擎）：
- **(a)** 把現在的 M002 視為「草稿」，正式的製片 Mission 等報名資訊補齊後才開，屆時把資訊加進影片再交貨。手機會顯示「卡點：素材 · 等報名資訊」——**這最接近真實的阻塞點**。
- **(b)** 把素材拆成「影片素材」與「報名資訊」兩個節點，製片只依賴前者。這要改 C001 Config 的陣型。

建議先用 **(a)**，因為真正擋住招生的是「報名資訊還沒有」，不是影片。
