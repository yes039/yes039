## 設計決定

| 決定 | 理由 |
|---|---|
| 出片交給 CapCut，Claude 只做規劃、字卡、文案、檢查 | 老闆帳號直接出片沒有證據；CapCut 是成熟的消費級 App，不用碰程式 |
| 用「母片＋逐格取代」重複使用模板 | C 無法產出 CapCut 專案檔；CapCut 公開範本（Remake）是公開發布功能，不適合店家私用 |
| 配樂用我方原創，不用 CapCut 音樂庫 | CapCut 一般音樂限非商業；商用音樂只限 CapCut／TikTok，不含 FB、IG、YouTube（06 查證） |
| 沒有旁白 | 沒有可商用的台灣口音配音（MPT-002、商品化準備報告） |
| 剪輯卡不用表格 | Claude 手機 App 看寬表格要左右滑 |
| 換店只換資料卡 | 指令、模板、教材、配樂全部跨店共用 |

## 遵守的執行原則

| 原則 | 做法 |
|---|---|
| 不新增 AI 工具 | 只用 Claude（老闆帳號）＋CapCut |
| 不開發軟體或平台 | 沒有新系統。配樂與佔位圖用兩支一次性產生素材的小腳本（numpy、Pillow），放在 `03-CapCut模板/素材/source/` 供重現；老闆端不需要執行任何程式 |
| 不修改 UZI-01 及既有影音系統 | 沒有動任何既有分支、成片或原始碼 |
| 模板與指令可跨店重複使用 | 見「設計決定」最後一列 |
| 不把 C 代製影片當驗收證據 | 演練說明明文排除；工時表把「開箱示範片」標為選配、不算證據 |
| 不試賣、不收費、不對外承諾 | 所有文件標示 8,800 為候選價 |

## 已知限制（演練前就知道的）

1. CapCut 按鈕名稱、「複製專案」「取代」的實際行為：C 沒有 CapCut，只能依一般操作描述，要演練確認（06 V1～V7）。
2. 兩首配樂 C 聽不到，只量過響度；好不好聽要 Shen 判斷。
3. 在 Claude 手機 App 建 Project、上傳資料卡的步驟沒有實測，教材寫了「找不到就用瀏覽器」的備案。
4. 每家店工時 6 小時的預算是推估；8,800 元下毛利約 22%，達不到 50% 門檻。這一階段先記錄，不處理。
5. Shen 演練通過，仍然不能證明非技術老闆能獨立操作；那要等第一家店試點。
