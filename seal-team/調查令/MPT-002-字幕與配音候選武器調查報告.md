## 1. 影片來源查核

- 影片內容：騰訊 **WorkBuddy** 的推廣短片「十個視頻 Skill，視頻一條龍」（字幕標 AIKEY27），13 頁，結尾是「留言 wb888，發你安裝包」。
- 影片**沒有給任何網址或 GitHub 連結**。畫面上的「AgentCaption」「VideoDubbing」是標籤，不一定是正式名稱。
- 因此下面的「官方來源」是用**功能比對**找出來的最接近專案，不是影片作者確認的來源。
- 同一支影片的其他項目查得到對應開源專案（例如 VideoSubtitleTranslator → [oomol-lab/video-subtitle-translator](https://github.com/oomol-lab/video-subtitle-translator)），所以「影片是在整理 GitHub 上的開源 Skill」這個推論算合理，但仍屬推論。

影片對兩項的描述（畫面原文）：

| 標籤 | 畫面列點 | 旁白字幕 |
|---|---|---|
| AgentCaption｜自動字幕 | 識別人聲對齊時間軸／字幕直接燒錄／支持本地運行 | 口播、課程、播客、Shorts 都特別省時間，而且支持本地運行 |
| VideoDubbing｜外語配音 | 識別翻譯配音一體／中改英日版本／多語言帳號必備 | 一條中文視頻，直接改成英文版、日文版 |

## 2. UZI-01 目前的具體問題（評估基準）

依 repo 內現有紀錄整理。新工具必須解決其中一項，才有理由進入實測。

| # | 現況問題 | 出處 | 跟字幕／配音有關嗎 |

| P3 | 店家實拍口播影片的字幕，目前由隊長在 CapCut 用自動字幕處理（H3 人工組片） | `README.md` 第 4、5 節、`武器配置表.md` | 有關，但換器條件「組片單支 > 30 分鐘連續 2 次」**尚未觸發**（無紀錄） |

## 3. 候選一：AgentCaption｜AI 自動字幕

### 3.1 逐題回答

| # | 問題 | 答案 | 依據 |
|---|---|---|---|
| 1 | 官方來源／GitHub | 最接近：[ahkamboh/agent-caption](https://github.com/ahkamboh/agent-caption)（個人專案，約 26 星、30 commits） | GitHub 頁面 |
| 2 | 是否存在？功能一致？ | **存在，功能大致一致**：語音辨識 → 逐字對齊時間軸 → 燒錄字幕成 `.captioned.mp4`，另出 `.srt`／`.vtt`；標榜 100% 本機執行。差異：主打印度式英語夾雜（Hinglish），中文只是「支援語言之一」 | README、SKILL.md |
| 3 | 費用 | 程式免費。首次安裝要下載約 **4 GB** 模型；之後在本機跑，沒有 API 費。是否需要 GPU、CPU 跑多慢：**待驗證** | README（Requires: Python 3.10+, ffmpeg, ~4 GB disk） |
| 4 | 商用授權 | 程式本身 **MIT**，可商用。**但要注意**：它的萬用對齊器 `mms_align.py` 用 Meta MMS_FA 模型，授權是 **CC-BY-NC 4.0（禁止商用）**。中文走 whisperX 預設的 `jonatasgrosman/wav2vec2-large-xlsr-53-chinese-zh-cn`（授權：待驗證）。商用交付時必須確認中文流程**不會退回 MMS** | [torchaudio MMS_FA 文件](https://docs.pytorch.org/audio/main/generated/torchaudio.pipelines.MMS_FA.html)、[HF mms-1b-all 授權討論](https://huggingface.co/facebook/mms-1b-all/discussions/1)、[whisperX alignment.py](https://github.com/m-bain/whisperX/blob/main/whisperx/alignment.py) |
| 5 | Claude 能直接調用？ | **能**。附 `SKILL.md`、`CLAUDE.md`、`AGENTS.md`，就是寫給 Claude Code 這類 agent 照著跑的命令列工具（`caption.py --lang zh --srt ...`） | README |
| 6 | 能接入 UZI-01？ | **能，且不用改架構**：輸入影片、輸出 `.srt` 和燒錄後 mp4，正好對上 `02-製作/字幕.srt` 的交接格式。待補：輸出是否為**繁體中文**（Whisper 中文常出簡體，可能要另接 OpenCC 轉換）——**待驗證** | 契約 `contracts/02-製作紀錄.md` |
| 7 | 與 FFmpeg／Remotion 差異 | FFmpeg 只會「燒」字幕，不會「聽」；Remotion／我們的 Playwright 渲染也一樣，字幕時間要自己給。AgentCaption 多做的是**聽打＋對時間**，最後燒錄其實也是交給 ffmpeg | — |
| 8 | 更成熟／更便宜的替代 | ① 直接用 [whisperX](https://github.com/m-bain/whisperX)（廣泛使用的開源專案，授權待核對）＋ ffmpeg：AgentCaption 本來就是包它的；② **CapCut 自動字幕**（現行，已在用，免費）；③ 有腳本的影片：維持現行「腳本直接出 SRT」，**零成本、零辨識錯誤** | — |

### 3.2 五項評分

| 指標 | 分數 | 依據 |
|---|---|---|
| 商用合法性 | **3** | 程式 MIT；但內含 CC-BY-NC 模型路徑，中文對齊模型授權未查清 |
| 製作成本 | **5** | 免費、本機執行、無 API 費（硬體需求待驗證） |
| 成片品質 | **待驗證** | 沒有找到台灣口音中文、繁體輸出的實測資料；專案主力是 Hinglish |
| 整合難度 | **4** | 命令列＋SKILL.md，Python＋ffmpeg 我們已有；扣分在 4 GB 模型與繁簡轉換 |
| 實際交付價值 | **2** | 目前影片字幕來自腳本（P2 已解決）；只在實拍口播（P3）有用，而 P3 尚未觸發換器條件 |

### 3.3 判定：**B｜收藏觀察**

升級為 A（進入實測）的條件，任一成立即可：
1. P3 觸發換器條件：隊長在 CapCut 組片單支 > 30 分鐘、連續 2 次，且主要卡在字幕；或
2. 開始接「店家實拍口播」類型任務，需要 Claude Code 端直接產出字幕與燒錄成片。

實測時要先驗證：台灣口音辨識率、繁體輸出、確認不走 MMS 路徑、CPU 處理 1 分鐘影片要多久。

## 4. 候選二：VideoDubbing｜AI 影片配音

### 4.1 逐題回答

| # | 問題 | 答案 | 依據 |
|---|---|---|---|
| 1 | 官方來源／GitHub | **查無同名專案，身分待驗證**。功能最接近：[InsiderX-Pro/video-translator](https://github.com/InsiderX-Pro/video-translator)（「Real time video translation / dubbing skill」）。其他同類：[jianshuo/claude-skills](https://github.com/jianshuo/claude-skills) 的 `wjs-dubbing-video` | GitHub 搜尋 |
| 2 | 是否存在？功能一致？ | InsiderX-Pro 版**部分一致**：流程含背景分離、說話人分離、語音辨識、翻譯、聲音複製、配音、字幕、合成，符合「識別翻譯配音一體」。**不一致**：目標語言**只有中文、英文**，影片說的「日文版」做不到 | README |
| 3 | 費用 | 程式是**雲端服務的遙控器**，實際運算在 `audiox-api-global.luoji.cn`，需 API 金鑰、按 token 計費（錯誤訊息有「Token insufficient」），**價格未公開——待驗證** | README |
| 4 | 商用授權 | 程式碼 MIT，但真正的服務條款、輸出成品的商用權利、上傳影片的資料處理：**全部待驗證**。另：聲音複製涉及配音者本人同意 | README |
| 5 | Claude 能直接調用？ | 技術上可以（curl＋python3，附 `SKILL.md`），但寫給 OpenClaw，Claude Code 相容性**待驗證**。回傳的是 `preview_url`，不是直接給檔案 | README |
| 6 | 能接入 UZI-01？ | 勉強可以，但要把**客戶影片上傳到身分不明的第三方雲端**，違反現行「素材留在店家／本機」的做法 | — |
| 7 | 與 FFmpeg／Remotion 差異 | FFmpeg 只能混音、換音軌；我們現行 TTS（zhtts）只會念中文。它多做的是翻譯＋外語配音＋聲音複製 | — |
| 8 | 更成熟／更便宜的替代 | ① [ElevenLabs Dubbing API](https://elevenlabs.io/pricing/api)：第三方整理約 **US$0.33／分鐘（有浮水印）、US$0.50／分鐘（無浮水印）**，官方頁待核對；② [BytePlus AI 配音](https://docs.byteplus.com/zh-CN/docs/byteplus-media-live/ai_dubbing)：約 US$0.11／分鐘；③ 開源本機：pyVideoTrans、VideoLingo（授權與品質待驗證）；④ jianshuo `wjs-dubbing-video`（MIT，中文走豆包 TTS、其他語言走 edge-tts） | 各連結 |

**可信度警示**：InsiderX-Pro/video-translator 有約 928 顆星，但只有 3 個 commit、1 個 fork，星數與活躍度明顯不成比例，不宜當作成熟度證據。

### 4.2 五項評分

| 指標 | 分數 | 依據 |
|---|---|---|
| 商用合法性 | **2** | 程式 MIT，但雲端服務條款、成品權利、資料處理皆未公開 |
| 製作成本 | **待驗證** | 按 token 計費，價格未公開 |
| 成片品質 | **待驗證** | 無公開實測；只支援中英 |
| 整合難度 | **3** | 呼叫簡單，但需外部金鑰、上傳影片、回傳網址再下載 |
| 實際交付價值 | **1** | 沒有任何任務需要外語版（P4 無需求）；也解決不了 P1（中文聲音太年輕） |

### 4.3 判定：**C｜不予採用**

日後若真的出現「同一支片要出英文／日文版」的付費需求，再另開調查令，優先比較 ElevenLabs、BytePlus 這類**價格公開、條款清楚**的服務，不從這支影片的來源下手。

## 5. 附帶發現：真正卡住的是 P1（中文配音音色）

兩項候選都**不解決** P1。P1 的方向是「更好的中文 TTS 或真人配音」，不是字幕或翻譯工具。供 Shen 參考，**本次不建議採用、不展開**：

| 方向 | 說明 | 狀態 |
|---|---|---|
| 真人配音 | M002 README 已建議；換掉 `vo0–vo5.wav` 重跑 `mix.py` 即可，流程不用改 | 現成可行 |
| Azure 台灣華語神經語音 | 有 zh-TW 聲音；中國區官方價 ¥95.4／百萬字、每月 50 萬字免費（[azure.cn](https://www.azure.cn/en-us/pricing/details/cognitive-services/)）；30 秒片約百字，成本近乎零 | 國際區價格、具體聲音分級待驗證 |
| CosyVoice（開源 TTS） | 可本機跑、支援中文；授權據二手來源為 Apache-2.0 | 官方授權檔待驗證 |

如需處理 P1，建議另開 MPT-003。
