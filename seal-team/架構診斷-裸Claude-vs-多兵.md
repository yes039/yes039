# 架構診斷｜為什麼裸 Claude 比「企劃兵 → 製片兵」順？

> 只做診斷，不重寫架構。依據：兩個口頭案例（玉欣珍 MV、壽司郎短影音）＋本 repo 現況（`roles/`、`contracts/`、`missions/M001`、`missions/M002`）。

## 0. 先講結論

1. **多 Agent 本身不是病因，切口位置才是。** 目前的設計把「企劃 → 製作」這個高度耦合的創作迴路從中間切開，並在切口上加了三道鎖：「逐字沿用、不得改」、「未核可不動工」、「缺素材就停工」。Claude 的強項（看素材 → 想概念 → 寫字 → 對節奏 → 回頭改字）剛好就發生在被切開、被鎖住的那一段。
2. **這套架構有一個已被推翻的前提。** `README.md` 第 7 節與製片兵卡片寫的是「Claude 不能直接剪片 → 製片兵產剪輯單，隊長在 CapCut 組片」。但 M002 已經由 Claude 從腳本、TTS、配樂、混音一路做到 1080×1920 成片。結果製片兵被設計成「文書兵」，真正的製作反而落回人身上。
3. **repo 本身就是證據。** M001（照三兵流程走的演習）資料夾全是空的 `.gitkeep`；M002（真的出片的那次）完全沒有作戰令、沒有製作紀錄，直接一個主體做完。要真的出片時，流程自然走回單體模式。
4. **病因排序（最可能 → 較不可能）：架構前提與目標錯置 ＞ 角色切口位置 ＞ 交接資訊損耗 ＞ Prompt 規訓。** Prompt 規訓比較像放大器：它讓切口的問題更明顯，但只拿掉規訓不會解決。
5. **你們設計裡真正好的部分要留下**：戰果兵的獨立性、判讀規則先寫好、戰果庫、人工節點誠實標示、「換器前先換 Prompt」。問題只在於，這套「實驗管理紀律」被套進了「創作過程」。

## 1. 為什麼裸 Claude 直接拿素材做，反而可能比較好？

| 機制 | 裸 Claude | 企劃兵 → 製片兵 |
|---|---|---|
| **對素材的理解** | 看照片時產生的判斷（「這張光線最好，適合收尾」、「這個表情可以當 Hook」）直接變成剪輯決策 | 企劃兵的判斷要先寫成文字；製片兵讀的是《素材清單》的**文字描述**，不是它自己對照片的感受。視覺判斷在交接時被壓成文字，大部分寫不出來 |
| **迭代迴路** | 寫旁白 → 發現長了 2 秒 → 當場改字或改鏡頭，一個腦袋裡幾秒完成 | 同樣的事是一次往返：「作戰令文案超過影片長度 → 回報企劃兵，不自行刪字」 |
| **文字、聲音、畫面的關係** | 三者互相調整出來。M002 的 `vo_starts.json`、切點對齊音樂小節、旁白出現時音樂自動壓低，都是**互相遷就**的結果 | 文字先凍結（逐字），畫面和聲音只能配合。等於規定創作只能單向流動 |
| **人審的是什麼** | 審一支看得到的片，回饋很具體（「第 3 秒太快」） | 審一張紙上作戰令，等於核可一個想像中的影片，很難判斷好壞，而且核可之後還不能改 |
| **注意力花在哪** | 花在作品上 | 大量 token 花在填表：編號、偏差紀錄、判讀規則、核可欄 |
| **模型的預設姿態** | 主動補位、做出判斷 | 卡片寫滿「不得」「停止」「不動工」「不自行補」，Claude 會非常守規矩，結果就是多問、多停、多表格。這不是 Claude 變笨，而是它被要求「不要把事情做完」 |

補充一個誠實的保留：兩個成功案例都是單次、沒有盲評，裸 Claude 的優勢有一部分可能來自「第一次的驚喜感」。所以下面第 7 節的驗證設計才重要。

## 2. 問題最可能出在哪一層？

### (1) 架構本身：前提錯誤＋目標錯置（最主要）
- **前提錯誤**：假設 Claude 不能出片，所以把製片兵定義成產剪輯單。這個前提在 Claude Code 環境已不成立（M002）。
- **目標錯置**：整套設計真正在優化的是「**可歸因的行銷實驗**」（一片一測試點、預寫判讀規則、戰果庫）。這是很好的實驗管理框架，但它應該約束「**發布什麼、怎麼量**」，而不是「**怎麼做出來**」。現在它往上游滲透，連 Hook 都要逐字凍結，只為了讓測試點乾淨。

### (2) 角色拆分：切口位置錯（次要，但很關鍵）
影片裡「企劃」和「製作」的邊界本來就不存在：
- Hook 同時是文字、畫面，也是節奏。
- CTA 的長度取決於旁白秒數。
- 用哪張照片會決定故事怎麼講，而不只是「執行」。

所以「企劃決定腳本、製片只能執行」這條線，切在了最需要來回協商的地方。

### (3) 交接資訊損耗（真實存在，但它是切口錯誤的後果）
具體損耗在：
- 照片 → 素材清單文字（視覺壓成文字）。
- 模板只傳 **what**（分鏡、逐字文案），不傳 **why**（為什麼選這個 Hook、哪張照片是王牌、情緒曲線是什麼）。
- 製片兵被禁止回頭質疑，所以損耗無法被發現、也無法被修正。

### (4) Prompt 規訓（放大器）
點名最傷的幾條：
- 製片兵：「Hook、核心文案、CTA 必須逐字沿用，只能調整斷句」
- 製片兵：「隊長核可欄空白 → 不動工」
- 製片兵：「任一鏡頭缺素材 → 停止產出」
- 企劃兵：「完全依模板欄位輸出，不增刪欄位」

**怎麼區分是(2)(3)還是(4)？** 做一個 2×2 的小實驗（可放在 B 組裡）：
- 單一 Claude＋全部規訓（不拆）→ 如果變差，病在規訓。
- 拆成兩個 Agent、但拿掉規訓，交接用自由 brief＋原始照片 → 如果還是變差，病在拆分／交接。

## 3. 影片這種高耦合創作，是否本來就不適合拆成企劃 Agent → 製片 Agent？

**按「階段」拆（企劃 → 製片）不適合；按「別的軸」拆可以。**

| 可以切出去的 | 為什麼可以 |
|---|---|
| 素材篩選／整理（例：200 張照片挑 20 張） | 介面窄：輸出「候選清單＋原圖路徑＋一句理由」，下游仍然看原圖 |
| 事實與合規檢查（價格 500 元、時間地點、60+ 用語是否冒犯、有無誇大宣稱） | 可驗證、可對照清單，也不需要創作脈絡 |
| 技術產線（TTS、配樂、渲染、混音、字幕燒入） | 這是**工具**，不是兵。M002 的 `source/` 就是現成的武器 |
| 發布後判讀（戰果兵） | 時間上天然解耦（48h／7d 後才有輸入），而且需要獨立於創作者 |

| 不該切開的 |
|---|
| 概念 → 文案 → 選圖 → 節奏 → 剪輯 → 回頭改文案，這整個迴路 |

如果一定要保留「企劃」這一步，它的輸出應該**往上移**到 **brief**（目標、對象、必含事實、禁區、CTA、成功標準），不要包含逐字腳本和分鏡。腳本屬於製作。

## 4. 企劃兵、製片兵應該變成 Skill／武器嗎？

**是，大部分應該。** 但要改的不只是形式，還有內容：

- 現在的職責卡主要寫的是**身分＋禁令**（「你只負責…」「你不能…」）。在單一主體底下，身分與禁令沒有意義，甚至有害。
- Skill 應該寫的是**能力＋知識＋檢查表**，讓 Claude 在需要時自己拿來用：

| 原兵位 | 改成的 Skill（示意，不是現在就要寫） |
|---|---|
| 企劃兵 | 怎麼從素材寫出 brief；60+ 受眾洞察（字級、語速、避免「學不會」的焦慮詞）；Hook 模式庫；CTA 規範；怎麼讀戰果庫 |
| 製片兵 | M002 那套管線（渲染、TTS、配樂、混音、字幕規格、9:16 安全框、-14 LUFS）；出片 QA |
| 製作紀錄 | 改成「交付單」：成片完成後由 Claude 自動對照 brief 產出一頁，列出做了什麼決定、為什麼，以及與 brief 的差異。紀錄是事後產出，不是事前閘門 |

原則：**規則放在出口（驗收），不要放在入口（過程限制）。**

## 5. 什麼情況才真的值得拆成獨立 Agent？

值得拆（至少符合一條）：
1. **需要獨立判斷**：自己審自己的作品會手下留情 → 審片／合規 reviewer 用獨立 context，只看成片＋brief，不看製作過程。
2. **時間解耦**：輸入在很久之後才出現（戰果兵）。
3. **上下文隔離**：大量素材或長資料會淹沒主體的注意力 → 丟給 subagent 摘要，但要回傳原始檔路徑，不能只回傳文字描述。
4. **並行**：同一份 brief 同時做 3 個 Hook 版本。
5. **不同權限或工具**：發布帳號、付費 API、不同模型成本。
6. **不同的人負責**：交接點剛好也是組織裡責任轉移的地方（例如店家核可價格）。

不值得拆：
- 只是因為「職務名稱不同」。
- 交接介面需要來回協商（高耦合）。
- 下游無法直接存取上游看過的原始資料。

一句話判準：**切在介面窄、可驗證的地方；不要切在需要來回商量的地方。**

## 6. 目標是「保留 Claude 原生能力，同時穩定、可複製、可管理」，方向會是什麼？

（原則層級，等 A/B/C 數據出來再決定要不要改架構）

1. **一個主體端到端出片。** 導演 Claude 從素材一路做到成片，不在中間設閘門。
2. **人給的輸入縮成一張「任務卡」**：目標、對象、必含事實（500 元、時間、地點、報名方式）、禁區、交期。這是人寫的事實來源，不是企劃兵的產物。M002 最後缺報名資訊，就是缺這張卡。
3. **Skill 當武器、按需載入**，內容是知識、配方與檢查表，不是禁令。
4. **穩定性來自出口檢查**：一份硬性 Definition of Done（規格、事實正確、字幕安全區、響度、CTA 出現）＋一個獨立審片 Agent。
5. **可複製性來自保存產物**：每次保存任務卡、素材、`source/`、成片、Claude 自寫的 5 行「決策日誌」（為什麼選這個 Hook／這張照片）、人的回饋。可複製的是**產線與紀錄**，不是**流程表單**。
6. **可管理性來自人審「成品」而不是「計畫」**：人的關卡改成看成片，或看低解析的 animatic／3 版縮圖，不是核可紙上作戰令。
7. **實驗紀律移到發布層**：戰果兵、判讀規則、戰果庫全部保留，但測試變數用「同一支片做 Hook 變體」產生，不靠凍結創作過程。
8. **規則要靠證據才長出來**：只有裸 Claude 在同一類問題上重複失敗，才新增一條規則，並記錄是哪次失敗觸發的（這跟你們「換器前先換 Prompt」的精神一致）。

## 7. 第三案例（60+、500 元 AI 體驗課招生影片）A/B/C 驗證要記錄什麼

### 7.1 先把實驗做乾淨（不然數據沒意義）

| 風險 | 做法 |
|---|---|
| **污染**：本 repo 已有 M002（同主題「60+ 學 AI」），也有職責卡 | A 組必須在乾淨環境跑：不掛這個 repo、不掛 Project instructions、不帶記憶 |
| **輸入不一致** | 三組用**同一批照片＋同一張任務卡**（逐字相同），一定要含 500 元、時間、地點、報名方式。否則 A 組會因為缺資訊輸，這不是架構問題 |
| **只跑一次** | 每組至少跑 3 次；LLM 變異大，單次比較沒有意義 |
| **人的回饋不一致** | 評比「第一版成片」＋「一輪標準化回饋後的第二版」。標準化回饋 = 同一段文字發給每一組 |
| **評審知道是哪組** | 盲評：影片隨機編號，評審不知道來源 |
| **B 組沒跑** | 「逐步加能力」只會得到 A → C 的曲線。要判斷 Agent 分工，B 組（現行企劃兵 → 製片兵，照原樣）必須用同一案例跑 |

建議的組別：
- **A**：裸 Claude（照片＋任務卡）
- **B**：現行企劃兵 → 製片兵（照原卡片，不修改）
- **C**：單一 Claude＋Skill（逐步加：C1 加 60+ 受眾知識、C2 加製作管線、C3 加 DoD＋獨立審片 Agent）
- （選配診斷）**B′** 拆兩個 Agent 但拿掉規訓，交接給原圖＋自由 brief；**A′** 單一 Claude＋全部規訓。用來分辨病在「拆分」還是「規訓」

### 7.2 指標

**A. 成品品質（盲評，最重要）**
| 指標 | 怎麼量 |
|---|---|
| 配對偏好 | 兩兩比較「哪一支比較會讓 60+ 長輩想報名」。比絕對分數可靠 |
| 前 3 秒 Hook | 1–5 分 |
| 訊息清楚度 | 看完一次後，觀眾能不能說出：什麼課、多少錢、給誰、怎麼報名（4 題，答對數） |
| 對象適配 | 字級、語速、用語是否讓長輩安心（1–5 分） |
| 敘事／情緒 | 1–5 分 |
| 素材運用 | 最好的照片有沒有被用上、真實感（1–5 分） |
| 技術品質 | 字幕遮擋、音量、畫質、節奏（1–5 分） |
| 真實受眾小測（強烈建議） | 5–10 位 60+ 長輩：「會想報名嗎？」（1–5 分）＋價格回憶正確率 |

**B. 事實與規格（硬指標，零容忍）**
- 事實錯誤數：價格、時間、地點、報名方式、捏造的承諾
- DoD 合格率：9:16、時長在目標 ±2 秒內、字幕安全區、響度約 -14 LUFS、CTA 出現且可讀

**C. 過程成本**
| 指標 | 說明 |
|---|---|
| 到第一版可看成片的時間 | 牆鐘時間 |
| 到可發布版的時間 | 牆鐘時間 |
| 人工介入次數 | 人被問問題、核可、手動修改的次數 |
| 人工實際操作分鐘數 | 包括組片、填表、回答問題 |
| 修改輪數 | 從第一版到可發布版 |
| 停工／回報次數 | 再分成「有價值」（例如真的缺報名電話）和「不必要」兩類 |
| Token／費用 | 總用量 |

**D. 穩定性與可複製性**
| 指標 | 說明 |
|---|---|
| 同組 3 次的品質**最低分**與標準差 | 穩定＝下限高，不是平均高 |
| 換操作者一致性 | 換一個人照同一套方法跑，品質差多少 |
| 可修改性 | 「價格改成 600 元／換一張結尾照片」要花多久、會不會弄壞其他地方 |
| 可追溯性 | 事後能不能說出每個主要決定的理由（決策日誌是否存在且可讀） |

**E. 交接保真度（只適用 B／B′）**
- 企劃端標記的「王牌素材」在成片中是否被用上
- 企劃意圖（情緒曲線、Hook 理由）在成片中保留了多少（評審 1–5 分）
- 交接中遺失或變形的關鍵事實數

**F. 發布後（有發布才算，當作次要指標）**
- 3 秒留存、平均觀看比例、分享、私訊詢問、實際報名數
- 單支影片樣本太小，只用來確認方向，不作為勝負依據

### 7.3 事先寫好的判讀規則（照你們戰果兵的精神）

在跑之前就寫死，避免事後合理化：
- **C 勝過 A**：配對偏好不輸 A（勝率 ≥ 50%），**且**（DoD 合格率較高 **或** 3 次最低分較高），**且**人工時間不超過 A 的 1.5 倍。
- **B 才值得保留**：B 必須在品質**或**穩定性上明顯勝過 A 和 C，足以抵消它多出來的人工時間與往返次數。只是「比較有紀錄」不算。
- **A 就夠了**：A 在品質與穩定性上都不輸 C → 先不加 Skill，只補任務卡＋DoD＋戰果兵。
- 差異落在評審之間的誤差內 → 無法判定，追加一輪（換一批照片）。

### 7.4 每次執行記一列

```
| 組別 | 第幾次 | 操作者 | 模型/環境 | 到第一版(分) | 到可發布(分) | 人工介入次數 | 人工分鐘 | 修改輪數 | 停工(有價值/不必要) | 事實錯誤數 | DoD 合格(x/5) | 盲評平均 | 配對勝率 | 長輩想報名(1-5) | 訊息回憶(x/4) | 備註 |
```
