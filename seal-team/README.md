## D. MVP Runtime

### 1. 資料夾（一個任務一個資料夾，不做系統）

```
seal-team/
├── roles/                 # 三兵職責卡＋可直接貼上的 Prompt（= Skill）
├── contracts/             # 三份交接契約空白模板
├── 武器配置表.md
├── 戰果庫.md              # 戰果兵每次追加一列，企劃兵下次必讀（= 小隊記憶）
└── missions/
    └── M001/
        ├── 00-素材/       # 店家丟素材＋素材清單.md
        ├── 01-作戰令/     # 作戰令.md（企劃兵產出、隊長核可）
        ├── 02-製作/       # 製作紀錄.md、字幕.srt、成片（或成片連結）
        ├── 03-戰果/       # 數據截圖、戰果單.md
        └── 04-復盤/       # 復盤.md（企劃兵讀戰果單後寫）
```

放哪裡都可以：這個 GitHub repo、Google Drive、或店家電腦上的一個資料夾。**MVP 建議 Google Drive**（店家手機可直接上傳素材與截圖），本 repo 當作模板母版。

### 2. 檔案（最少 6 份）

| 檔案 | 誰寫 | 誰讀 |
|---|---|---|
| `00-素材/素材清單.md` | 隊長（或企劃兵代填後隊長確認） | 企劃兵、製片兵 |
| `01-作戰令/作戰令.md` | 企劃兵 | 隊長核可 → 製片兵、戰果兵 |
| `02-製作/製作紀錄.md` | 製片兵 | 隊長核可 → 戰果兵 |
| `03-戰果/戰果單.md` | 戰果兵 | 企劃兵 |
| `04-復盤/復盤.md` | 企劃兵 | 隊長、下一場企劃兵 |
| `戰果庫.md` | 戰果兵追加 | 企劃兵每次開場必讀 |

### 3. Prompt / Skill

每張職責卡最後一段「啟動 Prompt」就是該兵的 Skill。MVP 用法：

- **Claude.ai Project（建議）**：開 3 個 Project（企劃兵／製片兵／戰果兵），把職責卡全文貼進 Project instructions，把對應契約模板與 `戰果庫.md` 上傳成 Project knowledge。
- **沒有 Project 時**：開新對話，第一則訊息貼職責卡，第二則貼上游文件。
- 之後要進 Claude Code / Skill 化，職責卡可直接改成 `SKILL.md`，內容不用重寫。

### 4. 工具（能借不造）

AI：Claude（主）、ChatGPT／Gemini（備）。
剪輯：CapCut／剪映（手機或桌機，含自動字幕、模板）。
發布：Instagram Reels／TikTok／YouTube Shorts 原生 App。
數據：各平台原生洞察（IG 洞察報告、TikTok Studio、YouTube Studio）→ 截圖。
記錄：Google Drive＋Google 試算表（或本 repo 的 Markdown）。

### 5. 人工節點（隊長／店家，不是第四個 AI 兵）

| 節點 | 內容 | 為何目前是人 |
|---|---|---|
| H1 素材提供 | 拍照、拍片、上傳到 `00-素材/` | AI 不在現場 |
| H2 作戰令核可 | 看 CTA、價格、優惠是否真的能做 | 只有店家知道能不能兌現 |
| H3 剪輯組裝 | 在 CapCut 依《剪輯單》組片（見限制） | 目前 AI 無法可靠直接輸出成片 |
| H4 成片核可 | 看成片，打勾或退回 | 對外發布責任在店家 |
| H5 發布 | 用店家帳號發布，回填發布時間與連結 | 帳號授權不交給 AI |
| H6 現場 CTA | 例如「說通關密語打 9 折」要店員真的執行並記次數 | 線下行為 AI 看不到 |
| H7 數據回填 | 48 小時、7 天各截一次洞察畫面上傳 | MVP 不串平台 API |

### 6. 三兵如何傳遞任務（接力規則）

```
隊長 H1 放素材
   └→ 企劃兵：讀 素材清單＋戰果庫 → 寫《作戰令》
        └→ 隊長 H2 核可（改了就在作戰令「核可欄」寫改了什麼）
             └→ 製片兵：讀《作戰令》＋素材 → 產出《剪輯單》《字幕》《發布文案》→ 寫《製作紀錄》
                  └→ 隊長 H3 組片 → H4 核可 → H5 發布 → 回填《製作紀錄》發布欄
                       └→ 隊長 H6/H7 回填數據
                            └→ 戰果兵：讀《作戰令》判讀規則＋《製作紀錄》＋數據 → 寫《戰果單》→ 追加戰果庫
                                 └→ 企劃兵：讀《戰果單》→ 寫《復盤》→ 開下一張《作戰令》
```

傳遞方式 = **把上游檔案整份貼給下游兵**（或上傳到它的 Project）。三份文件共用同一組編號：
`任務編號 M001` → `影片編號 M001-V1` → `測試點編號 M001-T1`。下游只准引用上游編號，不准自己發明欄位意義。

**退回規則**：任何兵發現上游缺資料 → 在自己文件的「回報／退回」欄寫明缺什麼 → 交回隊長，不自行補。

### 7. 已知限制與替代方案（不假裝自動化）

| 限制 | 現況 | 替代 |
|---|---|---|
| AI 直接輸出成片 | Claude 不能直接剪片；一般 AI 影片生成工具難以忠實使用店家實拍素材 | 製片兵產出逐鏡《剪輯單》＋`.srt` 字幕＋封面字，隊長 10–20 分鐘在 CapCut 組片。進階：有 ffmpeg 的電腦由 Claude Code 依剪輯單產粗剪（非 MVP） |
| AI 看影片 | Claude 可看圖片，無法直接看影片檔 | 隊長對每支影片截 1–3 張關鍵畫面＋一句描述；或上傳到支援影片的 Gemini 做素材描述（備援器） |
| 自動發布 | 不交帳號給 AI | 隊長手動發布（H5） |
| 自動抓數據 | 不串 API | 隊長截圖（H7），戰果兵讀截圖轉成數字；看不清的欄位寫「無法讀取」 |
| 因果判定 | 單支影片樣本太小 | 戰果兵只依作戰令預先寫好的判讀規則下結論；觀看數低於門檻一律「無法判定」 |
| 線下轉換 | 看不到店內發生什麼 | 靠 H6 店員計次（通關密語、出示影片、專屬優惠碼） |
