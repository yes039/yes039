## 2. 能力盤點

| 能力 | 判定 | 說明與證據 |
|---|---|---|
| 素材匯入／整理 | **官方已支援** | 官方點名「organize media」[S1]；Scripting API 一直都有 MediaPool 匯入、建 bin、寫 metadata 的功能 [S19] |
| 時間軸剪輯（組裝） | **官方已支援（基本）** | 官方範例：把長片段剪成 3 分鐘精華、刪掉短於 1 秒的片段 [S6] [S9]；有實測文章說 AI 完成了剪接、標題、輸出 [S14]（🟡，沒有可驗證的細節） |
| 時間軸剪輯（修剪／移動） | **尚無證據／已知缺口** | 片段放上時間軸之後，只有 getter，**沒有 trim／slip／slide／roll／自由移動的 setter**；mcp.film 也記錄「目前的實作不支援重新定位片段」[S18] [S15] [S10]。結論：必須第一次放上時間軸就放對位置 |
| 轉場 | **文件宣稱（社群追蹤）** | 社群追蹤表說 21.1 新增了轉場、淡入淡出、變速、多機位的 API [S18]（🟠，沒有官方工具清單佐證） |
| 字幕 | **部分支援** | API 有 `Timeline.CreateSubtitlesFromAudio`，語言參數包含 `mandarin_traditional`，需要 Studio [S21]（🟠）。**字幕樣式（字型、底色、位置）能不能透過 MCP 控制，尚無證據** |
| 調色 | **第三方可支援** | 社群 MCP 宣稱支援節點、CDL、LUT、調色複製 [S19] [S20]；官方 MCP 能做到什麼調色程度，查無公開清單 |
| 音效／配樂 | **放置：文件宣稱；音量／閃避：尚無證據** | 把音訊片段放到軌道上，屬於基本 API。有一份實測（社群 bridge＋免費版 21.0.3，**不是**官方 21.1）透過 MCP 調音樂音量失敗，只好在 Resolve 外處理 [S17]。Resolve **沒有內建可商用配樂庫**（⚪，查無官方說明有） |
| 直式 9:16 | **時間軸／輸出尺寸：文件宣稱；自動重新構圖：尚無證據** | 可以用 `SetSetting(timelineResolutionWidth/Height)` 和 render 設定 `FormatWidth/Height` 設定尺寸（🟠 [S29]）；Smart Reframe 能不能透過 MCP 觸發，查無證據 |
| 批次輸出 | **官方已支援** | 官方點名「batch render」[S1]；官方範例是輸出 H.265 [S6]；渲染佇列 API 也存在 [S19] |
| 素材內容理解 | **第三方可支援** | Resolve 21 有轉錄（附講者與時間碼）[S11]；社群 MCP 有「視覺分析」工具 [S19]。有實測指出，餵外部逐字時間碼的轉錄稿效果比 Resolve 內建轉錄好 [S14] |
| 品質驗收 | **需要額外開發** | 有評論提醒：「success 回應不代表輸出檔裡真的有正確的畫面、音訊、字幕」[S17]；Claude 沒辦法直接看影片 |

## 3. 指定驗證情境：玉欣珍 30 秒 FB／IG 商品廣告

輸入：10 張商品照、5 段影片、商品文案。
**全部步驟都沒有實測。**

| # | 步驟 | 判定 | 依據／缺口 |
|---|---|---|---|
| 1 | 素材整理（匯入、分 bin、標註內容） | 匯入與分 bin：**官方已支援**；內容描述：**第三方可支援** | 照片可以交給 Claude 視覺辨識（現有流程就在用）；影片內容要靠 Resolve 轉錄或社群視覺分析工具，否則維持人工截圖 [S1] [S19] |
| 2 | 腳本 | **不屬於 Resolve 範圍**（現有企劃兵／製片兵已經在做） | 作戰令＋剪輯單由 Claude Project 產出，跟 Resolve 無關 |
| 3 | 剪輯（依剪輯單照順序放片、設入出點、照片設定秒數） | 基本組裝：**官方已支援**；放好之後再調整：**尚無證據**；照片的推拉搖移（Ken Burns 關鍵影格）：**尚無證據**；轉場：**文件宣稱** | 有 trim／move 缺口 [S18]，所以剪輯單必須在送進 Resolve 前就精確到影格。30 秒商品廣告裡照片佔大宗，**靜態照片沒有動態效果會很呆板**，這是本案最大的未知數 |
| 4 | 字幕（文案字卡＋字幕） | 從語音產生：**第三方可支援**（API 存在 [S21]）；匯入我們的 `.srt`＋套用樣式：**尚無證據** | 商品廣告多半沒有口白，字幕來源是我們自己的 SRT 或字卡，不是語音辨識；樣式能不能控制沒有證據 |
| 5 | 配樂 | 放上音軌：**文件宣稱**；音量／閃避／淡出：**尚無證據**（有一則失敗案例 [S17]）；音源：**需要外部授權** | FB／IG **付費廣告**用的配樂必須是可商用授權曲；能不能用平台內建音樂庫要另外查證（⚪） |
| 6 | 9:16 輸出 | 時間軸／輸出尺寸＋渲染：**官方已支援（渲染）／文件宣稱（尺寸）**；橫式素材自動重新構圖：**尚無證據** | 有教學提醒自動重新構圖可能漏掉主體或安全區 [S12] |
| 7 | 品質驗收 | **需要額外開發** | 需要用 ffprobe 檢查規格、確認響度（-14 LUFS）、抽幀給 Claude 看、對照剪輯單的秒數 → M002 已經有類似的 ffmpeg 做法可以沿用；最後仍是 H4 人工核可 |

**小結（⚪）**：Resolve MCP 能做的是「流水線中段的組裝與輸出」。本案最關鍵的三件事——照片動態、字幕樣式、配樂音量——**目前都沒有證據**。

## 4. 工作流整合分析（對照現行 seal-team）

現行流程裡唯一的痛點是 **H3 組片**：隊長依剪輯單在 CapCut 手動組片，README 估 10–20 分鐘，M001 估 20–30 分鐘。Resolve MCP 的目標就是取代 H3。

| 現有環節 | 可直接銜接 | 需額外開發 |
|---|---|---|
| `00-素材/` 資料夾 | 可以直接當成匯入來源 | 素材要從 Google Drive 同步到裝 Resolve 的本機 |
| 《剪輯單》（Markdown 表格） | 內容可以直接當 prompt | 要改成**結構化 JSON**（素材編號→檔案路徑、秒→影格、軌道、轉場），降低 AI 誤讀；trim 缺口也逼著入出點一次就要精準 |
| `字幕.srt` | 檔案格式通用 | SRT 匯入時間軸、樣式套用都要實測；不行就改用 Fusion Text+ 字卡（社群工具宣稱可行 [S19]） |
| 品牌規範（字體／顏色） | — | 要建一個 **Resolve 範本專案**（9:16 時間軸 preset、字幕樣式、片頭片尾、render preset），讓 AI 只填素材、不做設計 |
| 成片檢查 | — | QC 腳本（ffprobe、響度、抽幀）＋自動回填《製作紀錄》 |
| 製片兵職責卡 | — | 啟動 Prompt 第 6 條「你無法直接剪片」需要改版（**要等核准才能動**） |
| 執行環境 | — | 雲端 Claude Code → **改成本機 Claude Code**；要設定權限白名單（只能讀寫專案資料夾） |

### 建議的整合架構（如果將來導入）

```
企劃兵（Claude Project）→ 作戰令 ─H2核可→ 製片兵 → 剪輯單.json＋字幕.srt＋文案
                                                     │
              ┌──────────────── 本機（Windows／Mac，Resolve Studio 21.1）────────────────┐
              │  Claude Code ──MCP──▶ Resolve：匯入素材 → 套用範本專案 → 依 JSON 組時間軸  │
              │                         → 字幕／配樂 → 9:16 render（H.264／H.265）          │
              │  QC 腳本：ffprobe 規格／響度／抽幀 → Claude 對照剪輯單 → 寫製作紀錄草稿     │
              └──────────────────────────────────────────────────────────────────────┘
                                                     │
                     H4 人工核可（可以直接開 Resolve 專案微調，這是 Resolve 相對 ffmpeg 的最大優勢）
```

### 競爭基準：現有的 ffmpeg 路線

M002 已經證明：**雲端 Claude Code＋ffmpeg 可以全自動產出 1080×1920、-14 LUFS 的 30 秒成片**，不需要任何授權費，也不需要本機硬體。所以 Resolve 必須贏過 ffmpeg 路線，而不只是贏過 CapCut 手工。

| 比較 | Resolve MCP | ffmpeg（M002 路線） |
|---|---|---|
| 授權／硬體 | US$295＋符合規格的本機 | 0（雲端容器） |
| 人工微調 | 可以直接開時間軸改（**優勢**） | 要改腳本重跑（劣勢） |
| 照片動態、音量閃避 | 尚無證據 | 已在 M002 實作（zoompan、閃避混音） |
| 調色／Smart Reframe／AI 轉錄 | 有（Studio 功能），MCP 能不能控制要實測 | 沒有，或只能粗略做 |
| 穩定性 | 21.1 是新功能，評論普遍說「真的有用但還早」[S13] | 確定性高，可以重跑 |

| R8 | 供應商政策變動 | 中 | 21.1 已經把免費版的 Python 收回 Studio 限定 [S22]；社群的免費版 bridge 作者自己都說「可能被官方封掉」[S19] |
| R9 | Codex 路由問題 | 低 | 有使用者回報選 Codex 卻開成 Claude [S16] |
| R10 | 人工介入 | — | 目前看來 H4 成片核可、H5 發布、配樂選曲、品牌樣式都還是需要人；就算 MCP 順利，也只能把 H3 從「手工組片」變成「審片微調」 |

## 7. 商業適用性

| 對象 | 評估 | 理由 |
|---|---|---|
| 小店老闆自己用 | **不適合** | 要付 US$295、要有合格電腦、要裝 Claude Code 並接 MCP、要看懂 Resolve 介面才能審片微調；比 CapCut 手機 app 的門檻高很多（⚪） |
| 我們代製影片 | **有潛力，但尚未證實能提升效率** | 優點：成片可以直接在專業剪輯軟體裡微調，可以批次輸出多種尺寸，有 Studio 的調色與 AI 工具。缺點：照片動態、字幕樣式、配樂音量這三個本案關鍵都沒有證據；而且 ffmpeg 路線已經能零成本全自動出片 |

## 8. 最小實測方案（等核准後才執行；本報告沒有執行任何一項）

**前提（全部要 Shen 核准）**：① 購買 Resolve Studio 授權（US$295，付費操作）② 指定一台符合第 5 節規格的本機 ③ 店家同意把素材用於測試。

## 9. 最終判定

### **B｜收藏觀察，暫不導入**

**理由：**
1. **依據我們自己的軍規**（`武器配置表.md` 共通換器規則第 4 條「不為新工具而換：新工具只有在現有器觸發換器條件時才試用」）：製片兵的換器條件是「隊長組片單支 > 30 分鐘連續 2 次」，但 M001 還沒實戰、`戰果庫.md` 還是空的，**換器條件沒有觸發**。
2. **本案的三個關鍵能力（照片動態、字幕樣式、配樂音量）都沒有證據**，而且官方工具清單沒有公開，無法在紙上判斷能不能做到。
3. **已經有零授權成本的替代路線**（M002 的 Claude Code＋ffmpeg 全自動出片），Resolve 的邊際價值還沒證明。
4. **導入門檻是實體的**：要付費（US$295）、要本機硬體，而且雲端 Claude Code 接不上。
5. 正面看：官方原生支援、一次買斷、Claude Code／Codex 都在官方點名名單裡，成本不高、方向正確——**值得收藏，不值得現在就花錢**。

**升級為 A（進入隔離實測）的觸發條件——符合任一項，並經 Shen 核准預算後，直接執行第 8 節方案：**
- 製片兵換器條件觸發（H3 組片 > 30 分鐘連續 2 次），或 ffmpeg 路線在某類素材上品質不夠；
- 團隊已經有一台符合規格的 Mac 或 Windows（硬體成本 = 0），而 Shen 願意先投入 US$295；
- Blackmagic 公開官方工具清單，或出現獨立實測證實能控制字幕樣式、音量、關鍵影格；
- 有客戶明確要求交付可編輯的 Resolve 專案檔。

**建議觀察頻率**：每月查一次 Resolve 21.x 的 release notes，以及社群追蹤表 [S18]。
