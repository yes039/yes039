## 一、武器原理（流程、模組、用法）

### 1. 製作流程（`app/services/task.py` `_run_pipeline`）

| 階段 | 做什麼 | 程式位置 | 能否跳過 |
|---|---|---|---|
| ① script | LLM 依主題寫旁白稿 | `task.py:352`、`llm.py` | **可以**：傳 `--video-script` 就不呼叫 LLM（`task.py:354-363`） |
| ② terms | LLM 從稿子抽 5–8 個英文搜尋關鍵字 | `task.py:373` | 可傳 `--video-terms`；用本地素材時整段跳過（`task.py:1677`） |
| ③ audio | TTS 產生旁白 mp3 | `voice.py` `tts()` | 可傳 `--custom-audio-file` 改用自備錄音 |
| ④ subtitle | 依 TTS 時間戳（edge 模式）或 faster-whisper 轉寫產生 SRT | `subtitle.py`、`task.py:643` | `--subtitle-enabled false` |
| ⑤ materials | 下載圖庫影片，或把本地圖片/影片做前處理 | `task.py:717`、`material.py` | — |
| ⑥ video | MoviePy 切片＋轉場 → ffmpeg 串接 → 疊字幕、旁白、配樂 → MP4 | `video.py:958 combine_videos`、`video.py:1538 generate_video` | — |
| ⑦ 跨平台發布（選配） | 透過第三方 Upload-Post 自動上傳 TikTok／IG／YT Shorts | `upload_post.py`、README:204 | 不設 key 就不會動 |

**成片長度＝旁白長度。** 畫面不夠長就把片段循環補齊（`video.py:1228-1243`），最後依音訊長度裁切（`video.py:1262`）。沒有「指定 30 秒」的參數，只能靠稿子字數控制。

### 2. 核心模組

- `llm.py`：接三十幾家 LLM（OpenAI、Gemini、DeepSeek、Moonshot、Ollama…），**也有 `claude_code` provider**，透過本機已登入的 `claude` CLI 用訂閱額度（`llm.py:52-62`、`Dockerfile.claude`）。
- `material.py`：Pexels／Pixabay／Coverr 圖庫搜尋下載；另外接了好幾家**付費**的 AI 影片生成（Seedance、OFox、MiniMax H3、MuAPI、WaveSpeed、LoomLoom）與 OpenAI 文生圖。
- `voice.py`：Edge TTS（預設、免 key）、Azure TTS V2、SiliconFlow、Gemini、MiniMax、ElevenLabs、Fish Audio、VoxCPM（可複刻聲音），以及自架的 Kokoro／Chatterbox。
- `video.py`：MoviePy＋ffmpeg 合成；支援 16:9／9:16／1:1，輸出 1080×1920（`schema.py:39-46`）。
- `bgm.py`、`sonilo.py`、`elevenlabs_music.py`：本地配樂或 AI 生成配樂（付費）。

### 3. 使用方式（四種入口）

1. WebUI（Streamlit，`webui/Main.py`）
2. REST API（FastAPI，`app/controllers/v1/video.py`）
3. **CLI**（`cli.py`，48 個參數，最適合讓 C 呼叫）
4. 官方 Agent Skill（`docs/skill/SKILL.md`＋`mpt_agent.py`，見第二節）

## 二、Skill 可用性：C 能不能直接呼叫？

### Skill 實際在做什麼

`mpt_agent.py` 是一支自動安裝並執行的腳本：

1. 從 GitHub 下載 **`main` 分支的 zip**（沒鎖版本）到 `~/MoneyPrinterTurbo`（`mpt_agent.py:23-27`、`ensure_project()`）
2. 用 `uv` 建立 Python 3.11 環境並裝依賴；缺 uv 時 SKILL.md 要求 agent 自己用 `curl | sh` 安裝
3. 讀寫 `config.toml`，缺 key 就以 exit code 10 回報要使用者給
4. 呼叫 `cli.py` 產片，回傳 `VIDEO_FILE=…/final-1.mp4`

### 判定

| 問題 | 答案 |
|---|---|
| C 能直接呼叫嗎？ | **有終端機的 C（Claude Code／雲端容器）可以；只在 claude.ai 聊天、沒有終端機的 C 不行。** |
| 要不要另外裝環境？ | **要。** Python 3.11＋uv＋約 1 GB 依賴（MoviePy、faster-whisper 等）＋ffmpeg。這違反本令「不安裝」，所以本階段沒裝。 |
| 平台限制 | SKILL.md 寫明**只支援 macOS 和 Windows**（`SKILL.md:154`）。我們 C 跑的雲端容器是 Linux，Skill 不在官方支援範圍；但 MPT 主程式本身支援 Linux（README:246），改走 CLI 即可。 |
| **跟軍紀衝突的地方** | SKILL.md 第 2 條：「**不要在安裝、生成、使用預設值前徵求確認**」（`SKILL.md:18`）。這跟「未經 Shen 核准不得安裝、部署、串接 API」正面衝突。 |
| 付費防呆 | 有。Seedance／OFox／MiniMax／MuAPI／WaveSpeed 都要求使用者明確同意才加 `--confirm-*-charge`，不會靜默扣款。這點設計得好。 |

**建議用法（如果之後進實測）：不載入官方 Skill，由 C 直接呼叫 `cli.py`**，鎖定 commit、自己寫稿、只開免費元件。Skill 的流程控制交還給 C（呼應「C 是大腦，武器是工具」）。

## 四、主題成片（只給主題）

✅ **這是 MPT 的主場**，官方 Skill 的預設就是這條路（`SKILL.md:27`）：

1. LLM 依主題寫稿（可指定段落數、補充提示詞、自訂 system prompt）
2. LLM 產生英文關鍵字 → 到 Pexels 搜尋直式影片片段
3. Edge TTS 配音 → 依時間戳產生字幕
4. 隨機配樂 → 合成 1080×1920 MP4

**限制：**

- 畫面是**圖庫通用素材**（多半是歐美人物、辦公室、手機特寫），不會出現台灣小店，也不會有「老闆」本人。
- 關鍵字搜尋是語意配對，畫面跟旁白常常對不太上；可開 `--match-materials-to-script` 改善順序，但無法保證。
- 要真正「AI 生成畫面」得接付費影片模型（例：README 列的 MiniMax H3 每秒 0.09 元人民幣起）。

## 六、與 UZI-01 比較

> ⚠️ 本 repo 裡找不到 UZI-01 的規格文件。以下以本 repo 已有的實戰紀錄（M002：C 在雲端容器用 ffmpeg／Playwright／離線 TTS／程式配樂自己組片，零外部 API）作為 UZI-01 的能力基準。若 UZI-01 實際做法不同，請 Shen 補件，本節再修正。
>
> **更正（2026-10-12）**：上面這段只查了當時所在的分支。後來在其他分支找到 UZI-01 的真實紀錄（宜大鐵板燒 21 秒、宜大 A 版、羅東城隍廟），整理在 [UZI-01 規格](../武器規格/UZI-01-照片成片工作流規格.md)。依證據，下表有兩處要修正：
> 1. UZI-01 **沒有旁白**（三支實戰片都沒有）。離線 TTS 是 M002 的做法，不是 UZI-01。所以「中文配音」一列，MPT 的對手是「無」，不是「離線 TTS」。
> 2. UZI-01 的響度**不一致**（-13.9／-15.8／-22.5 LUFS），不是固定 -14 LUFS。所以「畫質」一列的響度優勢不成立。
>
> 其餘比較（照片成片可控性、授權乾淨度由 UZI-01 勝出，主題成片由 MPT 勝出）不受影響，最終判定維持 B。

| 面向 | UZI-01（C＋ffmpeg 自組） | MPT | 誰勝 |
|---|---|---|---|
| 照片成片 | 每張停留秒數、鏡頭運動、字卡、價格牌、CTA 都能逐格控制 | 統一秒數、單一放大效果、只有字幕 | **UZI-01** |
| 主題成片 | 沒有圖庫；畫面要自己繪製或靠店家素材 | 自動找圖庫影片＋配音＋字幕 | **MPT** |
| 成本 | 0 元 API | 可做到 0 元（C 寫稿＋Edge TTS＋Pexels 免費 key） | 平手 |
| 速度 | 每支片 C 要寫或調整合成腳本 | 參數化一行指令；30 秒片預估數分鐘（**未實測**） | MPT 略勝（主題片） |
| 畫質 | 1080×1920、自訂 CRF、-14 LUFS 響度標準化 | 1080×1920；響度未做平台標準化；圖庫畫質不一 | UZI-01 略勝 |
| 可控性 | 完全可控 | 中：參數多，但沒有逐鏡頭控制 | **UZI-01** |
| 中文配音 | 離線 TTS（音色偏年輕，M002 已記錄） | Edge TTS 台灣腔 3 種，自然度較好 | **MPT** |
| 字幕對時 | 自己算 | TTS 時間戳自動對時 | **MPT** |
| 整合難度 | 已在用 | 要裝 Python 3.11＋uv＋依賴；Skill 不支援 Linux；要調整 Skill 規則 | UZI-01 |
| 授權乾淨度 | 全自製，乾淨 | 內建配樂、字型要先換掉 | **UZI-01** |

## 七、驗兵場景可行性（只評估，未生成）

### 場景 A：宜大鐵板燒，10 張照片 → 30 秒 9:16 宣傳片

**可行，但不如 UZI-01。**

- 做法：C 寫約 120 字的台灣口語旁白，10 張照片依序放進 `storage/local_videos/`，用以下指令（示意，**未執行**）：
  `--video-source local --video-materials <10 個檔名> --video-concat-mode sequential --video-clip-duration 3 --video-aspect 9:16 --video-script "<C 寫的稿>" --voice-name zh-TW-HsiaoChenNeural-Female --bgm-file <自備音樂> --font-name <Noto Sans TC>`
- 成本：0 元 API（不需 LLM、不需 Pexels）。
- 卡點：
  1. 旁白不是剛好 30 秒，照片會被循環或截掉，要反覆調稿子字數。
  2. 不能讓招牌菜停久一點。
  3. 店名、價格、地址、CTA 只能寫在字幕裡，沒有字卡。
  4. 本 repo 根目錄現有照片是 1108×1477（3:4），放進 9:16 會被裁掉左右兩側；`contain` 模式則會留黑邊。
- 判斷：**UZI-01 能做得更好，MPT 不需要上場。**

### 場景 B：「小店老闆如何用 AI 做短影音」→ 30 秒 9:16 解說片

**可行，這是 MPT 的強項，也是 UZI-01 的缺口。**

- 做法：C 寫稿（不花 LLM 費用），給英文關鍵字（例：`small business owner, smartphone video, cafe, editing app`），Pexels 找畫面，Edge TTS 台灣腔配音。
- 需要：Pexels 免費 API key（**需 Shen 核准才申請**）。
- 預期品質：畫面是通用圖庫，「台灣小店」感不足，可能出現外國面孔；適合解說型、知識型內容，不適合品牌片。
- 判斷：**值得做一次小規模實測**，看圖庫畫面能不能過店家那關。

## 八、可直接用 vs 需要改造

### 可直接用（零件清單）

1. **`cli.py` 參數化出片**：主題成片可直接一行呼叫。
2. **Edge TTS＋時間戳字幕**（`voice.py`、`subtitle.py`）：台灣腔配音＋自動對時字幕，可補 UZI-01 的配音短板。
3. **Pexels 素材搜尋下載**（`material.py`）：圖庫找片的邏輯，可補 UZI-01「沒有圖庫」的缺口。
4. **付費防呆模式**：`--confirm-*-charge` 的設計值得在我們自己的流程裡借用。

### 需要改造／替換

1. 內建配樂 → 全部替換成有授權的音樂。
2. 內建字型 → 換成 Noto Sans TC／思源黑體。
3. 官方 Skill → 不直接用；由 C 呼叫 CLI、鎖 commit、移除「不經確認就安裝」規則。
4. 照片成片的逐張時長、字卡 → MPT 做不到，留在 UZI-01。
5. 成片響度 → 若要對齊 UZI-01 的 -14 LUFS，需要後處理一次 `ffmpeg loudnorm`。
