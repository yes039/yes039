## 建議：企劃兵，並把小爆排進同一場測試的對照組

用同一個任務跑三組（標準第 3 節）：

| 組別 | 做法 |
|---|---|
| 組 1｜C 直做 | 不載入任何員工，直接寫一張短影音作戰令 |
| 組 2｜C＋企劃兵 | 照企劃兵原始職責卡寫作戰令 |
| 組 3｜C＋小爆→企劃兵 | 先由小爆拆一支同業爆款，再交給企劃兵寫作戰令 |

一場測試可以回答三個問題：
1. **企劃兵**是否比 C 直做更好？（我們自有的核心商品）
2. **小爆**放在企劃兵前面當情報來源，是否加值？
3. 兩位重疊的員工，該留哪一種分工？

## 為什麼是企劃兵

| 理由 | 說明 |
|---|---|
| 授權乾淨 | 我們自有，否決項 6.1 一開始就能通過；驗證成功就能直接放進商品 |
| 是商品核心 | 四週建軍的第 1 週就是作戰令；它沒有價值，整個海豹流程就沒有價值 |
| 最大的空白 | M001 從來沒跑過；目前海豹三兵完全沒有實證 |
| 成本最低 | 純文字產出，**API 成本 0**，不需要安裝工具 |
| 有現成素材 | M002 的「60+ 學 AI」題目、或任一家店的素材清單都可以直接用 |

## 為什麼把小爆排進對照組

- 小爆和企劃兵重疊，而且規則衝突（仿寫可能用到素材清單沒有的畫面），**正是 C 基準對照最需要回答的情況**。
- 小爆是純提示詞，不用帳號、不用 API；只在內部測試，不涉及對外交付。
- 測完就能決定：小爆要變成企劃兵的情報方法（自建重寫），還是收藏觀察。

## 為什麼不是其他員工

| 員工 | 不排在下一位的原因 |
|---|---|
| 小廣 | 綁定原作者帳號、14 個空格、缺腳本；實測要**真的花廣告預算**，風險和成本最高。建議等企劃兵與戰果兵驗完，再用自建方式評估 |
| 小網 | 子技能缺件；和短影音核心流程關係較遠 |
| 製片兵 | 要先有企劃兵產出的作戰令才能測；排在企劃兵之後 |
| 戰果兵 | 需要真實發布後的數據，最後測 |
| 小定、小察、小挖 | 純提示詞，價值可能被 C 直做取代；可以在企劃兵測試後，用同樣方法快速驗證 |
