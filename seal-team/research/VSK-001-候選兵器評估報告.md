## 0. 一頁結論

- **最終判定：A 值得試煉，但只限 3 個模組**（`ffmpeg-auto-assemble`、`subtitles-and-text-effects`、`storyboard.json` 結構化分鏡），而且是在隔離環境中當**預備器**試煉，**不換掉 CapCut 主器**。其餘 10 個 Skill 為 B 收藏觀察或 C 不採用（見第 7 節）。
- **它真正的價值**：約 1,215 行 Python＋ffmpeg 的**本地成片管線**【碼】，正好對準我們目前最大的人工瓶頸 H3「隊長在 CapCut 依剪輯單組片」。我們的 M002 已證明本機能做出 -14 LUFS、燒字幕的成片，但那是**單支客製動畫**（`scenes.js` 389 行），沒辦法拿來處理店家實拍素材。這個 repo 補上的是**可重複使用、由資料驅動的組片器**。
- **不能直接用的地方**（全部有原始碼證據）：
  1. 實拍影片鏡頭的**原聲一律被丟棄**（`-an`），老闆講話、現場聲都會消失。
  2. 文件說可以換成真人配音，**程式其實做不到**（會被 TTS 覆蓋）。
  3. 字型寫死**簡體**，繁中字形會跑掉。
  4. **沒有** FB／IG Reels／YouTube Shorts 的匯出預設。
  5. 配音依賴 edge-tts，它呼叫的是**非官方**的微軟線上服務，商用授權不明。
  6. **沒有任何測試**，專案只有 2 天開發歷史。
- **四級能力差距**：「程式可執行」與「影片可產出」有原始碼加示範檔支撐，但我們尚未自行重現。「品質可交付」尚待驗證，示範片已出現花字壓到商品的情況。「老闆可獨立操作」**一律否**，因為只有命令列、要寫 JSON，沒有任何圖形介面。
- **依我們自己的換器規則**（武器配置表〈共通換器規則〉第 4 條「不為新工具而換」），ffmpeg 粗剪的觸發條件是「組片 > 30 分鐘連續 2 次」。M001 還沒實戰、戰果庫是空的，**觸發條件尚未成立**。所以本報告建議「試煉、收進預備器」，不建議「換器」。

## 3. 關鍵原始碼發現（禁止只看 README 的理由）

### 3.1 實拍影片鏡頭的原聲全部被丟棄【碼】
`assemble.py` `render_shot()` 編碼參數固定為 `-an`，最終音軌只有 TTS 加 BGM。台灣小店最常見的素材正是**老闆或店員對鏡頭講話、現場煎炸聲**，這些全部會消失。要改為「可選保留原聲、與 BGM 閃避混音」，需要修改程式。

### 3.2 「換真人配音」的文件宣稱與程式碼矛盾【碼】
`ai-voiceover-edge-tts/SKILL.md` 寫「把录音放进 `build/tts/lXX.wav`，流水线照样可用」，但實際行為是：
- `--tts edge` 模式：`synth_line()` 只在 `.key` 檔 hash 吻合時才沿用既有 wav，否則**重新合成並覆蓋**真人錄音。
- `--tts none` 模式：組裝音軌時的條件是 `a.tts == "edge"`，**所以完全不放任何人聲**。

結論：要用真人錄音，必須改程式。我們的 M002 復盤也已建議「旁白換真人」，這點直接相關。

### 3.3 繁體中文字型被寫死為簡體【碼】
- `make_subs.py` `detect_font()` 的候選清單只有 SC 系列（Noto Sans CJK SC、思源黑體 SC、PingFang SC 等），沒有任何 TC。用 `--font "Noto Sans CJK TC"` 可以覆蓋 ✅。
- `make_cards.py` 與 `cover_ab.py` 讀 `.ttc` 時寫死 `index=2`（Noto CJK 集合中 2＝SC）。**即使用 `--font` 指定 TC 的 .ttc 也無效**，「說、為、骨、這」等字會以簡體字形呈現。
- 我們的 M002 用的是 `Noto Sans CJK TC`【碼：lib.js】，兩邊必須統一。

### 3.4 品質面觀察（示範成品檔）【測：抽 1.0／4.0／7.5／15.5s 影格目視】
- 字幕高亮、描邊、CTA 按鈕清楚，屬於可用的「電商快剪」水準。
- 7.5s「24h 保冰」花字**壓在杯蓋上**，也跟資訊圖原本的文字打架，違反它自己的檢查清單「不压商品」。原因是花字位置固定在頂部 13%，不判斷畫面內容。
- 整支片都是 Ken Burns 靜態圖加模糊填底，觀感偏「投影片式」。BGM 是固定 I–vi–IV–V 和弦、112 BPM 的簡單合成【碼】，只到示範等級。
- 響度 -14.7 LUFS、LRA 2.3 LU，符合短影音常見標準。

### 3.5 其他
- 字幕分段計時依「字數比例」分配，沒有使用 edge-tts 的逐字時間戳。同一句內的分段只會大致對上口白【碼】。
- `live_clip.py` 的 drawtext 只跳脫 `'` 與 `:`，標題含 `%` 或 `\` 時可能出錯（小瑕疵）【碼】。
- CTA 與文案預設是中國平台用語（「点击下方小黄车」「点下方链接」）。合規字詞表依據中國《广告法》【碼／文】。台灣適用的是公平交易法、消費者保護法，以及食品、化粧品、藥事、健康食品等相關法規的療效與誇大宣稱規範，**不能直接套用**【待：法務】。

### 3.6 與我們邊界的衝突
製片兵職責卡 Boundary 明定：「✗ 不得用 AI 生成畫面冒充店家實拍」。所以 `image-to-video-shots` 和 `multi-model-shot-prompts` 的主要用途（把商品圖丟給圖生影片模型）在我們的體系內**原則上不採用**。只保留其中的「本地 Ken Burns 讓店家實拍照片動起來」，這部分其實就是 assemble 的功能。

## 5. 最值得研究的三項能力及理由

### ① 結構化分鏡 `storyboard.json`（優先度最高，是串接的關鍵）
- **理由**：這是把「人看的剪輯單」變成「機器可以算的剪輯單」的唯一接口。製片兵本來就要產出逐鏡剪輯單（素材編號、入出點、字幕、畫面字），只要讓它**同時輸出符合 schema 的 JSON**，就能直接餵給組片器，H3 從「手動組片」縮短為「跑一行指令加檢查」。
- **證據**：schema 欄位（image／video＋start、line、sub、title、cta、motion、fit、transition、min／duration／pad）與 `assemble.py` 的讀取邏輯逐一吻合【碼】。
- **需補**：作戰令、剪輯單欄位與 JSON 欄位的對照表；`video` 鏡要能指定出點（目前只有 `start`，長度由配音決定）【碼】；要保留素材編號 `A##`、鏡號 `S#`，才能回寫製作紀錄和偏差紀錄。

### ② FFmpeg 自動成片 `assemble.py`
- **理由**：直接攻擊 H3（M001 預估 20 至 30 分鐘一支），而且已內建響度、閃避、轉場時間軸等我們在 M002 手寫過的東西。
- **證據**：時間軸與 xfade 位移公式經核對正確；兩遍 loudnorm 的實作正確；示範檔響度 -14.7 LUFS【碼＋測：成品檔】。
- **必改（否則不適用台灣小店）**：
  - 3.1 保留實拍原聲
  - 3.2 支援真人錄音
  - TTS 改為可插拔：離線、edge、官方付費、真人錄音
  - 繁中字型
  - 素材以實拍影片為主的處理路徑（目前完全沒有範例）

### ③ 字幕與花字 `make_subs.py`
- **理由**：字幕是台灣短影音的必需品（多數人靜音滑），而 ASS 四種樣式加關鍵字高亮正好補上「CapCut 範本要隊長手動套」這一步。字幕產生邏輯只有 139 行，獨立、容易改。
- **必改**：TC 字型；台灣用語標點；IG／FB／YT Shorts 真機安全區重新量測；花字避開商品（至少能逐鏡指定位置）；可選擇用 TTS 逐字時間戳讓分段對得更準。

> 次要、可順便處理：`platform-spec-export` 加入 FB、IG Reels、YouTube Shorts 三個預設（屬於加資料，成本低）；`cover_ab.py` 修正 TC 字型 index 後可給戰果兵做封面 A/B。

## 6. 風險與限制

### 6.1 技術風險
| 風險 | 等級 | 說明 |
|---|---|---|
| 專案成熟度 | 高 | 26 小時開發、無測試、無 release，作者可能隨時大改或停更。**整合方式應為「釘選 commit 後拷貝並自行維護」，不依賴上游** |
| 供應鏈 | 中 | 安裝指令 `npx skills add` 或 `/plugin marketplace add` 會拉取**未釘版**的最新 HEAD，且有同名專案。我方若採用，一律以 commit `96c49b3` 拷貝並自行審閱，**不使用一鍵安裝** |
| 實拍路徑未驗證 | 高 | 所有範例都是 AI 靜態圖；`video` 鏡沒有任何範例，也沒有原聲 |
| 環境依賴 | 中 | 需要 ffmpeg（含 libass、libx264）、CJK 字型、Python 3.9 以上；Windows 路徑跳脫只做了部分處理 |
| edge-tts 中斷 | 中 | 非官方端點，微軟一改就可能失效，也沒有 SLA |

### 6.2 商業交付風險
| 風險 | 等級 | 說明 |
|---|---|---|
| **TTS 商用授權** | 高 | edge-tts 服務條款不明。另外附帶發現：**我們 M002 使用的 zhtts（標貝女聲）模型與資料集的商用授權也尚待查證**【待】 |
| 法規錯置 | 高 | 合規清單依中國法規。台灣食品、化粧品、保健品的療效與誇大宣稱，需依台灣法規另立檢查表【待：法務】 |
| 用語錯置 | 中 | 簡體字、中國平台 CTA（小黃車、视频号），台灣觀眾會立即感到「不是本地店」 |

| AI 配音標示 | 中 | 各平台對 AI 生成內容的標示規則【待】 |

### 6.3 人工介入（即使整合後仍然保留）
H1 素材、H2 作戰令核可、**H4 成片核可**、H5 發布、H6 現場 CTA、H7 數據回填，全部不變。組片器只把 H3 從「手工組片」變成「執行指令加抽影格檢查」。執行指令的人仍是隊長或 Claude Code 操作者，**不是老闆**。

### 6.4 成本
- 軟體：0 元（MIT 加開源依賴）。edge-tts 不收費但有授權風險；改用官方付費 TTS 時另有費用（價格未查，不在此估）。
- 運算：本機 CPU。示範片的渲染時間文件宣稱約 30 秒【文】／【待】。
- **主要成本在改造工程**，以下為粗估，尚未驗證：
  - TC 字型修正：小（0.5 天內）
  - 原聲保留與真人配音：中（1 至 2 天）
  - FB、IG、YT 預設：小
  - 作戰令／剪輯單→JSON 對照與製片兵 Prompt 升版：中（1 至 2 天）
  - 隔離試煉與比較：約 2 至 3 天

## 8. 後續隔離測試建議（**僅為提案，等待核准後才執行**）

**環境**
- 一次性容器或 VM，用完銷毀。
- 不放客戶資料、不放 API Key、不連正式帳號。
- 網路只開 PyPI；TTS 測項額外開 edge-tts 端點，其餘關閉。
- 依賴裝在 venv，並釘選版本（pillow、numpy、edge-tts）；使用系統 ffmpeg。
- **不安裝到 `~/.claude/skills`**，只拷貝 `scripts/`（commit `96c49b3`）。

**素材**：只用自行拍攝的測試素材（非客戶、非本 repo 根目錄來源不明的上傳檔）。準備 10 張照片、5 段 5 至 15 秒的手機直拍影片（含人聲口播一段）。

| 測項 | 內容 | 通過標準 | 驗證能力層級 |
|---|---|---|---|
| T0 重現 | 以示範 storyboard 渲染，比對 repo 內示範檔 | 長度差 ≤ 0.2s；響度 -14±1 LUFS；畫面一致 | ① 程式可執行 |
| T1 繁中、台灣口音 | 繁中字幕加 `--font "Noto Sans CJK TC"`；zh-TW 各聲線朗讀台灣讀音測試句（如：垃圾、星期、企業、危險、品質、頭髮、液體，以及店名、價格、地址） | 無簡體字形；讀音錯誤率記錄；隊長盲聽評分 | ③ 品質 |
| T2 實拍路徑 | 以 `video` 鏡組一支 20 秒店家風格片 | 確認原聲被丟（預期失敗，驗證 3.1）；畫面裁切、轉場無黑幀 | ② 影片可產出 |
| T3 字型 index 驗證 | cover_ab、make_cards 指定 TC .ttc | 預期出現 SC 字形（驗證 3.3） | ③ |
| T4 平台安全區 | 輸出 1080×1920，疊加 IG Reels、FB Reels、YT Shorts 介面截圖比對（不上傳正式帳號；如需真機上傳，另申請測試帳號） | 字幕、CTA 不被遮 | ③ |
| T5 對照實戰 | 同一張已核可作戰令：A 組隊長用 CapCut、B 組用 JSON 加 assemble | 記錄耗時、偏差數、隊長盲評。B 組耗時 ≤ A 組 50% 且盲評不劣於 A，才算通過 | ③／④ |
| T6 老闆操作 | 讓非技術人員只看一頁說明能否完成 | 預期 ✗；記錄卡在哪裡，作為是否需要包裝成介面的依據 | ④ |

**產出**：測試紀錄、改造清單（含 3.1、3.2、3.3 的 patch 範圍）、是否提請換器的建議。測試結束後銷毀環境。
