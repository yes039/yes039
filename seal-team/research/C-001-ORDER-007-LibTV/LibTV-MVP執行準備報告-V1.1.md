## 1. 執行環境限制（第五項：不得以無法連線推論平台不支援）

### 1.1 實際觀察到的限制

| 目標 | 結果 | 證據 |
|---|---|---|
| `mcp.liblib.tv`（MCP 端點與 OAuth metadata） | 連線被拒 | 環境 Proxy 狀態紀錄：`connect_rejected … gateway answered 403 to CONNECT (policy denial)`，host `mcp.liblib.tv:443` |
| `www.liblib.tv`、`im.liblib.tv`（OpenAPI）、`libtv-res.liblib.art`（素材 CDN）、`www.liblib.art` | 連線失敗 | `curl` 回 `000` |
| 網頁讀取工具讀 `www.liblib.tv` | 失敗 | `getaddrinfo ENOTFOUND` |
| `github.com`（官方 Skill、Marketplace 倉庫） | 正常 | V1.0 已完整 clone |

這是**本研究環境的出站網路政策**，由環境設定決定，跟 LibTV 平台的功能無關。
因此本報告所有「尚待實測」都只代表「我方還沒親自看到」，**不代表 LibTV 不支援**。

### 1.2 本環境能做與不能做

| 能做 | 不能做 |
|---|---|
| 讀官方 GitHub 原始碼與文件 | 連到 LibTV 任何服務 |
| 製作測試素材（音訊、分鏡、驗收表、腳本） | OAuth 登入（容器內也沒有可互動的瀏覽器授權流程） |
| 寫好探測與驗證腳本，交給授權環境執行 | 讀 LibTV 官網價目、條款原文 |

## 2. 六項補證：現況與差異

判定只用四種：**已證實／有條件可行／尚待實測／不支援**。
證據等級沿用 V1.0：E1 我方實測、E2 官方原始碼、E3 官方文件、E4 第三方。

### 2.1 總表（第六項：已證實 vs 尚待實測）

| # | 補證項目 | V1.0 判定 | **V1.1 判定** | 目前最強證據 | 尚缺什麼 | 補證要花點數？ |
|---|---|---|---|---|---|---|
| 1 | MCP 能否實際登入及操作 | 有條件可行（T01） | **尚待實測** | E2：官方 `.mcp.json` 指向 `https://mcp.liblib.tv/mcp`，OAuth、每人用自己帳號授權；E4：官網 `liblib.tv/plugin` 頁面據搜尋摘要列出相同安裝指令 | 未親眼看到 401／well-known 200；未完成 OAuth；未取得工具清單 | **0 點** |
| 2 | 是否支援上傳 WAV 或其他音訊 | Skill：不支援；MCP：有條件可行 | Skill：**不支援（限官方用戶端腳本）**；MCP：**有條件可行** | E2：官方 Skill 上傳腳本寫死只收 `image/`、`video/`（我方已讀原始碼，此點為直接觀察）；E3：官方 MCP 技能寫明「上傳並驗證 WAV」 | MCP 實際上傳一次 WAV；確認上傳本身不扣點；OpenAPI 伺服器端是否也拒收音訊（用戶端擋了，伺服器端沒測過） | **0 點**（預期，需實測確認） |
| 3 | 是否有音訊驅動對嘴的模型與參數 | 尚待實測（T03） | **尚待實測** | E3：官方 MCP 技能**沒有任何一個**用音訊驅動嘴型的範例，音訊都是生成後才疊上；E4：第三方工具彙整稱 LibTV 有「智能對口型」「上傳音訊驅動數字人」、Seedance 2.0 真人模式需活體檢測與肖像授權 | 用 MCP 讀**即時模型清單與參數 schema**，找有無音訊輸入欄位；網頁節點選單有無「對口型」 | **0 點**（讀 schema 不生成） |
| 4 | 每次 5 秒生成的實際點數與計費方式 | 尚待實測（T06） | **尚待實測** | E4：第三方實測約 17 點／秒（720p）、約 0.35 人民幣／秒（年會員）；各家價目互相矛盾 | 平台顯示的單價（生成前預估）；**實際扣點**（必須真的生成一次） | 單價 **0 點**；實際扣點需 **1 次付費生成（估 ~85 點，上限 150）**，另案核准 |
| 5 | 網頁會員、API、MCP 額度是否共用 | 尚待實測 | **尚待實測** | 推論：Access Key 與 MCP OAuth 都綁個人帳號，Skill 結果出現在同一張網頁畫布；**無任何官方說明** | 三個入口看到的餘額是否同一數字；會員贈送的模型額度能否被 API／MCP 使用 | 餘額比對 **0 點**；扣點歸屬要在第 4 項那次付費生成時一併確認 |
| 6 | 商業影片使用授權與必要限制 | 尚待實測 | **尚待實測** | 官方：LiblibAI《用戶協議》與《創作圖片商業使用規範》（**針對 liblib.art 圖片**：依模型授權＋「會員／API 身分存續期間」創作才可商用）；LibTV 影片條款原文**仍未取得** | LibTV 用戶協議、會員協議、模型使用條款原文；Seedance 等模型方條款 | **0 點** |

### 2.2 本輪實際「已證實」的事項（E1／直接觀察）

| 事項 | 證據 |

## 3. 授權測試環境方案（第五項）

三個方案都只走**官方提供的入口**（官方 Codex 插件、標準 MCP OAuth、官方網頁），不用任何非官方腳本。

### 方案 E-1｜操作員本機（推薦，最快）

在總指揮或指定操作員的電腦上，用自己的 LibTV 帳號授權。

| 步驟 | 指令／動作 | 說明 |
|---|---|---|
| 1 | `python3 MVP素材/source/probe_mcp_public.py > probe-結果.json` | 不登入、不帶憑證；驗證官方說的 401＋well-known 200，並取出 OAuth 授權伺服器資訊 |
| 2a（官方路徑） | `codex plugin marketplace add https://github.com/liblib-ai/marketplace.git --ref main`<br>`codex plugin add libtv@libtv` → 新建任務 → 在 MCP 連線管理對 `libtv` 完成 OAuth | 官方 README 的唯一保證路徑 |
| 2b（Claude Code） | `claude mcp add --transport http libtv https://mcp.liblib.tv/mcp` → 在 Claude Code 輸入 `/mcp` → 選 libtv 完成瀏覽器授權 | 標準 Remote MCP＋OAuth；官方未列出，能否成功本身就是補證項目 1 的一部分 |
| 3 | 依 §4 跑零點數補證 | |

優點：OAuth 在操作員自己的瀏覽器完成，Token 留在操作員電腦，不經過任何雲端環境或 repo。

### 方案 E-2｜雲端研究環境放行

如果要讓本雲端環境的 AI 直接操作：
1. 在環境的 **Network access** 設定（工作階段標題列的雲端環境選單 → Edit）把下列網域加入 Allowed domains：`mcp.liblib.tv`、`www.liblib.tv`、`im.liblib.tv`、`libtv-res.liblib.art`，再加上方案 E-1 第 1 步查出的 OAuth 授權伺服器網域。說明見 <https://code.claude.com/docs/en/cloud-environments#network-access>。
2. MCP 的 OAuth 需要瀏覽器登入，容器內做不到。改在 <https://claude.ai/customize/connectors> 把 `https://mcp.liblib.tv/mcp` 加成自訂連接器並完成授權，**再開新的工作階段**（連接器在工作階段開始時載入）。
3. LibTV 的 OAuth 是否接受 claude.ai 這個用戶端註冊**尚待實測**；不行就退回 E-1。

注意：放行網域後，雲端環境也能連到 OpenAPI。**Access Key 不得貼進對話或 repo**；若要測 Skill 路線，請用環境的 secret 設定注入 `LIBTV_ACCESS_KEY`。

### 方案 E-3｜人工操作備援

MCP 兩條路都不通時，補證 2–6 仍可由人工在 LibTV 網頁完成，不影響判定品質：

| 補證 | 人工動作 | 留存證據 |
|---|---|---|
| 2 音訊上傳 | 畫布上傳 `rap-5s-mix.wav` | 上傳後節點截圖、點數餘額前後截圖 |
| 3 對嘴模型 | 新增影片節點 → 逐一打開模型下拉選單，找可接音訊輸入或標示「對口型」的模型與參數 | 每個模型參數面板截圖 |
| 4 單價 | 設好 5 秒、9:16、720p，**不按生成**，讀按鈕或面板上顯示的預估點數 | 截圖 |
| 5 額度 | 個人中心點數頁、會員權益頁、API／開發者頁（若有） | 截圖 |
| 6 授權 | 網站底部用戶協議、會員協議、隱私權政策 | 存成 PDF 或全文文字檔 |

AI 戰隊負責讀截圖與條款全文，整理成補證紀錄。

## 4. 零點數補證流程（建議在 E-1 執行，約 1–2 小時）

**停止規則**：任何畫面或工具回應顯示「將扣點」「確認生成」，一律停下、不按、截圖回報。

| 步 | 動作 | 對應補證 | 留存 |
|---|---|---|---|
| Z0 | 跑 `probe_mcp_public.py` | 1 | `probe-結果.json` |
| Z1 | 註冊實驗帳號：記錄台灣手機能否註冊、需要哪些身分驗證（**若要求活體或證件，停下回報**） | 1、6 | 截圖 |
| Z2 | 讀官網價目、會員方案、點數規則頁；**不購買** | 4、5 | 截圖／PDF |
| Z3 | 讀並存下用戶協議、會員協議、模型使用條款全文 | 6 | 全文檔 |
| Z4 | 完成 MCP OAuth（E-1 步驟 2a 或 2b） | 1 | 授權成功畫面 |
| Z5 | 呼叫能力探測（官方技能提到的 `get_capabilities`／doctor），**把完整工具清單與 schema 存檔** | 1、3 | `mcp-tools.json` |
| Z6 | 列出可用影片模型，逐一讀參數 schema，找：音訊輸入、對口型、時長、比例、解析度、負面提示、預估點數欄位 | 3、4 | `model-schemas.json` |
| Z7 | 記錄點數餘額 → 上傳 `rap-5s-mix.wav` 與 `分鏡動態腳本-animatic-5s-9x16.mp4` → 再記錄餘額 | 2、5 | 回傳的素材 ID、前後餘額 |
| Z8 | 建一個 5 秒、9:16 影片節點，接上 WAV（若 schema 允許），跑**預檢／virtual generation plan**，讀預估點數；**不送出** | 3、4 | 預檢結果 |
| Z9 | 網頁上打開同一張畫布，確認 MCP 建的節點看得到；比對網頁顯示的餘額與 MCP 回報的餘額（若有此工具） | 1、5 | 截圖 |
| Z10 | 看帳號設定是否有 Access Key 頁：能否建立、撤銷、設權限；**只看不建立** | 5、安全 | 截圖 |

Z0–Z10 完成後，第 1、2、3、5（部分）、6 項可以從「尚待實測」改判。第 4 項的「單價」可改判，「實際扣點」仍要一次付費生成。

| 素材 | 狀態 | 規格／說明 |
|---|---|---|
