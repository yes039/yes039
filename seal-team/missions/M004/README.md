# SEAL-004｜企劃兵 vs C 獨立執行：實測方案

- 狀態：**方案待核准，尚未執行**
- 版本：V1.0（2026-10-12）
- 依據：[SEAL-003 驗兵標準 V1.0](../../驗兵/SEAL-003_AI員工商品化驗兵標準_V1.0.md) 第 3 節「C 基準對照」
- 受測員工：海豹企劃兵（[roles/01-企劃兵.md](../../roles/01-企劃兵.md)）
- 附件：[測試素材需求.md](測試素材需求.md)、[評分表.md](評分表.md)

## 1. 要回答的問題

**企劃兵是否比 C 直接做，更能產出「拍得出來、驗證得了」的短影音企劃？**

只比兩組。小爆和其他員工暫不加入，等這次基準比較完成後再決定。

| 回合 | 做什麼 | 載入企劃兵 | 看得到另一回合嗎 |
|---|---|---|---|
| 第一回合 | 企劃兵執行任務，跑 3 次 | 是 | 不適用 |
| 第二回合 | C 獨立執行相同任務，跑 3 次 | **否** | **否** |
| 第三回合 | 盲評與比較 | — | 評審在揭盲前看不到組別 |

## 2. 實測範圍

| 涵蓋 | 檢查項 |
|---|---|
| 會拿到證據 | 2.1～2.5、3.1～3.4、4.1～4.4、7.1、7.2 |
| 部分涵蓋 | 1.2（Project 設定步驟） |
| 不涵蓋 | 第 5 關（非技術店主獨立操作）、第 6 關（第二位客戶）、7.3～7.5 |

**觀察指標（不作為通過門檻）**：每次任務人工介入 ≤ 15 次、毛利 ≥ 50%。照實記錄，不用來判定通過或不通過。

## 3. 公平條件

兩回合必須完全相同的東西：

| 項目 | 規定 |
|---|---|
| 店家資料、素材清單、素材截圖 | 同一份，見[測試素材需求](測試素材需求.md) |
| 派工單（給執行者的第一則訊息） | 一字不差，見第 4.3 節 |
| 標準答覆表 | 執行者提問時，Shen **只照表回答**；表上沒有的一律回「未提供」 |
| 驗收標準 | [評分表](評分表.md)，**實測前定稿，看到產出後不得修改** |
| 模型與介面 | 同一個 Claude.ai 帳號、同一個模型，每次開新對話；記錄實際模型名稱 |
| 記憶 | 兩回合都關閉 Claude 的記憶與「參考過去對話」，避免互相影響 |

**能力差異只來自一件事**：第一回合有企劃兵職責卡＋作戰令模板＋戰果庫；第二回合沒有。

## 4. 執行流程

### 4.1 前置準備（Shen，執行前一次完成）

1. 準備[測試素材需求](測試素材需求.md)裡的 6 樣東西，存在 `M004/00-素材/`。
2. 填好**標準答覆表**，存檔後不再修改。
3. 建兩個 Claude.ai Project：
   - **「M004-企劃兵」**：Project instructions 貼上企劃兵職責卡全文；Project knowledge 上傳 `contracts/01-短影音作戰令.md`、`戰果庫.md`（目前空白）、店家資料卡、素材清單、素材截圖。
   - **「M004-對照組」**：Project instructions **留空**；Project knowledge **只上傳**店家資料卡、素材清單、素材截圖。
4. 確認兩個 Project 的記憶設定都已關閉。
5. 備好計時器和[評分表](評分表.md)的「執行紀錄」頁。

### 4.2 第一回合：企劃兵（3 次）

每一次都要：
1. 在「M004-企劃兵」開一個**新對話**，開始計時。
2. 貼上派工單（第 4.3 節），一字不改。
3. 企劃兵提問 → 照標準答覆表回答；每回一次記「問答 1 次」。
4. 企劃兵產出作戰令 → 停止計時。**不修改、不追問、不要求重寫**。
5. 產出全文存成 `M004/01-企劃兵/run{1,2,3}.md`；對話匯出或截圖存在同一資料夾。
6. 在執行紀錄填：耗時、問答次數、其他介入、明顯錯誤。

如果產出不完整（例如回覆被截斷），只允許說一句「請繼續」，記一次介入。

### 4.3 派工單（兩回合共用）

```
這是我的店，資料和素材都在附件。
請幫我企劃一支 30 秒以內的短影音：要能直接交給剪輯的人製作，而且發布後我能知道它有沒有效。
有不清楚的地方先問我。
```

派工單**刻意不提**作戰令、測試點、判讀規則這些詞。企劃兵知道要產出這些，是它職責卡的能力（S）；C 直做會不會自己想到，正是要比較的地方。

### 4.4 第二回合：C 獨立執行（3 次）

在**第一回合 3 次全部完成之後**才開始。流程同 4.2，但：
- 使用「M004-對照組」Project。
- 產出存成 `M004/02-C直做/run{1,2,3}.md`。
- Shen 在第二回合期間**不看**第一回合的產出，也不把它貼進對話。

### 4.5 第三回合：盲評與比較

1. **匿名化**（由 Shen 以外的人或一個新的 C 對話處理）：6 份產出改名為隨機代號（例如 P1～P6），代號對照表另外存放、封存。
2. **Shen 盲評**：依[評分表](評分表.md)逐份評分，包括 8 個品質項目、5 道陷阱題、缺陷清單、整體 1～5 分。
3. **獨立評審**：開一個新的 C 對話，只給評分表與 6 份匿名產出，請它逐項評分並引用原文作為依據。
4. 兩份評分都完成後才揭盲，填寫比較表，套用 SEAL-003 第 3.4 節的加值判定。
5. 產出《M004 實測成績單》（使用[通用驗兵表](../../驗兵/通用驗兵表_模板.md)）。

**盲評的限制**：作戰令有固定的表格格式，Shen 可能從格式猜出組別。所以評分**以逐項證據為主**，每一分都要引用原文；整體分數只當參考。

## 5. 能力歸屬怎麼判定

第一回合的每一個評分項目，都要標出能力來自哪裡：

| 代碼 | 判定方式 |
|---|---|
| **S** 企劃兵原有 | 職責卡規則或作戰令模板**有明文要求**的部分（例如首戰寫「首戰，無歷史」、優惠標【待店家確認】、只用現有素材編號） |
| **C** C 臨場補強 | 職責卡和模板都沒寫、但產出有做到的部分（例如自行加上的拍攝提醒、發布時段建議） |
| **H** 人工 | 所有提問的回答、「請繼續」、任何修正 |

第二回合全部歸屬 **C**（加上 **H** 的回答）。

**判讀原則**：某項在第一回合做到、第二回合沒做到，而且是職責卡明文要求的 → 可以算企劃兵的加值。兩回合都做到 → 那項是 C 本身的能力，不算企劃兵加值。

## 6. 記錄項目

| 項目 | 怎麼記 |
|---|---|
| 品質 | 評分表 8 項（Q1～Q8，每項 0～3 分）＋整體 1～5 分 |
| 陷阱題 | 5 題，各記通過／不通過，附原文 |
| 錯誤 | 嚴重／一般缺陷清單 |
| 耗時 | 貼上派工單 → 產出完成，以分鐘計；另記 Shen 實際操作的分鐘數 |
| 成本 | API 費用 0；Claude 用量記錄訊息數與回覆字數（介面看得到的話） |
| 人工介入 | 問答次數＋其他介入（「請繼續」、修正） |
| 可重複性 | 3 次之間總分的最高與最低差距、陷阱題 3 次都通過的題數、測試點是否 3 次都只有 1 個 |

## 7. 判定方式

套用 SEAL-003 第 3.4 節。企劃兵要算有加值，相較 C 直做至少一項明顯較好：
- 嚴重缺陷較少，或盲評整體高 1 分以上
- 耗時少 20% 以上
- 人工介入少 30% 以上
- 3 次都通過的陷阱題數較多

而且其他指標沒有明顯較差。

**可能的結論與後續**：

| 結果 | 意義 | 建議後續 |
|---|---|---|
| 企劃兵明顯加值 | 職責卡的規則有實際作用 | 進入第 5 關（店主實測）與小爆對照測試 |
| 沒有差異 | 規則被 C 本身能力涵蓋 | 精簡職責卡，或改成「檢查清單」交給 C 用 |
| C 直做較好 | 職責卡反而限制了產出 | 檢討職責卡規則，修訂後重測 |

## 8. 執行限制

- 這份方案核准前，不建立 Project、不執行任何一回合。
- 實測期間不修改企劃兵職責卡、作戰令模板或任何員工檔案；發現問題只記錄。
- 本次只測企劃兵寫作戰令，不測製片兵、戰果兵，也不實際拍片或發布。
- 本方案的設計者（本對話的 C）讀過企劃兵職責卡，**不擔任任何一回合的執行者，也不擔任獨立評審**。
