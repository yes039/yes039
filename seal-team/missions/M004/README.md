### 盤點的關鍵結論

**依照影片兵自己的設計，MP4 是由人在 CapCut 組出來的。** 影片兵負責的是組片包、成片檢查與製作紀錄。

所以這次比較的實質是：

| 組別 | 誰把素材變成 MP4 |
|---|---|
| 第一回合｜影片兵 | 影片兵產出組片包 → **Shen 在 CapCut 組片**（H3）→ 影片兵做成片檢查、寫製作紀錄 |
| 第二回合｜C 獨立 | **C 自己決定怎麼做**；可以寫程式出片（M002、M003 已證明 C 能用 ffmpeg 出片） |

這不是不公平，而是照實測試：影片兵就是這樣設計的。Shen 的組片時間要完整計入第一回合的人工成本。

第一回合**不允許**改成讓影片兵自己寫程式出片。那等於改寫員工，做出來的成果也只能算 C 的補強。

## 3. 公平條件

兩回合完全相同：

| 項目 | 規定 |
|---|---|
| 作戰令 | 同一份、已核可、有隊長簽名。由 Shen 依[作戰令模板](../../contracts/01-短影音作戰令.md)事先寫好（見[素材需求](測試素材需求.md)第 2 節） |
| 素材 | 同一批真實拍攝的照片與影片，加上同一份素材清單、同一批影片截圖 |
| 成片規格 | 9:16、1080×1920、30fps、MP4（H.264＋AAC）、片長依作戰令 ±3 秒、燒入繁體中文字幕、**沒有口白** |
| 音樂 | 同一個指定的音樂檔，或「無配樂」，由 Shen 事先決定；兩組都不得另外找音樂 |
| 禁止事項 | 兩組都**不得使用 AI 生圖、生影片、生歌**，只能用提供的素材。這是影片兵的規則，對照組也一體適用 |
| 標準答覆表 | 執行者提問、停工回報時，Shen 只照表回答；表上沒有的回「未提供」 |
| 評分表 | [評分表](評分表.md)在實測前定稿，看到任何成片後不得修改 |
| 記憶 | 兩組都關閉 Claude 的記憶與「參考過去對話」 |
| 模型 | 盡量用同一個模型；兩組的實際模型都要記錄 |

## 4. 執行流程

### 4.1 前置準備（Shen）

1. 依[素材需求](測試素材需求.md)準備素材、素材清單、作戰令、音樂、標準答覆表，存在 `M004/00-素材/`，之後不再修改。
2. 建立 Claude.ai Project「M004-影片兵」：
   - Project instructions：貼上影片兵職責卡全文
   - Project knowledge：上傳製作紀錄模板、作戰令、素材清單、影片截圖
3. 準備第二回合的隔離環境（見 4.4）。
4. 準備計時器與[評分表](評分表.md)的「執行紀錄」頁；如果可以，全程錄螢幕。

### 4.2 派工單

```
第一回合（影片兵）：
附件是核可過的作戰令、素材清單和素材。請依作戰令製作這支短影音。

第二回合（C 獨立）：
附件是核可過的作戰令、素材清單和素材。請依作戰令製作這支短影音，交付一支可以播放的 MP4。
```

第二回合多寫「交付一支可以播放的 MP4」，是因為 C 沒有職責卡告訴它要交付什麼。兩組的驗收標的都是 MP4。

### 4.3 第一回合：影片兵（3 次）

每一次：
1. 在「M004-影片兵」開新對話，開始計時，貼上派工單。
2. 影片兵如果停工回報或提問 → 照標準答覆表回答，記一次「問答」。
3. 影片兵交出組片包（剪輯單、SRT、封面字、發布文案）→ 記下時間點。
4. **Shen 在 CapCut 照剪輯單組片**，另外計時；只照剪輯單做，**不自己加創意**，遇到剪輯單寫不清楚的地方，記下來並回問影片兵（記一次問答）。
5. 匯出 MP4，回報影片兵（附 3～5 張成片截圖與一句描述，這是職責卡規定的流程）。
6. 影片兵做成片檢查、填製作紀錄 → 停止計時。
7. 存檔到 `M004/01-影片兵/run{1,2,3}/`：MP4、組片包、製作紀錄、對話匯出、CapCut 專案（若可以）。

### 4.4 第二回合：C 獨立（3 次）

在**第一回合 3 次全部完成後**才開始。

**隔離環境**：
- 用 Mac 上的 Claude Code，每次開新的工作資料夾（例如 `~/m004-c-run1/`），**只放** `00-素材/` 的檔案。
- 這個資料夾裡**不放**海豹 repo、職責卡、製作紀錄模板，也不放第一回合的任何產出。
- `~/.claude/skills/` 裡目前有 `skill-xiao-qu` 與 `video-shotcraft`，它們會被「影片」「MV」這類字自動叫出來，**必須先排除**。建議做法：測試前暫時把這兩個資料夾移到 skills 以外的地方，測完再移回。**這一步會動到安裝，執行前要再經 Shen 核准**。
- 每次開始後確認畫面上**沒有**出現 `Skill(...) Successfully loaded`；如果出現，該次作廢重跑。
- 使用 manual mode，每一個指令都經 Shen 核准，並計入介入次數。

每一次：
1. 開新資料夾、啟動 Claude Code、開始計時，貼上派工單。
2. C 提問 → 照標準答覆表回答。C 如果要求 Shen 動手剪片或修片 → 回答「請你自己完成」，記一次介入。
3. C 需要安裝工具時 → 只允許安裝**測試前列入白名單**的工具（見[素材需求](測試素材需求.md)第 6 節），其他一律拒絕，記一次介入。
4. C 交付 MP4 → 停止計時。
5. 存檔到 `M004/02-C獨立/run{1,2,3}/`：MP4、C 寫的所有程式、對話紀錄。

### 4.5 第三回合：戰果比較

1. **技術檢查**：用 `ffprobe` 檢查 6 支 MP4 的規格（尺寸、幀率、長度、編碼、有無音軌）。
2. **匿名化**：由不是 Shen 的人或一個新的 C 對話，把 6 支 MP4 改名為隨機代號 V1～V6，對照表封存。
3. **Shen 盲評**：依評分表逐支評分，包含 10 個品質項目、5 道陷阱題、缺陷清單、能否直接發布。
4. **抽幀佐證**：每支抽 20 幀做成拼圖，評分時對照使用。
5. **揭盲**後填比較表，套用 SEAL-003 第 3.4 節的加值判定。
6. 依[通用驗兵表](../../驗兵/通用驗兵表_模板.md)寫《影片兵 M004 驗兵成績單》。

**盲評的限制**：CapCut 與程式出片的字幕樣式、轉場可能不同，Shen 可能看得出組別。所以評分以「逐項證據」為主：每一分都要寫出成片的秒數或抽幀編號；整體印象只當參考。

## 5. 能力歸屬怎麼判定

| 代碼 | 第一回合（影片兵） | 第二回合（C 獨立） |
|---|---|---|
| **S** 員工原有 | 職責卡或製作紀錄模板**有明文要求**的：剪輯單格式、逐字沿用 Hook／CTA、停工回報、偏差紀錄、成片檢查表 | 無 |
| **C** C 臨場補強 | 職責卡沒寫、但影片兵做到的（例如自己加上的剪輯技巧建議） | 全部的規劃、程式、出片 |
| **T** 外部工具 | CapCut（自動字幕、轉場、匯出） | ffmpeg、Python 套件等 |
| **H** 人工 | 回答提問、**CapCut 組片**、回報成片截圖 | 回答提問、核准指令、拒絕越界要求 |

**判讀原則**：某項在第一回合做到、第二回合沒做到，而且是職責卡明文要求的 → 算影片兵的加值。兩組都做到 → 那是 C 本身的能力。第一回合做到但是靠 Shen 組片做到的 → 算 H，不算影片兵。

## 8. 可能的結論

| 結果 | 意義 | 建議後續 |
|---|---|---|
| 影片兵成片品質明顯較好 | 職責卡的規則（逐字沿用、停工回報、偏差紀錄）有實際作用 | 評估把影片兵的規則交給 C 出片時使用 |

| C 獨立明顯較好 | 影片兵現行設計沒有加值 | 檢討影片兵職責卡，或改為 C 出片時的檢查清單 |
| 兩組都達不到交付品質 | 素材或規格本身有問題 | 先檢討素材與作戰令 |
