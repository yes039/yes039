## 五、與 M002 的差異

M002（60+ 學 AI 招生片，`main`：`seal-team/missions/M002/`）常被當成「C 自己出片」的範例，但**它不是 UZI-01**：

| 面向 | UZI-01（Y1／Y2／R1） | M002 |
|---|---|---|
| 畫面來源 | **店家實拍照片與影片** | **沒有實拍**，全部是 SVG／JS 繪製的插畫動畫 |
| 渲染方式 | Python／Pillow 逐格合成，或 ffmpeg zoompan | Playwright＋Chromium 截取 900 格網頁畫面 |
| 旁白 | 無 | 有：離線 TTS（zhtts，標貝女聲） |
| 配樂 | numpy 合成，或 MIDI＋FluidSynth | MIDI＋FluidSynth |
| 現場原音 | 有（Y1、Y2） | 無；音效由 numpy 合成 |
| 響度 | 不一致：-13.9 ／ -15.8 ／ -22.5 LUFS | -14 LUFS（README 記載） |
| 依賴 | ffmpeg、Pillow、numpy（Y2 加 FluidSynth） | 多出 Node、Playwright、TensorFlow、zhtts |
| 適用場景 | 店家已有照片或影片 | 沒有素材，要從零做出畫面 |
| 授權疑點 | 字型（見第六節） | **旁白聲音**：zhtts 用的標貝中文語料，一般以「非商業用途」釋出（待查證）。若屬實，M002 的旁白不宜商用 |

**更正**：MPT-001 報告第六節把 M002 當成 UZI-01 的基準，並寫「UZI-01 響度 -14 LUFS、有離線 TTS」。依本次證據，UZI-01 **沒有旁白**，響度也**不一致**（R1 只有 -22.5 LUFS）。MPT-001 報告已加註更正。

## 七、紀錄之間的矛盾（需要 Shen 釐清）

1. **宜大第一支片是否存檔**：《宜大工作紀事手冊》YD-001 寫「曾試做過一支影片，成果沒有存檔」。但 Y1（21 秒版）完整存在 `claude/optimistic-feynman-776q3u`，含成片、原始碼與確認紀錄。

## 八、能力邊界（依證據）

**已驗證 ✅**
- 從實拍照片或影片產出 9:16、1080×1920 的 MP4，全程不需要外部 API 或付費服務。
- 逐鏡控制停留秒數、運鏡、字卡、片尾店家資訊。
- 混用照片與影片，並保留現場原音。
- 原創配樂，沒有版權問題。
- 依畫面內容排除隱私或品牌鏡頭（R1）。

**部分驗證 ⚠️**
- 響度沒有固定標準（R1 偏小聲）。
- 字幕與菜名靠 C 看圖判斷，需要人工確認（Y1 有確認；R1 被跳過）。
- 成片品質最後由 Shen 判斷；C 聽不到聲音，只能量數字。

**未驗證或做不到 ❌**
- **旁白**：三支都沒有。
- **一鍵重跑**：素材清單、字幕、運鏡都寫死在每案的腳本裡，換案子必須由 C 改程式。
- **沒有素材的主題成片**：UZI-01 本身沒有圖庫或生成畫面的能力。
- **橫拍照片**：三支片都是直拍素材，橫拍效果沒有測過。
- **大檔交付**：超過 30 MB 要另外壓縮。
