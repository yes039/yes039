# T01｜水電 3 天人工回報試跑計畫

目的：**不寫程式、不接系統**，用現有 LINE 驗證三件事：
1. 師傅／主任會不會每天回報？（回報率）
2. 回報內容夠不夠讓老闆掌握狀況？（欄位完整度）
3. 老闆看一頁摘要後，追問電話有沒有變少、覺得有沒有用？

前提：F01 J5 同意試跑；書面同意書已簽（含照片與個資處理、是否允許去識別化內容交由 AI 整理）。

---

## 一、範圍與角色

| 項目 | 設定 |
|---|---|
| 工地 | 2 個（代號 A、B），由老闆選；建議一個配合度高、一個問題較多 |
| 回報者 | 每工地：主任 1＋師傅 2–4（名單由主任確認） |
| 彙整者 | 1 人（我方訪談者，或老闆指定的行政） |
| 摘要讀者 | 老闆 |
| 期間 | 連續 3 個工作日（不含停工日） |
| 前置基準 | 試跑前 2–5 個工作日：老闆記錄每日主動撥出的工地電話數（通話紀錄截圖即可） |

## 二、回報方式

- 師傅以 **LINE 一對一**傳給該工地主任；主任每天 17:30 前把彙整後的回報傳給彙整者（一對一）。
  - 若主任不願轉傳，改為師傅直接傳給彙整者（試跑前與老闆決定）。
- **不在既有工地群組進行**，避免干擾與隱私問題。
- 文字、照片、語音皆可；照片最多 3 張。

### 回報範本（印成小卡或釘選在聊天室）

```
【A 工地 10/21】
完成：
進度：　%
問題：（沒有就寫「無」）
缺料：（品名／規格／數量／何時要，沒有寫「無」）
明天：
人數：
```

### 給師傅的 30 秒說明（主任口頭講）

> 「老闆想試 3 天，下班前用 LINE 傳一則今天做了什麼、有沒有問題、缺什麼。照這張小卡寫，或直接講語音也可以，大概 1 分鐘。目的是少打電話問你們，不是要考核。」

（「不是考核」須先經老闆同意才能說。）

## 三、每日流程

| 時間 | 誰 | 動作 |
|---|---|---|
| 07:30 | 主任 | 確認今日出工名單（傳一句給彙整者即可） |
| 白天 | 師傅 | 有異常或缺料可隨時傳，不必等下班 |
| 16:30 | 彙整者 | 未收到回報的工地，提醒主任一次（只提醒一次） |
| 17:30 | 主任 | 傳當日回報 |
| 17:30–18:00 | 彙整者 | 貼入私人試算表（欄位見第四節），標記未回報、缺欄位 |
| 18:00 | 彙整者 | 產出一頁摘要傳給老闆（格式同 C-001 `04-線框圖.md` E 節，固定五段、每條附來源：誰／幾點） |
| 晚間 | 老闆 | 讀摘要，回覆「有用／沒用＋一句原因」；記錄今天撥出幾通工地電話 |

摘要產生方式：彙整者人工撰寫；若同意書允許，可將**去識別化**內容交由 AI 草擬，再由彙整者逐條核對來源後才傳出。兩種方式需在紀錄中註明，供日後比較。

## 四、紀錄欄位（私人試算表，不得上傳公開 repo）

| 欄位 | 說明 |
|---|---|
| 日期、工地代號、回報者角色 | |
| 回報時間 | 用於計算是否準時 |
| 回報方式 | 文字／語音／照片／混合 |
| 估計耗時 | 每天問 1 位師傅：「今天回報花幾分鐘？」 |
| 欄位完整度 | 範本 6 欄中填了幾欄 |
| 異常、缺料內容 | 原文 |
| 是否需要追問 | 彙整者是否需回頭問才能看懂（是／否＋問了什麼） |
| 老闆回饋 | 有用／沒用＋原因 |
| 老闆當日撥出工地電話數 | |

## 五、指標與判定

| 指標 | 計算 | 通過（閘門 G0） | 觀察 |
|---|---|---|---|
| 回報率 | 已回報工地日 ÷ 應回報工地日（3 天 × 2 工地 = 6） | ≥ 60%（≥ 4／6） | 第 3 天是否下滑 |
| 準時率 | 17:30 前回報 ÷ 已回報 | 記錄，不設門檻 | |
| 欄位完整度 | 平均填寫欄數 ÷ 6 | ≥ 70% | 哪一欄最常空白 |
| 回報耗時 | 師傅自述平均分鐘 | ≤ 3 分鐘 | |
| 需追問比例 | 需追問的回報 ÷ 總回報 | 記錄 | 用來設計 AI 確認卡的欄位 |
| 摘要有用度 | 「有用」天數 ÷ 3 | ≥ 2／3 | 老闆說沒用的原因 |
| 老闆追問電話 | 試跑期平均 vs. 基準期平均 | **如實記錄**，3 天樣本不足以下結論 | |

**判定**
- **通過**：回報率與摘要有用度都達標 → 寫入 F04，建議 Shen 核准 MVP 開發。
- **調整後再試**：回報率 40–59%，或有用度僅 1／3 → 依回饋修改範本或流程，再試 3 天（最多一次）。
- **不通過**：回報率 < 40%，或老闆 3 天都說沒用 → 不建議開發回報類 MVP；在 F04 改列其他需求卡或「不適合導入 AI」。

## 六、試跑後回饋訪談（各 10 分鐘）

| 對象 | 問題 |
|---|---|
| 老闆 | 摘要哪一段最有用？缺什麼？少打了哪些電話？還願意繼續嗎？ |
| 主任 | 轉傳負擔多大？師傅配合情況？想改哪裡？ |
| 師傅 | 花多久？哪一欄最難寫？語音還是打字好？願意繼續嗎？ |

## 七、試跑結束的資料處理

1. 試算表、截圖、照片保留在私人位置，至少保存至 Shen 核准下一階段為止。
2. 試跑結果（含彙總數字）一律寫在私人位置的 F04 報告，**不寫入公開 repo**。
3. 若企業要求，試跑結束後刪除原始資料並留存刪除紀錄。
