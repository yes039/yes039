# F05｜需求優先級與 MVP 建議表

用途：把 F04 需求卡用同一套標準排序，選出**前三大問題**與**最小可行 AI 方案**。評分由訪談者填、Shen 核准。

---

## 一、評分維度（每項 1–5 分）

| 維度 | 權重 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|---|
| V 改善價值（月損失估算） | 25% | > NT$5 萬 | NT$5,000–5 萬 | < NT$1,000 或無法估 |
| F 發生頻率 | 15% | 每天 | 每週 | 每季 |
| I 影響程度 | 15% | 依 F02 定義 | | |
| A AI 適合度 | 15% | 大量非結構化訊息需整理、可人工確認、錯了可更正 | 部分需 AI，部分規則即可 | 規則或表單就能解決，或錯誤代價過高 |
| D 資料可得性 | 10% | 資料已存在或每天自然產生 | 需新增簡單回報 | 需大量補建資料 |
| U 使用者意願 | 10% | 第一線主動要 | 中立 | 明確抗拒 |
| E 導入難度（反向） | 10% | 2 週內可驗證、不需串接 | 4 週、少量串接 | 需整合正式系統或硬體 |

```
加權分 = 0.25V + 0.15F + 0.15I + 0.15A + 0.10D + 0.10U + 0.10E   （滿分 5）
優先分 = 加權分 × 證據係數（A=1.0、B=0.8、C=0.5，見 F02）
```

## 二、排除與降級規則（先於分數適用）

| 規則 | 處理 |
|---|---|
| 證據強度 C（只有籠統說法） | 不得列入前三名；改列「待量測」，先做基準量測 |
| 涉及工安、法律、合約責任判斷 | AI 適合度最高 2 分；AI 只做整理，判斷歸人 |
| 用規則或表單即可解決 | 列入「不適合導入 AI」，改提非 AI 建議 |
| 需接入客戶正式系統 | 本階段不列入 MVP，列下一階段 |
| 需採購硬體 | 本階段不列入 MVP |
| 受訪者之間說法矛盾 | 狀態維持「❓ 待確認」，補訪後再評分 |

## 四、MVP 選擇規則

從前三名中選出 MVP，須**全部**符合：

- [ ] 可在 2 個工地（或 1 個工程）、4 週內驗證
- [ ] 基準可在 5 個工作日內量到
- [ ] 不需接入正式系統、不需採購硬體
- [ ] 至少一位第一線使用者意願 ≥ 3 分
- [ ] 有明確停損條件

若前三名都不符合 → MVP 改為「基準量測＋人工流程試跑」，不進開發。

## 六、評分校準（避免主觀偏差）

1. 兩家企業評分完成後，並排檢查同類需求分數是否一致。
2. 任何 V=5 的需求，必須附 F02 損失計算與信心等級。
3. 由第二人（Shen）抽查 3 張需求卡重評；差距 ≥ 1 分的維度需說明理由。
