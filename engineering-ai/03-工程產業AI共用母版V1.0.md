# 03｜工程產業 AI 共用母版 V1.0

目的：水電、營造（及日後的空調、裝修、機電）共用一套核心，只換產業模組與設定，**不為每個客戶重寫整套系統**。

## 一、分層

```
┌──────────────────────────────────────────────────────────┐
│ 產業模組層   水電：派工｜點工｜料件｜零星追加                    │
│             營造：標單｜圖說｜發包｜估驗｜合約                    │
├──────────────────────────────────────────────────────────┤
│ 共用核心層   企業與工地｜使用者與權限｜任務與責任｜工程進度        │
│             異常事件｜AI 摘要｜經營儀表板｜稽核紀錄               │
├──────────────────────────────────────────────────────────┤
│ 入口層       LINE 官方帳號（一對一＋LIFF）｜手機網頁｜電腦網頁     │
├──────────────────────────────────────────────────────────┤
│ 基礎層       收件與原始訊息保存｜AI 閘道（模型選擇、費用計量）      │
│             檔案儲存｜排程｜通知｜備份                            │
└──────────────────────────────────────────────────────────┘
```

## 二、共用核心資料模型（V1.0）

所有表共通欄位：`id`、`tenant_id`（企業）、`created_at`、`created_by`、`updated_at`、`updated_by`。

| 實體 | 主要欄位 | 說明 |
|---|---|---|
| `tenants` 企業 | 名稱、產業別（`plumbing`／`construction`）、啟用模組、設定 JSON | 一個客戶一筆 |
| `sites` 工地／工程 | 名稱、代號、地址、狀態（規劃／施工中／停工／完工）、主任、預計起訖 | 水電叫工地，營造叫工程，同一張表 |
| `users` 使用者 | 姓名、手機、角色、LINE 綁定 ID、啟用狀態 | 外包人員也是使用者，權限另設 |
| `site_members` 工地成員 | 使用者、工地、角色 | 權限依工地限縮 |
| `raw_messages` 原始訊息 | 來源（LINE／網頁／上傳）、型別（文字／照片／語音／檔案）、原文或檔案位置、時間 | **永不修改、永不刪除**（僅依保存政策封存），是追溯根據 |
| `tasks` 任務與責任 | 標題、工地、指派人、負責人、期限、狀態（待接收／進行中／完成／取消）、完成佐證 | 交辦、缺料、異常處理都可掛任務 |
| `progress_reports` 進度回報 | 工地、日期、回報人、完成內容、進度 %、明日計畫、出工人數、天候、照片 | 水電「今日回報」＝營造「日報」基礎 |
| `issues` 異常事件 | 工地、類型（停工／缺料／變更／安全／品質／其他）、等級（1–3）、描述、負責人、期限、狀態（新開／處理中／待確認／結案） | 逾期由規則判定 |
| `ai_summaries` AI 摘要 | 範圍（全公司／工地）、期間、內容、引用的紀錄 ID 清單、模型、token 用量、使用者回饋 | 每句必須能對應紀錄 ID |
| `field_provenance` 欄位來源 | 紀錄、欄位、值、來源（`ai`／`human`／`rule`／`import`）、來源訊息 ID、信心 | 沿用玉欣珍小購「品類來源」做法並推廣到所有欄位 |
| `audit_log` 稽核紀錄 | 誰、何時、對哪筆、哪個欄位、舊值、新值、原因 | 只增不改 |
| `dashboards` 儀表板設定 | 角色、卡片清單、門檻 | 老闆首頁卡片可依產業換 |

## 三、權限模型

角色 × 工地範圍 × 動作。預設角色：

| 動作 | 老闆 | 管理者 | 主任 | 現場人員 | 行政 | 外包 | 稽核 |
|---|---|---|---|---|---|---|---|
| 看全部工地 | ✅ | ✅ | 所屬 | 所屬 | ✅ | 指定 | ✅ 唯讀 |
| 回報進度／異常 | ✅ | ✅ | ✅ | ✅ | — | 指定工地 | — |
| 指派任務 | ✅ | ✅ | 所屬 | — | 限行政類 | — | — |
| 修正 AI 結果 | ✅ | ✅ | 所屬 | 自己的回報 | 行政欄位 | 自己的回報 | — |
| 看金額（合約、成本） | ✅ | 依設定 | 依設定 | ❌ | 依設定 | ❌ | ✅ 唯讀 |
| 改權限、人員 | ✅ | ✅ | — | — | — | — | — |

## 四、AI 規則（全產業共用）

1. **不捏造**：AI 只能根據紀錄回答；素材沒寫的寫「無資料」（沿用 FB 產生器 V4.2「缺資料標【待補】」規則）。
2. **必附來源**：每一筆結構化結果帶 `source_message_ids`；摘要每句帶紀錄 ID；沒有來源的句子不顯示。
3. **AI 只建議，人決定**：異常等級、派工、採購、金額、對外文件，AI 只產草稿。
4. **人工值優先**：被人改過的欄位，AI 重跑不得覆寫。
5. **分級用模型**：擷取／分類用小模型（例：Claude Haiku 級），摘要與長文件用中模型（例：Sonnet 級）；每次呼叫記錄實際 token 與費用（沿用 FB 工作室 `cost.js` 做法），月費設上限與警示。
6. **測試分級**：回報一律分「真實環境通過／模擬通過／尚未測試」（沿用 FB 工作室 V5 交接紀律）。

## 五、產業模組契約

每個產業模組必須提供下列五樣，核心不需要改：

| 契約項目 | 說明 | 水電範例 | 營造範例 |
|---|---|---|---|
| 資料表 | 只能新增自己的表，透過 `site_id`、`task_id`、`issue_id` 連到核心 | `dispatches`、`labor_days`、`materials`、`change_orders` | `tenders`、`drawings`、`subcontracts`、`valuations`、`contracts` |
| AI 擷取範本 | 欄位定義＋提示詞＋驗證規則 | 缺料：料名、規格、數量、單位、需要日 | 標單：工項、單位、數量、規格摘要、截止日、罰則 |
| 字典 | 產業詞彙與同義詞 | 「4 分管＝1/2 吋」 | 「估驗＝計價」 |
| 儀表板卡片 | 給首頁用的卡片 | 今日缺料、待派工 | 待估驗、發包進度 |
| 規則 | 逾期、門檻、提醒 | 缺料超過需要日未到場 → 異常 | 估驗到期未請 → 提醒 |

## 六、複製到新客戶的步驟（目標：不寫新程式）

1. 建 `tenant`、選產業模組。
2. 匯入工地與人員（Excel 範本）。
3. 調整字典與回報範本（設定檔）。
4. 設定老闆首頁卡片與門檻。
5. LINE 官方帳號綁定（每家公司用自己的官方帳號）。
6. 兩個工地先跑 2 週，再擴大。

## 七、沿用既有資產對照

| 母版元件 | 沿用自 | 改動 |
|---|---|---|
| 雲端底座、登入、Session、防暴力破解、部署交接 | FB 內容工作室 V5（①） | 加多租戶與角色權限 |
| AI 費用計量 | FB 內容工作室 `cost.js`（①） | 加每租戶月上限 |
| 拍照→辨識→待確認→確認 狀態機、欄位來源標記 | 玉欣珍小購（②） | 改工程欄位；從單據擴大到所有回報 |
| 人工節點、退回規則、不假裝自動化 | 海豹任務小隊（②） | 換成工地角色 |
| 經營 KPI、90 天節奏、商機交接 | 尚未查證（④） | 補查後再決定 |
