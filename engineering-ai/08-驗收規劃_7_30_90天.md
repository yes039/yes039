# 08｜7 天、30 天、90 天驗收規劃

> 起算日＝Shen 核准且企業書面同意後。驗收結果一律分「真實環境通過／模擬通過／尚未測試」，不把模擬當實測。

## 水電《八工地 AI 經營指揮台》

### 7 天｜需求與回報意願驗證（階段 0）

| 驗收項 | 方法 | 通過標準 |
|---|---|---|
| 訪談完成 | 09 清單 A 類必問題 | 全部有答案或明確「不知道」 |
| 基準量測 | 老闆記錄 5 天追問電話數；回溯 3–5 件異常 | 有數據 |
| 回報意願 | 2 工地 LINE 文字範本試跑 3 天 | 回報率 ≥ 60% |
| 摘要價值 | 人工產 3 份摘要給老闆 | 老闆說「有用」≥ 2 份 |
| 決策 | Shen＋老闆 | 進入開發／調整／停止 三選一並留紀錄 |

### 30 天｜MVP 2 工地上線（階段 1＋2）

| 驗收項 | 通過標準 |
|---|---|
| 功能 | 五項功能在 2 工地真實環境可用：總覽、回報、交辦、缺料、摘要；追溯、更正、未回報標記可操作 |
| K1 回報率 | 最後 2 週 ≥ 80% |
| K5 AI 理解正確率 | ≥ 85% |
| K6 摘要有用度 | 最後 2 週「有用」≥ 70% |
| K2 老闆追問電話 | 與基準比較，**如實報告**升降 |
| 稽核 | 抽 20 筆紀錄，每筆可追到原訊息；人工修改皆有歷程 |
| 成本 | AI 月費實際值與估算比較 |
| 停損 | 觸發 01 第五節任一停損條件 → 停止擴大，提出原因報告 |

### 90 天｜擴到 8 工地並評估營運價值

| 驗收項 | 通過標準 |
|---|---|
| 擴展 | 4 工地（第 45 天）→ 8 工地（第 75 天），新工地上線不需改程式 |
| 回報率 | 8 工地平均 ≥ 75% |
| 異常管理 | K3、K4 有 60 天數據，提出可比較的趨勢 |
| 缺料 | K7 與基準比較 |
| 老闆時間 | 老闆自述每日掌握全部工地所需時間，與基準比較 |
| 母版驗證 | 列出哪些需求靠設定完成、哪些需要改程式；改程式項目進母版評估 |
| 商業決策 | 是否進入標準營運版付費、是否加派工／點工／追加模組 |

## 營造《營造企業 AI 經營與工程管理指揮台》

### 7 天｜需求診斷

| 驗收項 | 通過標準 |
|---|---|
| 訪談 | 09 清單 B 類必問題完成 |
| 硬體資訊 | 取得 25 萬設備規格、報價、包含內容；或明確紀錄「廠商未提供」 |
| 痛點排序 | 老闆在五項能力中選出前 2 名 |
| 文件樣本 | 取得 2–3 份可使用的去識別化文件，或確認無法提供 |

### 30 天｜文件擷取實測（不建完整系統）

| 驗收項 | 通過標準 |
|---|---|
| 標單擷取 | 3 份文件，AI 擷取工項與人工結果比對：項次召回率、數量正確率**如實記錄**；目標召回率 ≥ 95%、數量正確率 ≥ 98%（未達即表示需人工全核，價值下降） |
| 時間比較 | 人工整理時間 vs. AI＋人工核對時間，各量 1 份 |
| 日報草稿 | 1 工程試 5 天，主任修改量（字數或欄位數）記錄 |
| 部署決策 | 依實測結果與 02 第五節 TCO，提出雲端／混合／本地建議；若建議本地，需附本地模型同文件實測數據 |

### 90 天｜1 工程 MVP

| 驗收項 | 通過標準 |
|---|---|
| 功能 | 多工程總覽＋日報＋會議紀錄在 1 工程真實運作 |
| 日報準時率 | 與導入前比較 |
| 決議追蹤 | 會議決議全部有負責人與期限，逾期可見 |
| 投資決策 | 是否擴大、是否需要任何硬體採購（附數據） |
