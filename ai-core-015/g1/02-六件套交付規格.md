# 02｜六件套交付規格（G1 草案）

> **狀態：草案。** PKG-001 原文未取得（缺件 P1），六件的切法由 C-001 先提。收到原文後以原文為準，本表逐項對齊並標註差異。

## 1. 六件套總表

| # | 件名 | 內容 | 來源 | 現況 |
|---|---|---|---|---|
| 1 | 員工本體包 | 五份 SKILL.md＋各自 references／scripts | **原件**，只打包不改寫 | 缺件 A2 |
| 2 | 資料契約包 | 統一 JSON Schema＋任務單 Schema＋交接 Schema | Schema 為**原件**；任務單、交接 Schema 為新增外殼 | 缺件 A3 |
| 3 | 安裝包 | A 版：外掛清單（plugin manifest）、安裝說明；B 版：部署設定範本 | 新做 | 待 G2 |
| 4 | 操作手冊 | 總調度 SOP、每日／每週操作步驟、常見錯誤處理 | 依 OPS-001 | 缺件 P2，03 號為草案 |
| 5 | 驗收包 | 測試案例、正解、去識別化 A／B 店示範資料、驗收帳本範本、R0–R3 證據摘要 | 測試與證據為**原件**；帳本範本依 VAL-001 | 缺件 A4–A7、P3 |
| 6 | 複訓包 | 退件分類表、SKILL 版本升級流程、回歸測試清單 | 新做，接 VAL 的複訓佇列 | 待 G2 |

## 2. 每件的驗收條件

| # | 驗收條件（全部可自動檢查） |
|---|---|
| 1 | 五份 SKILL.md 的 SHA-256 與原件清單一致；沒有任何一份被修改 |
| 2 | 所有 Schema 能通過 JSON Schema Draft 2020-12 自我驗證；每名員工的範例輸出能通過對應 Schema |
| 3 | 乾淨環境中依說明安裝，能跑出第一份示範報告；安裝時間有實測紀錄 |
| 4 | 手冊每個步驟都對應到一個實際指令或畫面；沒有「自行判斷」的空白步驟 |
| 5 | 示範資料經去識別化檢查（無真實姓名、電話、會員編號、統編）；測試案例數與原件一致 |
| 6 | 任一退件能在帳本中追到：哪份輸出、哪條規則失敗、修了哪個 SKILL 版本、回歸是否通過 |

## 3. 打包規則

1. **原件唯讀：** 第 1、2、5 件中的原件只複製，不改寫。若需調整，另開新版本號，舊版保留。
2. **雙版同源：** A、B 兩版的第 1、2 件必須是同一份檔案（雜湊值相同）。
3. **SHA256SUMS：** 交付盒根目錄附完整雜湊清單，安裝時先驗證。
4. **不含個資：** 交付盒只放去識別化示範資料；店家真實資料留在店家端，不進交付盒、不進本 repo。
5. **版本號：** `PKG-001 v<主>.<次>`，任一件變動都升次版本，並在帳本記錄。
