# 04｜任務成果驗收帳本（G1 草案）

> **狀態：草案。** VAL-001 原文未取得（缺件 P3）。欄位設計會接 AI-CORE-013 已完成的 `verify_assets.py` 與 `06-品質評分表.csv`，不另立評分法。
> 範本：`04-驗收帳本範本.csv`（只有表頭與一筆**標明為範例**的列，不是實測結果）。

## 1. 帳本原則

1. **只增不改：** 每筆寫入後不可修改；更正一律新增一筆 `supersedes` 指向舊筆。
2. **雜湊鏈：** 每筆含前一筆的雜湊值，任何竄改都會讓後續雜湊對不上。
3. **只記摘要：** 帳本存輸入／輸出的雜湊值與路徑，不存原文，避免帳本本身變成個資庫。
4. **已封存證據只引用：** R0–R3 等既有證據以檔名＋SHA-256 引用，不複製、不修改。
5. **模擬不得當真：** `run_type` 必填，`demo`／`test`／`production` 分開統計。

## 3. 退件分類（接複訓佇列）

| 代碼 | 意義 | 複訓動作 |
|---|---|---|
| R-SCHEMA | 格式錯 | 修 SKILL 的輸出段落；回歸跑該員工全部案例 |
| R-CALC | 數字與正解不符 | 查是資料還是邏輯；邏輯問題才改 SKILL |
| R-ISO | 跨店洩漏 | **最高優先**，停用該員工直到回歸通過 |
| R-HALLU | 引用不存在的資料 | 加強「缺資料要明說」規則 |
| R-USE | 店長看不懂或用不上 | 改輸出呈現，不改計算 |

## 4. 判定規則

- 一筆成果要 `chk_schema=PASS`、`chk_isolation≠FAIL`、`chk_golden≠FAIL`，且有人工 `verdict=ACCEPT`，才算**驗收通過**。
- `NO_GOLDEN`（沒有正解可比）可以通過，但要在報告中標出「未經正解比對」的比例。
- 商品化 G2 門檻（草案，待核准）：五名員工各自的 test 筆數 ≥ 原測試案例數，且 R-ISO＝0。
