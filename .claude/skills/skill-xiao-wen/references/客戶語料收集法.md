# 客戶語料收集法（VOC, Voice of Customer）

> 文案寫不出來，99% 不是文筆問題，是**資料不夠**。
> 小文的第一守則：**只用客戶說過的話，不用自己想的話。**

---

## 1. 語料從哪裡撈（依可信度排序）

| 來源 | 撈什麼 | 備註 |
|:--|:--|:--|
| 客戶訪談逐字稿 | 抱怨的原句、稱讚的原句 | 最高等級素材 |
| LINE／私訊對話紀錄 | 問句、猶豫的句子 | 反對意見都在這裡 |
| 電話／現場成交錄音 | 客戶問倒你的那一題 | 直接變 FAQ |
| Google／FB 評論 | 五星寫什麼、一星寫什麼 | 一星是最好的痛點礦 |
| 競品評論區 | 別人被罵什麼 | 那就是你的機會 |
| 客服常見問題 | 重複三次以上的問題 | 一定要寫進文案 |
| 社群留言／論壇 | 素人怎麼描述這件事 | 抓「行話 → 白話」的對照 |

**收料時只做一件事：原句照抄，不要順稿。** 「我怕買了又放著長灰塵」比「擔心使用率不高」有力一百倍。

---

## 2. 功能 → 利益 → 結果（三段「所以呢？」）

| 層 | 問題 | 例（線上課程） |
|:--|:--|:--|
| 功能 Feature | 它是什麼 | 12 支影片＋3 場直播答疑 |
| 利益 Benefit | 所以呢？ | 卡住可以當場問，不用自己猜 |
| 結果 Outcome | 所以呢？ | 不用再拖三個月才上線第一支片 |
| 身分 Identity | 所以呢？ | 你從「一直說要做」變成「已經在做」的人 |

**文案的主標寫在「結果」或「身分」那一層，規格表才寫「功能」那一層。**

---

## 3. USP 提煉（唯一賣點）

依序過三關，過不了就換一個講法：

1. **真的嗎？**（是事實，不是形容詞）
2. **對手不能講嗎？**（對手也能講＝不是 USP，是行業標配）
3. **客戶在乎嗎？**（你引以為傲的，客戶可能一點都不在意）

> 三關都過 → 這句話放主標。
> 只過 1、3 → 放內文當支撐。
> 只過 1 → 放規格表。

---

## 4. 賣點提煉表（交件前先給客戶確認這張）

```
【產品】
【一句話定位】對〈誰〉來說，我們是〈類別〉裡唯一〈差異〉的
【USP】
【三大支撐點】1. 2. 3.（每點後面附一個可驗證事實）
【客戶原話 TOP5】
【他心裡的 5 個「可是」】
【不適合誰】
```

⚠️ 這張表沒被確認之前，不要開始寫正式文案——寫了也是白寫。
