# AI 影片部隊：窗口架構與 V1→V3 演進路線

先說結論：**你改變的這個前提，會推翻我上一輪「以 LINE 為入口」的結論。**

在「交付生產能力、算力由店家自己負擔」的前提下，V1 最合理的窗口是 **Claude 本身**。LINE 在 V1 只當人工客服和提醒，不當操作窗口。等到付費店家數量夠多，再把高頻的簡單操作抽出來做成「LINE 遙控器」。

但這個結論有一個**必須先驗證的技術前提**。這個前提沒過，整個結論都要重來，我放在最前面講。

---

## 必須先驗證：老闆自己的 Claude 帳號，真的跑得動這支部隊嗎？

今晚這支影片的實際執行環境是：
- 你用 Claude App 上傳照片和 .mov 影片，這一點老闆也做得到。
- 但背後跑的是 **Claude Code 雲端環境**：裡面有容器，可以安裝 ffmpeg、Playwright、numpy，並用 git 保存檔案。
- 渲染一支 30 秒影片要跑好幾分鐘，整個過程大約 15 輪修改。

一般老闆常用的 **Claude 聊天介面**（Project＋Skills＋程式執行），我**不確定**能不能穩定完成下面這些事：
- 處理 iPhone HDR 影片。
- 渲染 30 秒、1080p 的影片並配樂。
- 在用量上限內完成十幾輪修改。

這些要在老闆實際會用的方案上**實測**才知道，我不能替你打包票。

所以你現在實際上有兩種「Claude 窗口」可以選：

| | A1：Claude 聊天＋Project | A2：Claude Code（今晚用的這套） |
|---|---|---|
| 對老闆的友善程度 | 高，就是一般聊天 | 中低，畫面上會看到程式執行過程，而且需要 GitHub 帳號 |
| 影片製作能力 | **未驗證** | **今晚已證實可行** |
| 設定成本 | 低 | 中，每家店要建一個「店家倉庫」和環境設定 |

**第一件事就是花 1～2 天，用 Pro 方案的帳號在手機上實測 A1。** 測試結果會決定 V1 走哪條路：
- **A1 能穩定做出 30 秒影片：**V1 走 A1。
- **A1 做不到：**V1 走 A2，但要把畫面上的技術感壓到最低（見後面 V1 的做法）。

另外，你可以把渲染流程**改寫得更輕量**，例如只用 ffmpeg 模板，不再逐格截圖。這樣在哪個環境都比較容易跑，而且這套輕量渲染引擎本身就是你的智慧財產。

## 1. 這個前提會改變上一輪的結論嗎？

**會，而且是根本性的改變。** 原因有三個。

**第一，「算力由店家負擔」這一點，天然就偏向 Claude 當窗口。**
- **走 LINE 架構：**後台要呼叫模型 API，那費用算誰的？
  - 如果用店家自己的 API 金鑰：老闆必須去開發者後台綁信用卡、儲值、管理額度。這對小店老闆來說幾乎做不到，而且金鑰出事的責任在你。
  - 如果用你的金鑰，再向店家收使用費：你就變成在經營 SaaS 訂閱制，違反「不是賣平台」的定位。
- **走 Claude 架構：**老闆訂閱自己的 Claude 方案，**訂閱本身就是計費機制**，你一行計費程式都不用寫。

**第二，上一輪選 LINE，是因為老闆不必學。** 但你現在賣的就是「讓老闆自己會操作」。學習本來就是商品的一部分，你要做的是**把學習壓到最小**，而不是完全消除。

**第三，代工模式下，人工品管可以藏在幕後。** 但交付模式下沒有人在後面幫忙把關，品管規則必須寫進部隊裡，由部隊自己執行。

## 2. 用 8,800 元去建 LINE Bot＋LIFF＋後台，商業上太重嗎？

**太重，而且不是重一點。** 以下是粗估，實際數字會依團隊能力浮動：

| 要建的東西 | 初期開發（人天） | 持續成本 |
|---|---|---|
| LINE Webhook、素材下載、任務佇列 | 5～8 | 伺服器 |
| 渲染主機（無頭瀏覽器＋ffmpeg，一支片跑幾分鐘） | 8～12 | **每支影片都在燒 CPU**，量一大就很可觀 |
| LIFF 預覽、修改、下載頁 | 8～15 | 前端維護 |
| 多店家隔離、帳號、權限、資料儲存 | 5～10 | 資安與個資責任 |
| 模型串接、錯誤重試、成本紀錄 | 5～8 | 模型改版就要跟著改 |
| 監控、客服、除錯 | — | **最大的隱性成本** |
| **合計** | **約 30～55 人天** | 每月數千到上萬元，外加你的時間 |

用這些數字算一下：
- **打平開發成本：**以一個工程師人天 5,000～8,000 元估算，光初期開發就要賣出 **20～50 套 8,800 元方案**。
- **每月還要持續支出：**而且這筆支出**不會隨著「交付一次」就結束**。

一次性收費，卻背著持續性的營運成本，這正是你最怕的錯誤。**V1 不該建這套系統。**

## 3. 要不要「借 Claude 當現成的 Runtime」？

**要。但你要擁有的是 Runtime 上面那一層。**

| 層 | 誰負責 |
|---|---|
| 算力、模型、程式執行、多輪對話記憶 | **Claude（借用）** |
| 部隊的編制、做法手冊（SOP）、品管規則 | **你** |
| 影片模板、渲染引擎、配樂風格包（例如台客搖滾第一版、第二版） | **你** |
| 店家檔案格式、口令、上線流程 | **你** |
| 裝備更新、使用者社群、成效案例 | **你** |

**判斷標準：**如果老闆明天換成其他 AI 工具，你這層東西還能不能搬過去？能搬的部分就是你的產品。只有「Claude 使用教學」的部分，才是你最怕的那個陷阱。

**借用 Claude 的風險：**
- Claude 的方案、價格、功能可能改變，你的 SOP 可能因此失效。
- 老闆如果退訂 Claude，部隊就停擺了。

**對策：**
- 部隊的所有資產（店家檔案、模板、配樂風格包）都要存在**老闆自己的空間**，而且可以匯出。
- 收一筆小額的**年度「裝備更新」費用**，用來支應你跟著 Claude 改版維護 SOP 的成本。例如首年免費，之後每年 1,500～3,000 元，金額請自己再評估。

## 4. 能不能包裝成「一支部隊」，而不是在學 Prompt？

**可以，而且這才是 8,800 元真正值錢的地方。** 做法是：

**① 一個以店名命名的空間：**例如「夯Bar 影片部隊」，裡面放好這些東西：
- **部隊編制：**
  - 企劃兵：挑素材、排順序。
  - 剪輯兵：套模板、上字幕。
  - 配樂兵：從風格包裡選曲。
  - 品管兵：交件前逐項檢查。
- **店家檔案：**店名、地址、電話、菜單與價格、品牌調性、禁用詞。
- **影片模板和配樂風格包。**
- **品管清單：**
  - 電話一律從店家檔案帶入，不從對話裡擷取。今晚的電話就是老闆一開始給錯的。
  - 猜測的內容一定要標記出來，請老闆確認。今晚的食材字幕就是猜的，而且猜錯了。
  - 畫面有人入鏡就提醒取得同意。
  - 不使用有版權的音樂。

**② 一張護貝的「口令卡」，貼在收銀台旁邊。**
這是實體的東西，比任何軟體介面都有效：

```
━━ 夯Bar 影片部隊 口令卡 ━━
📸 先丟照片／影片，再說：
「出任務：新品 15 秒」
「出任務：今晚來店 30 秒」
「出任務：節日檔期」
✏️ 要修改：
「改字：第 3 秒 改成 ○○」
「換音樂：台客 2」
「電話換成 ○○○」
✅ 完成：「交件」
🆘 卡住：打給教官（LINE ○○○）
```

**③ 部隊回報的格式要固定：**「收到任務，素材 8 張，預計做 30 秒台客風，開工。」每次交件都附上品管勾選結果。

老闆的感受會是「我在叫兵做事」，而不是「我在寫 Prompt」。**口令就是介面。**

## 5. LINE 應該在什麼時候加入？

**第一版就加入，但只當「人」的管道，不當操作窗口。等到有 30 家以上的店，才考慮做遙控器。**

| 階段 | LINE 的角色 | 開發量 |
|---|---|---|
| V1（0～10 家） | 你的 LINE 官方帳號，用來做教官客服、提醒出片、分享成效案例 | **零開發**，用官方帳號內建功能就好 |
| V2（10～30 家） | 定期群發「本週出片挑戰」、關鍵字自動回覆常見問題 | **零開發**，用官方帳號內建功能 |
| V3（30～100 家） | 只把資料證明是**高頻而且簡單**的任務，做成 LINE 遙控器 | 開始開發，但範圍很小 |

**LINE 遙控器的開發觸發條件，三個都要成立：**
1. **量夠多：**付費店家超過 30 家，而且已經有持續性收入可以負擔維運，例如裝備更新費或月費。
2. **任務高度重複：**使用紀錄顯示，超過一半的任務都是同一種簡單任務，例如「丟照片加新品名稱，做成 15 秒模板片」。
3. **打開 Claude 是主要流失原因：**訪談或數據證明，老闆不用的原因主要是「打開 Claude 太麻煩」，而不是「不知道要拍什麼」。

**就算開發了遙控器，深度修改還是留在 Claude。** 遙控器只負責「叫兵」和「收貨」。

## 6. 用「交付一支兵」的角度重新思考

**SaaS 平台思維是：**「我要打造一個完整的系統，讓店家登入使用。」你要負責穩定運作、上線率、所有功能。

**交付一支兵的思維是：**「我幫你挑兵、裝備、訓練、配口令，然後把兵交給你。」你負責的是：
- **安裝：**上線當天兩三個小時，當場用老闆自己的手機、自己的照片做出第一支影片。
- **訓練：**老闆要學會口令卡上的 5 句話。
- **保固：**30 天內卡住隨時找教官。
- **裝備更新：**新模板、新配樂風格、SOP 跟著 Claude 改版修正。

**這其實比較像「裝潢」或「安裝收銀機」，不像賣軟體。** 台灣小店老闆本來就很習慣這種模式：付一筆安裝費，有問題找師傅，每年保養一次。

## 兩個極端之間，最合理的位置

| 極端 | 問題 |
|---|---|
| 自己開發 LINE＋LIFF＋後台 | 8,800 元一次性收入，扛不動持續的開發和維運 |
| 完全依賴 Claude，只教怎麼用 | 沒有自己的產品，任何人上完網路課程都能取代你 |
| **中間位置** | **Claude 是營區和武器，兵的編制、裝備、口令和教官是你的** |

**具體來說：**
- **你不寫平台程式。**
- 你打造的是這些：
  - 部隊安裝包：模板、配樂風格包、SOP、品管清單。
  - 店家檔案格式、口令卡。
  - 上線流程、裝備更新節奏、店家社群。
- 每新增一家店，你付出的主要是**安裝時間**，而不是開發和維運成本。所以可以複製。

## AI 影片部隊 V1 → V2 → V3 窗口演進路線

### V1：「教官陪你上線」（0～10 家店）

| 項目 | 內容 |
|---|---|
| **老闆看到** | Claude App 裡的「〇〇店 影片部隊」、收銀台旁的口令卡、教官的 LINE |
| **我們建置** | 一套手工安裝包（依實測結果走 A1 或 A2）、店家檔案、兩三小時上線服務、第一支影片當場完成 |
| **Claude 扮演** | **主要窗口＋Runtime**，執行部隊的全部工作 |
| **LINE 扮演** | 教官客服、每週提醒出片。**零開發** |
| **收錢方式** | 500 元說明會，現場示範今晚這支影片的製作過程，接著成交 8,800 元方案 |
| **升級到 V2 的條件** | ① 10 家店付費；② 上線 30 天後，**超過 60% 的店每月還自己出 2 支以上的影片**；③ 前 3 大卡關原因都已經記錄下來 |

⚠️ V1 最重要的指標是第 ② 條。如果老闆 30 天後就不用了，問題不在窗口，而在「老闆不知道要拍什麼、什麼時候發」。這時候要先修 SOP 和提醒機制，而不是開發 LINE。

### V2：「標準化部隊」（10～30 家店）

| 項目 | 內容 |
|---|---|
| **老闆看到** | 跟 V1 一樣，但口令更少、模板更多，每月收到新的「裝備包」，例如節日模板、新的配樂風格 |
| **我們建置** | 一鍵安裝包，安裝時間從半天縮到 1 小時；品管規則寫進部隊裡；一份卡關處理手冊，讓助教也能支援；推出年度裝備更新費 |
| **Claude 扮演** | 一樣是主要窗口＋Runtime |
| **LINE 扮演** | 群發出片挑戰、成效案例分享、關鍵字自動回覆常見問題。**仍然零開發** |
| **升級到 V3 的條件** | ① 30 家以上付費，並且有持續性收入；② 數據顯示超過一半的任務是同一種簡單模板任務；③ 流失原因主要是「打開 Claude 太麻煩」 |

### V3：「LINE 遙控器」（30～100 家店以上）

| 項目 | 內容 |
|---|---|
| **老闆看到** | LINE 裡的「出片」按鈕：丟 5 張照片加一句話，就收到 15 秒的模板影片。要深度修改時，點連結回到 Claude 部隊 |
| **我們建置** | **只做一個遙控器**：LINE Webhook、一條模板渲染流程、成品連結。不做完整的 LIFF 和 Agent 平台 |
| **Claude 扮演** | 深度製作和修改的窗口。遙控器背後的模板任務，可以改用比較便宜的模型，甚至不用 AI、只套規則 |
| **LINE 扮演** | 高頻、簡單任務的快速入口，加上交件通知 |
| **收費** | 這時候必須加上月費或使用費，因為你開始承擔算力和維運成本了 |
| **警示** | 如果屆時 Claude 或 LINE 官方已經推出可以直接串接的功能，**直接用官方的，不要自己做** |

## 最後一句話

**8,800 元賣的不是軟體，是「一支已經裝備好、訓練好、會聽口令的兵，加上一位教官」。**

- **Claude 是兵營：**用借的。
- **編制、裝備、口令卡和上線流程：**是你自己的。
- **LINE：**先用來跟老闆維持關係，等有數據證明需要時，再做成遙控器。

**明天要做的第一件事**不是寫程式，而是：用一個 Pro 方案帳號在手機上，走一次「丟照片 → 出任務 → 修改 → 交件」。確認一般的 Claude 聊天介面做不做得出今晚這支影片，再決定 V1 走 A1 還是 A2。
