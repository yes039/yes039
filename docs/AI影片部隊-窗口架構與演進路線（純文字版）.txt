【AI 影片部隊：窗口架構與 V1→V3 演進路線】

■ 結論
在「交付生產能力、算力由店家自己負擔」的前提下：
・V1 最合理的窗口是 Claude 本身。
・LINE 在 V1 只當人工客服和提醒，不當操作窗口。
・等付費店家夠多，再把高頻的簡單操作抽出來做成「LINE 遙控器」。

■ 必須先驗證（這關沒過，結論要重來）
今晚的影片是在 Claude Code 雲端環境做的（可以安裝 ffmpeg、Playwright，用 git 保存檔案）。一般的 Claude 聊天介面能不能穩定做到下面這些，要實測：
・處理 iPhone HDR 影片
・渲染 30 秒、1080p 的影片並配樂
・在用量上限內完成十幾輪修改

兩種 Claude 窗口：
・A1：Claude 聊天＋Project
　友善程度高／影片能力未驗證／設定成本低
・A2：Claude Code（今晚用的這套）
　友善程度中低，要有 GitHub 帳號／今晚已證實可行／每家店要建一個倉庫

→ 第一件事：花 1～2 天，用 Pro 方案帳號在手機上實測 A1。
　做得到就走 A1；做不到就走 A2，並把畫面上的技術感壓到最低。
→ 建議把渲染流程改輕量（只用 ffmpeg 模板），比較容易跑，這套引擎也是你的智慧財產。

■ 1. 這個前提會改變上一輪的結論嗎？
會，原因有三個：
① 算力由店家負擔，天然偏向 Claude 當窗口。
　・走 LINE：要嘛讓老闆自己申請 API 金鑰、綁信用卡（幾乎做不到），要嘛你代付再向店家收費（變成 SaaS）。
　・走 Claude：老闆訂閱自己的 Claude 方案，訂閱本身就是計費，你不用寫任何計費程式。
② 你賣的就是「讓老闆自己會操作」。學習是商品的一部分，要做的是把學習壓到最小。
③ 交付模式下沒有人在後面把關，品管規則必須寫進部隊裡。

■ 2. 用 8,800 元建 LINE Bot＋LIFF＋後台，太重嗎？
太重。粗估初期開發約 30～55 人天：
・LINE Webhook、素材下載、任務佇列：5～8 人天
・渲染主機：8～12 人天（每支影片都在燒 CPU）
・LIFF 預覽、修改、下載頁：8～15 人天
・多店家隔離、帳號、權限：5～10 人天
・模型串接、錯誤重試、成本紀錄：5～8 人天
・監控、客服、除錯：最大的隱性成本
每月還要數千到上萬元維運費，外加你的時間。
以一個工程師人天 5,000～8,000 元估算，要賣 20～50 套才能打平初期開發，而且維運成本不會停。
→ V1 不該建這套系統。

■ 3. 要不要借 Claude 當現成的 Runtime？
要，但你要擁有的是上面那一層：
・Claude（借用）：算力、模型、程式執行、多輪記憶
・你的：部隊編制、SOP、品管規則、影片模板、渲染引擎、配樂風格包、店家檔案格式、口令、上線流程、裝備更新、社群
判斷標準：老闆換成別的 AI 工具，你這層東西還能不能搬過去？能搬的就是你的產品。

風險：Claude 的方案、價格、功能可能改變；老闆退訂 Claude，部隊就停擺。
對策：
・所有資產存在老闆自己的空間，而且可以匯出。
・收小額的年度「裝備更新費」（例如首年免費，之後每年 1,500～3,000 元，請自行評估）。

■ 4. 包裝成「一支部隊」，而不是學 Prompt
① 以店名命名的空間，例如「夯Bar 影片部隊」，裡面放好：
・部隊編制：企劃兵（挑素材、排順序）、剪輯兵（套模板、上字幕）、配樂兵（從風格包選曲）、品管兵（交件前逐項檢查）
・店家檔案：店名、地址、電話、菜單與價格、品牌調性、禁用詞
・影片模板和配樂風格包
・品管清單：
　- 電話一律從店家檔案帶入（今晚電話就是一開始給錯的）
　- 猜測的內容要標記，請老闆確認（今晚食材字幕就猜錯了）
　- 有人入鏡要提醒取得同意
　- 不使用有版權的音樂

② 護貝口令卡，貼在收銀台旁：
━━ 夯Bar 影片部隊 口令卡 ━━
📸 先丟照片／影片，再說：
「出任務：新品 15 秒」
「出任務：今晚來店 30 秒」
「出任務：節日檔期」
✏️ 要修改：
「改字：第 3 秒 改成 ○○」
「換音樂：台客 2」
「電話換成 ○○○」
✅ 完成：「交件」
🆘 卡住：打給教官（LINE ○○○）

③ 部隊回報格式固定：「收到任務，素材 8 張，預計做 30 秒台客風，開工。」交件時附上品管勾選結果。
→ 口令就是介面。

■ 5. LINE 什麼時候加入？
・V1（0～10 家）：教官客服、提醒出片、分享案例。零開發。
・V2（10～30 家）：群發出片挑戰、關鍵字自動回覆。零開發。
・V3（30～100 家）：只把高頻而且簡單的任務做成 LINE 遙控器。
開發遙控器的條件，三個都要成立：
① 付費店家超過 30 家，而且有持續性收入
② 超過一半的任務是同一種簡單模板任務
③ 流失主因是「打開 Claude 太麻煩」，而不是「不知道拍什麼」
深度修改永遠留在 Claude。

■ 6. 交付一支兵，而不是 SaaS 平台
你負責：
・安裝：上線當天 2～3 小時，用老闆的手機和照片當場做出第一支影片
・訓練：學會口令卡上的 5 句話
・保固：30 天內卡住隨時找教官
・裝備更新：新模板、新配樂、SOP 跟著 Claude 改版修正
這比較像「裝潢」或「安裝收銀機」，不像賣軟體。

■ 兩個極端的中間位置
・自己開發 LINE＋LIFF＋後台 → 一次性收入扛不動持續維運
・完全依賴 Claude、只教怎麼用 → 沒有自己的產品，容易被取代
・中間位置 → Claude 是營區和武器；兵的編制、裝備、口令和教官是你的

・Claude：主要窗口＋Runtime
・LINE：群發挑戰、案例分享、自動回覆。仍然零開發

　① 30 家以上付費，並有持續性收入

【V3：LINE 遙控器】30～100 家以上
・老闆看到：LINE 裡的「出片」按鈕，丟 5 張照片加一句話就收到 15 秒影片；要深度修改點連結回到 Claude
・我們建置：只做遙控器（Webhook、一條模板渲染流程、成品連結），不做完整的 LIFF 和 Agent 平台
・Claude：深度製作與修改。遙控器背後的模板任務可改用便宜模型，甚至只套規則
・LINE：高頻簡單任務的入口，加上交件通知
・收費：必須加上月費或使用費
・警示：如果屆時官方已經有現成的串接功能，直接用，不要自己做

■ 最後一句話
8,800 元賣的不是軟體，是「一支已經裝備好、訓練好、會聽口令的兵，加上一位教官」。
・Claude 是兵營：用借的
・編制、裝備、口令卡、上線流程：是你的
・LINE：先用來維持關係，有數據證明需要時再做成遙控器

明天第一件事：用一個 Pro 方案帳號在手機上，走一次「丟照片 → 出任務 → 修改 → 交件」，再決定 V1 走 A1 還是 A2。
