# 交付二｜POS 可取得資料與缺口清單

證據等級：A＝手冊明載；B＝畫面跡象；C＝推論待確認；D＝無證據。
「可取得」分兩層判斷：**資料是否存在於系統**，以及**能否批次取出成檔案**。兩者分開評等。

## 1. 可取得資料（資料存在等級 A 或 B）

| 資料主題 | 存在證據 | 存在 | 批次取出 | 建議取得來源 |

## 2. 缺口清單

| # | 缺口 | 影響的分析 | 嚴重度 | 補救方式 |
|---|---|---|---|---|
| G01 | **Excel、CSV 匯出能力未證實** | 全部 | 🔴 關鍵 | G1 實測；若不可行，改走路線 D（列印成 PDF 再轉換） |
| G02 | **逐筆明細無批次取出方式** | 每小時、客單價分布、合菜組成 | 🔴 | 詢問廠商；以 R03、R07 等彙總報表替代（粒度較粗） |
| G03 | **請購、採購、進貨模組可能未開通**（p117 選單無此功能） | B 採購成本分析 | 🔴 | 補拍完整選單；若沒有，改用**供應商發票、進貨單整理成 Excel** |
| G04 | **成本、進價欄位未見** → 毛利報表可能失真 | B、C 毛利 | 🔴 | 確認成本來源；必要時以外部「食材單價表＋標準配方表」計算 |
| G05 | 庫存、盤點、耗損報表無證據 | B 耗損 | 🟠 | 補拍；若沒有，用外部盤點表（每週一次關鍵 20 項食材） |
| G06 | 配方畫面無證據 | B 食材成本率 | 🟠 | 補拍；若沒有，外部建立三增商品與前 20 名商品的標準配方表 |
| G07 | 時段報表的切分粒度未知 | A 每小時、C 深夜粥 | 🟡 | G1 截圖 |
| G08 | 員工上下班紀錄是否有人使用、能否查詢 | D 工時 | 🟠 | 實測；若沒有，用外部排班打卡 Excel |
| G09 | **薪資、時薪、人事成本**：手冊完全沒有 | D 人力成本率 | 🔴 | **外部 Excel 補充**，絕不虛構（格式見交付三） |
| G10 | 外送平台（Foodpanda、Uber Eats）佣金與實收 | A、C 淨營收 | 🟠 | 確認外送平台是否另設銷售方式；佣金率由平台對帳單取得 |
| G11 | 手機報表網頁的指標與下載功能未知 | 自動化 | 🟡 | 截圖 |
| G12 | 傳輸工具「總部匯出」產出格式未知 | 自動化 | 🟡 | 只詢問廠商，不操作 |
| G13 | 手冊版本是否與玉欣珍現場版本一致 | 全部 | 🟠 | G1 截圖「關於」畫面或版本號 |

## 3. 個資與機敏欄位：一律不送進 AI

| 欄位 | 出現位置 | 處理方式 |
|---|---|---|
| 訂購人姓名、電話 | 收銀訂貨作業（p118） | **刪除** |
| 貴賓姓名、電話、生日、地址 | 貴賓開卡資料檔 | **刪除**；貴賓編號改為不可逆雜湊值（例：M_7f3a…） |
| 外送地址 | 銷售方式「輸入地址」（p133） | **刪除**；最多只保留行政區 |
| 客戶統編、載具號碼、愛心碼 | p119 | **刪除** |
| 員工密碼、手機報表密碼 | p11 | **絕不擷取** |
| 員工姓名 | R05、O01 | 改成員工代碼（E01、E02…），對照表只留在店內 |
| 信用卡、禮券憑證號碼 | p129 | **刪除** |
