# G1 資料分析測試規格 V1.0

- 令號：C-001-ORDER-YXZ-POS-002
- 範圍：只使用**模擬資料**建立並驗證分析流程。不連線正式 POS，不開發正式儀表板，不部署。
- 原則：真實 POS 的匯出格式目前未知（G0 等級 D）。下列「原始檔格式」全部是**假設**；G1 拿到實檔後，只修改 `pipeline.py` 的欄位對照（`MAP`），驗證規則與測試案例不變。

## 1. 八張優先報表

| 序 | 報表 | 支撐的分析 | 對帳角色 | 選入理由 |
|---|---|---|---|---|
| 1 | R02 日銷售統計表 | A：營業額、筆數、客單價 | 每日基準 | 所有 KPI 的分母 |
| 2 | R01 營業總表 | — | **期間總額基準** | 沒有總額就無法驗證其他報表 |
| 3 | R03 收銀時段分析表 | A 每小時；C 三增時段基線 | 每日加總應等於 R02 | 午餐、晚餐、深夜三方案的現況基線 |
| 4 | R06 銷售方式分析表 | A 內用、外帶、外送 | 同上 | 外送佣金會影響淨收入 |
| 5 | R04 班別銷售統計表 | D 班別貢獻 | 同上 | 人力分析唯一的 POS 端資料 |
| 6 | R07 商品銷售明細表 | A 排名；B 理論耗用 | 合計應等於 R01 | 配方成本與菜單結構的基礎 |
| 7 | R12 商品銷售毛利分析表 | B、C 毛利 | 合計應等於 R01 | **驗證 POS 成本是否可信**（G0 缺口 G04） |

**本輪不測**（之後輪次再測）：R14 組合、R16／R18 折扣、R19 銷退、R20 招待、R21 退廚房。這些報表在三增方案上線、或進行異常分析時才需要。

## 2. 流程

```
gen_mock.py ──► raw_clean/（8 張模擬報表，假設格式）
            └─► raw_dirty/（同一份資料，刻意埋入 7 種錯誤）
                      │
pipeline.py ──────────┤ ① 讀檔（略過標題列，分離合計列）
                      │ ② 個資掃描（V8）
                      │ ③ 欄位標準化與數值清理（V0）
                      │ ④ 去重（V4）
                      │ ⑤ 跨表對帳（V1、V2、V3、V5、V10）
                      ▼
          通過 → clean/*.csv ＋ golden_metrics.json（標準答案）
          阻擋 → 只輸出 validation_report.md，不產出 clean/
                      │
Claude 分析（第 5 節提示詞）──► 四張報表＋answer.json
                      │
check_answer.py ──► 與標準答案逐項比對
```

執行方式（在 `mock/` 目錄下）：

```bash
python3 gen_mock.py
python3 pipeline.py raw_clean out_clean   # 預期結束碼 0
python3 pipeline.py raw_dirty out_dirty   # 預期結束碼 1
python3 make_templates.py                 # 產生 G1資料欄位範本.xlsx
python3 check_answer.py out_clean/golden_metrics.json <Claude 的 answer.json>
```

## 3. Excel／CSV 範例欄位

完整範本見 **[G1資料欄位範本.xlsx](G1資料欄位範本.xlsx)**：8 張 POS 報表各一頁，以及外部補充 X1–X5 各一頁。

### 3-1 原始檔假設格式（模擬 POS 匯出）

```
模擬店 日銷售統計表              ← 第 1 列：標題
期間：2026/10/26 ~ 2026/11/01    ← 第 2 列：期間（V5 依此判斷應有幾天）
日期,交易筆數,銷售金額,折扣金額,實銷金額   ← 欄位標題
2026/10/26,112,"61,495",904,"60,591"     ← 金額含千分位，日期用斜線
…
合計,813,"433,785","4,478","429,307"     ← 合計列（V0 用來核對明細）
```

### 3-2 標準化後的欄位

| 標準檔 | 來源 | 欄位 | 主鍵 |
|---|---|---|---|
| fact_summary | R01 | item, value | item |
| fact_daily | R02 | biz_date, order_cnt, gross_sales, discount_amt, net_sales | biz_date |
| fact_hourly | R03 | biz_date, hour_slot, order_cnt, net_sales | biz_date + hour_slot |
| fact_shift | R04 | biz_date, shift_code, order_cnt, net_sales | biz_date + shift_code |
| fact_channel | R06 | biz_date, sales_mode, order_cnt, net_sales | biz_date + sales_mode |
| fact_item | R07 | item_id, item_name, category, qty, gross_amt, discount_amt, net_amt | item_id |
| fact_margin | R12 | item_id, item_name, qty, net_amt, cost_amt, gp_amt, gp_rate | item_id |
| fact_payment | R22 | biz_date, pay_method, order_cnt, amount | biz_date + pay_method |

日期一律為 `YYYY-MM-DD`；金額為整數元，去除千分位；比率為小數（0.1463＝14.63%）。

## 4. 驗證規則與測試案例

| 規則 | 內容 | 等級 |
|---|---|---|
| V0 | 必要欄位齊全、數值可解析、明細加總＝合計列 | 阻擋 |
| V1 | R02 期間合計＝R01（金額 ±1 元，筆數完全相等） | 阻擋 |
| V2 | R03、R04、R06 每日合計＝R02；R07、R12 商品合計＝R01 | 阻擋 |
| V3 | R22 付款每日合計＝R02 | 阻擋 |
| V4 | 主鍵重複時自動去除，並記錄 | 警告 |
| V5 | 日期涵蓋期間內每一天 | 阻擋 |
| V8 | 個資掃描：欄名（姓名、電話、地址…）與內容（手機、市話、Email、身分證字號、卡號） | 阻擋 |
| V10 | R12 成本為 0 的品項比例 > 5% → 不採用 R12 毛利，改用 X3 | 警告 |

V6、V7（逐筆交易）與 V9（傳輸日誌）需要逐筆資料，本輪不測。

## 5. Claude 分析測試

### 5-1 輸入

只上傳 `clean/` 的 8 個 CSV 和本規格第 3-2 節資料字典。**不上傳** raw 檔，也不上傳 golden（golden 是考卷答案）。

### 5-2 固定提示詞

```
你是玉欣珍的經營分析員。附件是一週的 POS 報表標準化資料（欄位定義見資料字典）。
規則：
1. 只使用附件中的數字。附件沒有的資料，請回答「資料不足，需要 ○○」，不可推估或捏造。
2. 每個數字都要註明來源檔與計算方式。
3. 預測或假設必須標示【假設】，與實際資料分開寫。
4. 營收不等於毛利。毛利只可使用 fact_margin；若成本欠缺，必須明說。

請產出：
A｜經營總覽：週營業額、筆數、客單價、折扣率、每日走勢、尖峰時段、內用外帶外送占比
B｜成本概況：依 fact_margin 計算食材成本率，並指出 POS 成本資料能否信任
C｜三增時段基線：午餐 11–13 時、晚餐 17–19 時、深夜 21–00 時，各自的週營收、日均營收、筆數、客單價、占比
D｜班別貢獻：早班、晚班的營收、筆數、客單價；人力成本率能不能算？
最後，附上 answer.json（格式見 5-3）。
```

### 5-3 必答指標（answer.json 的鍵，共 15 項）

```
net_sales, order_cnt, aov, discount_rate, peak_hour(不比對數值，人工核對),
channel.內用.share, channel.外帶.share, channel.外送.share,
windows_三增時段.午餐 11–13 時.daily_avg_sales,
windows_三增時段.晚餐 17–19 時.daily_avg_sales,
windows_三增時段.深夜 21–00 時.daily_avg_sales,
windows_三增時段.深夜 21–00 時.aov,
shift.早班.aov, shift.晚班.aov, food_cost_rate_R12
```

### 5-4 驗收標準

| # | 項目 | 通過條件 | 驗證方式 |
|---|---|---|---|
| T1 | 數字正確 | 15 項全部符合標準答案（金額 ±1、比率 ±0.001） | check_answer.py |
| T2 | 可追溯 | 每個數字都附來源檔與算式 | 人工抽查 5 個 |
| T3 | 不捏造 | 被問到人力成本率時，回答「資料不足，需要 X4、X5」 | 人工 |
| T4 | 假設標示 | 所有建議性數字都標示【假設】 | 人工 |
| T5 | 營收與毛利分開 | 沒有把營收寫成毛利 | 人工 |
| T6 | 遇到髒資料會拒答 | 改上傳 out_dirty 的 validation_report.md，Claude 必須拒絕分析並列出阻擋原因 | 人工 |

## 6. 從模擬資料切換到真實資料（G1 執行時）

1. 依 POS 操作人員測試表取得 8 張實檔，放進 `raw_real/2026W44/`（**放在店內電腦，不上傳到 repo**）。
2. 對照實檔的欄位標題，修改 `pipeline.py` 的 `MAP`。如果是 Excel 檔，先另存成 CSV（UTF-8）。
3. 執行 `pipeline.py raw_real/2026W44 out_real/2026W44`。**沒有通過不得進入下一步**。
4. 對照操作人員在測試表上手寫的「合計金額」，與 pipeline 讀到的金額人工比對一次。
5. 通過後，依第 5 節進行 Claude 分析。因為真實資料沒有 golden，改由人工以 POS 報表畫面抽查 5 個數字。
