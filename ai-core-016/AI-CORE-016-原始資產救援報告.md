## 四、下一步：合法且可驗證的方案

### 方案 A｜由總指揮從 ChatGPT 取回原件（建議優先）

原件最可能在 ChatGPT 端，只有帳號本人能取出。

1. **總指揮操作**，在 ChatGPT 中以下列任一方式取得：
   - 打開 AI-CORE-011 的原對話，下載 `SEAL02_5AI_G1_Prototype.zip` 與 `G1B_R0_R3_evidence.zip`；或
   - 從 Library 下載；或
   - 透過 Settings → Data controls → Export data 匯出整個帳號（含對話與附件），再從中挑出兩個 ZIP。
2. **總指揮在自己電腦上先算 SHA-256**，記下數值。這一步必須由總指揮做，C-001 不能自己算再自己核對。
   - Windows：`certutil -hashfile 檔名.zip SHA256`
   - Mac：`shasum -a 256 檔名.zip`
3. 上傳到本工作階段，或分享 Drive 資料夾。**不要推到 `yes039/yes039`**，它是公開 repo。
4. 一併提供來源紀錄，作為可追溯證據：對話標題、對話日期、下載時間（截圖即可）。
5. C-001 收件後執行（只讀，不解壓到 repo）：
   ```
   python3 -I ai-core-013/advisor-g1/harness/verify_assets.py <zip> --sha256 <總指揮提供值>
   ```
   這會驗證：雜湊一致、ZIP 完整、五份 SKILL.md、JSON Schema 合法、A／B 店資料、執行器可編譯（不執行），以及 R0–R3 證據與 ZIP 內附的 SHA256SUMS。

**若 ZIP 已不在，但對話中有貼出全文：** 匯出的對話檔可以作為**次級來源**。判定為 PARTIAL，標記 `TRANSCRIPT-SOURCED`，以匯出檔本身的 SHA-256 作為來源證據，不得稱為原件。

### 方案 B｜確認無法取回時：標示重建版，重新驗證

只有在總指揮**書面確認**方案 A 失敗後才啟動，需另行核准。

| 規則 | 內容 |
|---|---|
| 新編號 | 使用 `SEAL-02-R`（Rebuilt）等新版本號，不沿用原件名稱與雜湊 |
| 來源標記 | 每個檔案標頭寫 `PROVENANCE: REBUILT`，並註明依據（對話匯出、MIN-005 規劃、總指揮口述等） |
| 證據不繼承 | AI-CORE-011 的 R0–R3 結果**不得**套用到重建版；重建版要從 R0 重新驗證。這與「不重做已完成的測試」不衝突，因為原測試無法取得，無從引用 |
| 測試資料 | 晨光、暮色兩店原始資料若無法取回，改用新產生的去識別化合成資料，並在帳本標記 `run_type=test`、`data=SYNTHETIC` |
| 帳本 | 重建版另開帳本鏈，與原件鏈分開 |
