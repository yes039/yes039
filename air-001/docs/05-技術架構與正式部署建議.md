# 05｜技術架構與正式部署建議

## 一、本輪原型架構

```
瀏覽器（手機優先 Web App，原生 ES Modules，無建置步驟）
  web/index.html · app.js（六畫面＋測試報告＋操作紀錄）· styles.css · i18n.js
        │  fetch /api/*                     │（無伺服器時）
        ▼                                   ▼
server/server.js（Node 內建 http）      web/db-browser.js（sql.js，瀏覽器記憶體）
        │                                   │
        └──────────► core/（兩種模式共用同一份業務核心）◄──────┘
                     router.js   REST 路由與錯誤對應
                     service.js  訂單、派車、帳本、結算、權限、稽核
                     money.js    整數美分、固定四捨五入
                     time.js     America/Los_Angeles、DST 處理
                     schema.js   10 張業務表＋users/roles/sessions/app_meta
                     scenarios.js 模擬資料與 10 大測試情境
        │
        ▼
server/db-node.js → node:sqlite → data/air001.db
```

| 選擇 | 理由 |
|---|---|
| Node 22 內建 `node:sqlite`、`http`、`crypto`（scrypt） | 執行期零外部套件，免原生編譯，原型可在任何 Node ≥ 22.13 主機直接跑 |
| 時區用 `Intl.DateTimeFormat`（IANA tz 資料） | 瀏覽器與 Node 內建，正確處理 PDT/PST 切換 |
| sql.js（SQLite WebAssembly） | 只用於展示模式，讓總指揮在手機上直接操作，與伺服器跑同一份 SQL 與業務邏輯 |
| 業務核心與 UI 分離 | 正式版換資料庫或框架時，計算規則與測試可直接沿用 |

**本輪邊界**：無付費 API、無金流、無簡訊／LINE 通知、無正式部署；全部資料為虛構（電話使用 555 號段）。

## 二、正式版建議架構

| 層 | 建議 | 說明 |
|---|---|---|
| 前端 | Next.js（React）或 SvelteKit＋PWA | 沿用現有六畫面與配色；加入離線提示、推播（司機端） |
| API | Node.js（TypeScript）＋ Fastify／NestJS | 直接移植 `core/` 規則，型別化，加 zod 輸入驗證 |
| 資料庫 | PostgreSQL 16（託管：Supabase、Neon、AWS RDS、Cloud SQL） | 帳本表撤銷 UPDATE/DELETE 權限；每日備份＋PITR |
| Migration | Prisma Migrate 或 Drizzle | 取代原型 `CREATE TABLE IF NOT EXISTS` |
| 身分驗證 | 託管身分服務（Auth0／Clerk／Supabase Auth）＋ MFA | 老闆與會計帳號強制 MFA；司機用手機 OTP |
| 金流（下一階段） | Stripe（信用卡）、Zelle 只做對帳登錄 | 以 webhook 自動把款項由 PENDING 轉 CONFIRMED；冪等鍵防重複入帳 |
| 通知（下一階段） | LINE Messaging API、Twilio SMS | 派車通知司機、接機提醒客戶；需先取得同意 |
| 航班 | FlightAware AeroAPI 等 | 航班延誤自動提示調度（付費 API，需另行核准） |
| 地圖 | Google Maps Platform | 報價距離、司機導航連結（付費 API） |
| 主機 | Cloud Run／Fly.io／Render（美西區域） | 容器化、HTTPS、自動擴展；資料庫同區 |
| 監控 | Sentry＋結構化日誌＋uptime 監測 | 帳務錯誤即時告警 |
| 報表 | 唯讀副本＋Metabase | 經營分析不影響交易庫 |

## 三、上線前必做

1. **資安與個資**：真實客戶電話、地址、航班屬個資，需 HTTPS、資料庫加密、存取權限最小化、隱私權政策；評估 CCPA（加州消費者隱私法）適用性。
2. **帳務控制**：結算付款雙人覆核（會計登錄、老闆核准）；月結鎖帳，鎖帳後只能用調整分錄；每月匯出給會計師。
3. **稽核紀錄**保存至少 7 年（依會計師建議），不可刪除。
4. **併發**：PostgreSQL 交易隔離＋`SELECT … FOR UPDATE`，避免兩位調度同時派同一單（原型已有唯一索引兜底）。
5. **備份演練**：每季做一次還原測試。
6. **法規**：加州機場接送營運的 CPUC 執照（TCP）、機場商業營運許可（LAX/SNA 等）、商業車險；司機身分（1099 承攬或員工）影響結算與報稅（1099-NEC）。需由法務／會計確認。
7. **E2E 測試**：把 `core/scenarios.js` 接入 CI；加入 Playwright 介面測試。

## 四、分階段建議

| 階段 | 內容 | 驗收重點 |
|---|---|---|
| G1（本輪） | 可操作原型、規則與測試 | 畫面能看、資料能建、訂單能派、帳務能算、紀錄能查、錯誤能追 |
| G2 | PostgreSQL＋正式登入＋部署測試環境；匯入真實（去識別）歷史訂單試算 | 與過去人工帳一致 |
| G3 | 司機 PWA、LINE 通知、Stripe 收款 webhook | 司機實際用手機接單 |
| G4 | 航班追蹤、自動報價、經營分析報表 | 老闆週報自動產生 |

## 五、執行方式（原型）

```bash
cd air-001
npm start            # http://localhost:8787，第一次啟動自動建立模擬資料
npm test             # 執行 10 大情境，產生 docs/04-測試報告.md
npm run reset        # 刪除資料庫並重建模擬資料
```
環境變數：`PORT`（預設 8787）、`DB_FILE`（預設 `data/air001.db`）。
