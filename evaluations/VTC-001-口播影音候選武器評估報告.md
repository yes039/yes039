## 一、武器本體

### 1. 核心功能與實際操作流程【證據：SKILL.md「流程」】

```
① 口播稿 → ② 配音輸入（預剪口水詞）＋逐字時間戳（本機 CPU）→ ③ 素材 → ④ SHOTBOOK 分鏡（語意拍、層矩陣、排版預算）
→ ⑤ Remotion 實作（先做樣板鏡給使用者確認，再做其餘鏡頭）→ ⑥ 分段渲染 → ⑦ 三重驗收（機器閘＋1 輪獨立審片）→ ⑧ 響度歸一交付＋開工作台微調
```

- 輸入：口播稿＋**成品配音**（真人或任何 TTS）。人物素材與 B-roll 是選配。數字人不在範圍內（SKILL.md description）。
- 實際操作：在 Claude Code 對它說「用 video-talkcraft 把這份口播稿＋voiceover.wav 做成影片」（README「快速開始」）。
- 流程中的人工關卡【證據：SKILL.md ②-0、⑤-1、⑥-1.5、⑦】：
  - 預剪報告要給使用者看過才落盤；
  - 樣板鏡要使用者確認，才能動其餘鏡頭；
  - 首次渲染前要問「整片還是逐鏡」；
  - 審完 1 輪要問是否續審（最多 3 輪）；
  - 交付時打開 workbench 給人做剪映式微調。
- 字幕【證據：design-language.md §5】：字幕直接燒進畫面，整句一次出現，**不帶標點**。直式字幕距底 350px、字號 48。文件裡**沒有看到另外輸出 .srt 的步驟**【未查證】，但我們在平台另外上傳字幕會需要 .srt。

### 2. 108 張動效卡的用途【證據：references/taxonomy.md、template/cards/ 共 108 個 tsx】

每張卡附有意圖、參數、已知坑、可直接複製的 Remotion tsx 原始碼，以及 HTML 預覽。分類如下：

| 類別 | 張數 | 用途 |
|---|---|---|
| 字幕花字 | 22 | 關鍵字彈出、打字機、標題砸字等，讓靜音觀看也能接收重點 |
| 強調標註 | 14 | 螢光筆、手繪圈、放大鏡、聚光，用來指向畫面重點 |
| 數據資訊圖 | 14 | 數字滾動、長條／折線生長、步驟線，讓數字「長出來」 |
| 素材呈現 | 27 | 截圖巡遊、聊天紀錄、照片牆、分屏對比等，用來呈現證據與多素材 |
| 轉場結構 | 13 | 章節卡、甩鏡、黑震、長鏡頭世界畫布等 |
| 人物互動 | 10 | 名牌條、關注卡（抖音／X）、人物縮成角標 |
| 運鏡 | 8 | 極緩推拉、3D 傾斜、視差，讓靜態截圖動起來 |

對小店解說片最有用的是「數據資訊圖」「步驟」「字幕花字」三類（價格、步驟、優惠重點）。部分卡是平台專用的，例如 `douyin-follow-card` 抖音關注卡，不適合台灣 IG／YT。

## 二、技術架構

### 1. 如何透過 Claude Code／Agent Skill 操作【證據：README「快速開始」】

- 這是一個標準 Agent Skill：根目錄有 `SKILL.md`（約 62 KB 的流程與硬規則），加上 `references/` 方法論與 `scripts/` 工具。
- 安裝方式：`npx skills add …`，或 clone 後 symlink 到 `~/.claude/skills/video-talkcraft`。
- Claude Code 讀 SKILL.md 之後自己寫 Remotion 程式、跑腳本、派子代理審片。整個流程的「大腦」是 Claude，**跟「C 為唯一大腦」不衝突**。

### 2. 使用的現成技術【證據：runtime/package.json、README 致謝】

- 渲染：Remotion 4.0.519、React 19、GSAP、anime.js、three.js、lottie
- 時間戳：FireRedASR2-CTC（sherpa-onnx，模型 767 MB）或 faster-whisper（460 MB）
- 其他：ffmpeg（響度歸一、拼接）、Playwright（網頁截圖）、OpenCV YuNet（人臉安全區偵測）、Vite（workbench）
- 音效：Mixkit 免費採樣（可商用、免署名）；圖示：Lucide（ISC）／Feather（MIT）

### 3. 能否與現有 Remotion、UZI-01 共用

- **Remotion**：本 repo（`yes039/yes039`）**沒有任何 Remotion 專案或依賴**。M002 的做法是 `index.html`＋`render.js`（Playwright 逐格截圖）＋ffmpeg。如果兵工廠在別處有 Remotion，個別動效卡的 tsx 理論上可以搬過去用（每張卡標明「自包含，複製單檔即用」）——**但搬程式碼本身也受 PolyForm NC 約束**。
- **UZI-01**：本 repo 找不到這個名稱，無法評估相容性【未查證，請補充 UZI-01 的位置或規格】。
- 可共用的部分：ffmpeg、Playwright／Chromium、Claude Code、M002 的音樂與音效合成腳本（`music.py`、`mix.py`）。

### 4. 是否需要另外建置系統

**需要。** README 寫明一份 `node_modules` 約 760 MB（含 190 MB 無頭瀏覽器），另外要裝 Python ASR 依賴與 767 MB 模型、ffmpeg，交付時還要在本機起 workbench（`localhost:5199`）。這和軍令「不另開 SaaS、不重建工作流」有衝突，也和 seal-team README「不做系統、能借不造」的原則有衝突。

## 五、收編判斷

### 判定：**B｜收藏觀察**

**不選 A（立即試槍）的理由**

1. **授權攔截**：試槍本身就帶有商業應用目的，可能已經不在 PolyForm NC 允許範圍內。要先拿到作者書面授權。
2. **違反現行軍令與換器規則**：要另建 Node＋ASR 執行環境與 workbench。現有製片兵也沒有觸發換器條件（「組片單支超過 30 分鐘連續 2 次」之類）。
3. **在地化缺口**：預設橫式、簡體字型、zh-CN 語系、抖音版面，每一項都要額外改。

**不選 C（不適合收編）的理由**

1. 功能高度切合「口播稿 → 動態解說片」這個需求，而且是 Claude Code Skill，符合「C 為唯一大腦」。
2. 支援 9:16，主流程可以完全本機執行、不用付費 API。
3. 專案很活躍（2026-09 起幾乎每天更新），授權問題有機會靠作者授權解決。

**升級為 A 的觸發條件**（三項都成立才試槍）

1. 取得作者書面商業授權，條款涵蓋「代客製作、收費交付」，而且價格可接受；
2. 確認 Remotion 授權狀態（公司人數 ≤ 3 免費；超過要買 Company License）；
3. seal-team 製片兵觸發換器條件（例如 H3 組片單支超過 30 分鐘、連續 2 次）。

**需要補充的資訊**

- UZI-01 的位置與規格（本 repo 找不到）；
- 兵工廠裡 Remotion 的位置（本 repo 找不到）；
- 公司員工人數（決定 Remotion 是否要付費）；
- Fish Audio 免費層的商用條款（官網這次連不上）。
